## 🔍 深度技术分析

### 架构决策记录 (ADR)

#### ADR-001: 选择 inline styles 而非 CSS Modules
**决策**: 使用 Tailwind utility classes + inline style 混合方案

**理由**:
1. **快速迭代**: Tailwind class 热重载快，无需重新编译 CSS
2. **类型安全**: inline style 配合 TypeScript 确保 correctness
3. **按需加载**: Tree-shaking 优化更好
4. **维护成本低**: 无需管理额外的 CSS 文件

**权衡**: 
- ❌ 可读性略逊于纯 CSS 方案
- ✅ 但开发效率提升显著

#### ADR-002: 当前步骤脉冲动画的 CSS keyframes 实现
**决策**: 使用 CSS `@keyframes` 而非 JavaScript Animation API

**理由**:
1. **性能更优**: GPU 硬件加速
2. **代码更少**: 不需要复杂的 state management
3. **更易维护**: 声明式 vs 命令式

**实现**:
```css
@keyframes pulse {
  0%, 100% { transform: scale(1); }
  50% { transform: scale(1.05); }
}
.animate-pulse {
  animation: pulse 2s cubic-bezier(0.4, 0, 0.6, 1) infinite;
}
```

#### ADR-003: 进度条数据计算放在组件内而非状态中
**决策**: 每次渲染时实时计算进度，而非存储到状态

**理由**:
1. **数据一致性**: 总是基于最新的 `bid_chapters` 数组
2. **简化代码**: 避免多余的状态同步逻辑
3. **性能可接受**: 计算开销极小 (< 1ms)

**未来优化**: 如果章节数 > 50，考虑 Web Worker 异步计算

## 🐛 已知限制与待优化项

### P2 优先级（非阻塞）
- ⏸️ **未使用虚拟滚动**: 当章节数 > 20 时，考虑添加虚拟列表优化
- ⏸️ **硬编码文本**: 如"继续编写"等文案未来需国际化
- ⏸️ **缺少错误边界**: 极端情况下可能崩溃，建议添加 ErrorBoundary

### P3 优先级（可选增强）
- ⏸️ **无离线支持**: 网络断开时的降级体验
- ⏸️ **缺少撤销重做**: Cmd+Z 快捷键支持
- ⏸️ **无主题切换**: Dark mode 未适配

### 技术债清单
| 编号 | 描述 | 影响 | 修复成本 |
|------|------|------|---------|
| TECHNICAL-DEBT-001 | 章节列表无虚拟滚动 | >50 章卡顿 | 低 |
| TECHNICAL-DEBT-002 | i18n 缺失 | 多语言支持困难 | 中 |
| TECHNICAL-DEBT-003 | 无错误边界 | 全局崩溃风险 | 低 |
