## 一、十二条不可协商的规矩

这 12 条是"完美主义"的落地点。评审时逐条打勾，任何一条不满足即打回。

| # | 规矩 | 反例（线上真实存在） |
|---|---|---|
| 1 | **一类决策一屏**：一屏内只允许用户做一类决定 | 客户管理同屏做「找/看/推商机/补资料」4 件事 |
| 2 | **每屏 1 个实心主色 CTA** | 客户管理 4 个并列按钮 |
| 3 | **禁用按钮必须旁挂原因** | 标书检查「开始检查」灰着不说明 |
| 4 | **危险操作三件套**：红描边 + 二次确认 + 后果一句话 | 团队管理「停用」无确认 |
| 5 | **禁止两级筛选并存** | 情报中心左侧 6 组 + 中部 3 组 |
| 6 | **表格 > 12 行必须分页** | 资质台账 34 行一次渲染 |
| 7 | **空态必须有主行动按钮** | 「还没有 XX」死白屏 |
| 8 | **长任务 > 3s 要有骨架，> 30s 要能取消** | AI 生成无进度、不能取消 |
| 9 | **数字诚实**：同一概念同屏前后一致 | 「废标 4 条」与「4 项」并列出现 |
| 10 | **禁止行内色值**：颜色只能来自 token | 各页面硬编码 `#3B82F6` |
| 11 | **弹窗 ≤ 560px，抽屉 ≤ 560px** | 全屏宽弹窗 |
| 12 | **文案说售前的话**：写数字与后果，不写功能说明 | 「该功能用于管理客户信息」 |

## 二、设计令牌（唯一色板 / 间距 / 字阶 / 圆角 / 阴影）

### 2.1 色彩：一套主色 + 一档中性 + 五档语义

```
主色（医疗青蓝，沿用品牌 #0E7C99，6 档）
  --primary-700  #0A5E75   悬停 / 强调文字 / 侧栏激活条
  --primary-600  #0C6E88   按下
  --primary      #0E7C99   主 CTA / 主色文字
  --primary-400  #2A98B4   图表渐变起点
  --primary-300  #6BB9CC   描边 / 次级
  --primary-100  #D3EAF0   提示条边框
  --primary-50   #EBF5F8   选中行底 / 浅底

侧栏（深青，唯一深色面）
  --side         #0B2430
  --side-hover   #123240
  --side-active  #0D3A4A
  --side-ink     #9DB6C0   （正文项）
  --side-ink-2   #6C8994   （分组标题 / 副行）

中性（冷灰，与青色同色相）
  --bg      #F1F5F7   页面底
  --bg-2    #E8EFF2   分段控件底 / 表头底
  --card    #FFFFFF
  --card-2  #FAFCFD   卡内浅底 / 表头
  --line    #E1EAEE   分隔线
  --line-2  #EDF3F5   表格行线
  --line-3  #D6E2E7   控件描边
  --ink     #122A31   标题 / 主文
  --ink-2   #425D67   正文
  --ink-3   #6B8490   辅助
  --ink-4   #93A7B1   提示 / 占位
  --ink-5   #B7C6CE   禁用 / 图表底
```

**语义色只有五档，且必须与"用户该做什么"绑定**（不是"好看"）：

| 语义 | token | 用于 | 绑定动作 |
|---|---|---|---|
| **阻断 red** | `--red #D64545` / `--red-bg` | 废标风险、已过期、不可导出、删除 | 必须处理，不处理会失败 |
| **临期 orange** | `--orange #D97B26` / `--orange-bg` | 30 天内到期、超 30 天未跟进 | 本周内处理 |
| **提示 amber** | `--amber #B08313` / `--amber-bg` | 未登记、待确认、低于建议值 | 需要人判断 |
| **完成 green** | `--green #17876B` / `--green-bg` | 已确认、已通过、中标 | 无需动作 |
| **进行 blue** | `--blue #2E6FB0` / `--blue-bg` | 编制中、已开始、在流转 | 观察进度 |
| 特殊 purple | `--purple #7B4FB0` | 方案交流、答疑节点 | 低频区分 |

> **禁止**：用蓝色表示"重要"，用绿色表示"好看"。语义色只表达"用户下一步该做什么"。
> **禁止**：同屏出现两种红（比如 `#D64545` 与 `#DC2626`）——线上现在有 4 种红。

### 2.2 间距：8px 栅格，只允许 6 个值

```
4   图标与文字间隙 / 徽标内边距
8   同组控件间距 / 行内 gap
12  卡片网格 gap / 表单字段纵向间距
14  卡片内边距（紧凑）
16  区块之间 / 卡片内边距（标准）
24  大区块之间
32  页面顶部距（首页 hero 后）
```

**禁止** 10 / 13 / 15 / 18 / 20 / 22 这些"手感值"。线上现在 8/12/16/20/24 混用，导致页面没有节奏。

### 2.3 字阶：6 档，语义绑定

| 档 | 大小 | 字重 | 用途 |
|---|---|---|---|
| 页面标题 h1 | 22px | 650 | 每屏唯一（`.ph h1`） |
| 区块标题 h2 | 15px | 600 | 卡片组级（少用） |
| 卡片标题 h3 | 13.5px | 600 | 卡片头（`.card-h h3`） |
| 正文 | 13px | 400 | 默认（`body`） |
| 辅助 | 12px | 400 | 说明、副行（`.small`） |
| 微文字 | 10.5–11px | 400/500 | 徽标、时间、编号（`.tiny`） |

数字统一 `--font-mono`（Roboto Mono）+ `tabular-nums`，金额保留 1 位小数（`286.0 万`），百分比 1 位（`23.1%`）。

**为什么是 13px 而不是 14px**：B 端高密度工作台（Linear / Stripe / TDesign 紧凑模式）正文 13px 是行业惯例。本产品一屏要同时放表格、检查栏、指标，14px 会让 1366×768 笔记本上放不下。

### 2.4 圆角 / 阴影

```
圆角：控件 6px（--r-sm）· 卡片 8px（--r-md）· 大面板 12px（--r-lg）· 徽标 999px · 微标记 4px
阴影：sh-1 静态卡片 · sh-2 悬停/抬升 · sh-3 下拉与浮层 · sh-4 弹窗与抽屉
```

**规则**：静态卡片必须有 `sh-1`（不能只在 hover 才有阴影，否则默认状态像"没做完"）；`sh-4` 只给 modal/drawer，不要给卡片。

## 三、组件规范（逐项：什么时候用 / 怎么放 / 什么禁止）

### 3.1 按钮

**四级层级，一屏只能有 1 个主 CTA。**

| 级别 | class | 何时用 | 禁止 |
|---|---|---|---|
| 主 | `.btn.btn--primary` | 本屏唯一"推进流程"的动作 | 一屏出现 2 个；用于"保存"这种非推进动作 |
| 次 | `.btn` | 并列备选、导出、筛选、取消 | 用主色描边冒充主按钮 |
| 文字 | `.btn--ghost` / `.btn--link` | 表格行内"打开/查看"、"全部 →" | 用于会跳转页面丢失上下文的主动作 |
| 危险 | `.btn--danger`（描边）/ `btn--danger-solid`（仅确认弹窗内） | 删除、停用、清空、仍然导出 | 与主按钮同权重并列 |

**尺寸**：默认 30px 高（表格/工具条）；`.btn--sm` 26px（行内/密集区）；`.btn--lg` 36px（弹窗底部主按钮、空态主按钮）。
**宽度**：不写死宽度；工具条内按内容；弹窗底部按钮固定 `min-width: 72px` 视觉对齐。
**图标**：14px，与文字 gap 6px；纯图标按钮必须 `title` 属性。
**禁用**：`is-disabled` + **旁边必须有 `.small.muted` 原因文案**。这是硬性要求。

**按钮放在哪**（这是"大厂规范"最常被问的点）：
- **页面级主 CTA** → 页头右上 `ph-actions`（新建、导入、开始检查）
- **区级操作** → 卡片头右侧（导出、排序、全部 →）
- **行级操作** → 行尾，只留 1 个最常用，其余进 ⋯ 菜单
- **流程推进** → 步骤区底部或固定底栏（下一步 / 提交）
- **危险操作** → 永远不放在行首、不放在主 CTA 右侧紧邻位置（防误点）

### 3.2 下拉框 / 选择器

**全站自绘，禁用原生 `<select>` 做主要筛选**（原生无法分组、无法带说明、不同浏览器样式不一致）。

```
触发器：与输入框同高（32px），右侧 9px 内嵌 12px 箭头
菜单：min-width = 触发器宽度，最大高度 280px 滚动
结构：分组标题(可选) → 选项(可带右侧计数) → 分隔线 → 危险项(可选)
选中：左侧无 radio，用右侧 ✓ + primary 文字 + primary-50 底
```

**什么时候用下拉 vs 分段控件 vs 筛选 chip**：
| 控件 | 选项数 | 用途 |
|---|---|---|
| 分段控件 `.seg` | 2–4，互斥且高频 | 视图切换（卡片/表格）、时间范围（24h/7d/30d） |
| chip `.chip` | 3–6，可多选，带计数 | 状态筛选（全部 34 / 临期 3 / 已过期 1） |
| 下拉 `.dd` | > 4，或需要分组/带说明 | 等级、状态、负责人、模板选择 |
| 抽屉 | > 6 个筛选条件 | 高级筛选（触发器上显示生效数量徽标） |

**禁止**：把一个 5 选项的筛选用 5 个按钮平铺（线上「进行中/已归档/回收站」+「卡片/表格」就是两组平铺，挤在一行）。

### 3.3 筛选区

```
一行结构：[搜索框 flex:1] [chips 3-4个] [筛选按钮(带生效数)] [右侧：排序/视图切换]
```

规矩：
- 常驻筛选 **≤ 4 个**，其余进「筛选」按钮的抽屉
- 抽屉按钮上必须有**生效数量徽标**（用户要知道自己有没有在"过滤态"）
- 筛选生效时，上方出现一行「已选条件」chips，每个带 ×，末尾「清空」
- **禁止**页面左侧竖排 6 组筛选栏 + 中部横排筛选行并存（两级并存必有一级失效）
- 搜索框统一 `placeholder` 写清搜索范围：「搜索客户名称 / 编号 / 联系人」

### 3.4 表格

| 项 | 规范 |
|---|---|
| 高度 | 表头 34px，行 40px（紧凑区 36px） |
| 表头 | 吸顶 `sticky top:0`，`--card-2` 底，11.5px 600 `--ink-3` |
| 对齐 | 文本左对齐；**金额/数量右对齐 + mono**；状态居中 |
| 主列 | 第一列写"名称"并用 `.name`（600 字重 + 下方 `.sub` 放编号/附加信息） |
| 操作列 | 右对齐，最多 2 个图标按钮，**其余进 ⋯ 下拉**；危险图标 hover 变红底 |
| 行高亮 | hover `#F7FBFC`；选中 `--primary-50` |
| 空行 | 必须给空态，不允许"表头 + 空白" |
| 分页 | > 12 行必须分页；底部条显示「已选 0 / 共 3 条」+ 批量操作 + 页码 |
| 长文本 | 单行截断 + `title` 悬浮全文；**禁止**让一列挤到换行 3 行（线上资质台账证书名列） |

**列宽分配原则**：名称列弹性（`min-width: 220px`），状态列固定（80–96px），金额列固定（96–120px），操作列 `width:1%` 自适应内容。

### 3.5 卡片

```
结构：card-h(标题 + 副说明 + 动作) → card-b(内容) → card-f(可选，底部统计/跳转)
```

- 卡片头 `min-height: 44px`，`h3` 内可带图标（15px，primary 色）
- 副说明（`.sub`）只在**能帮助判断**时出现，不写"该模块用于…"
- 卡内如果放表格，用 `.card-b.flush` + `.tbl-wrap` 去边框，避免"卡中卡"
- **同级卡片必须等宽等高**（用 grid 自动），不允许一张卡独占整行装着 1 条数据（线上方案工作室）

### 3.6 指标卡 / 数据条

**决策规则（重要）**：
- 指标 **≥ 4 个且每个都有独立行动含义** → 用 `.stat-row`（4 卡）
- 指标 **≤ 3 个，或只是"计数汇总"** → 用 `.databar`（一行，省 200px 高度）
- 线上首页/方案工作室/PPT 页都是 3 个数字占 3 张大卡 → 一律改 `databar`

**指标卡语义着色**：
- 每个指标必须挂**唯一的语义色左边框**（`is-red / is-orange / is-amber / is-green / is-blue / is-primary`）
- **禁止** 5 张卡同权重同颜色（线上资质台账五卡就是这个问题：最该报警的「未登记 25」和其他数字长得一样）
- 数值用 mono 23px 680；单位 `<small>` 12px；foot 写"变化"或"构成"

### 3.7 弹窗 / 抽屉 / 确认

| 类型 | 形态 | 宽度 | 何时用 |
|---|---|---|---|
| 表单弹窗 | 居中 modal | 480–560px | 新建、编辑、设置（字段 ≤ 8 个） |
| 详情抽屉 | 右侧 drawer | 480–560px | 看详情不离开列表（情报详情、检查报告） |
| 危险确认 | 居中 modal + `.modal--danger` | 400–440px | 删除、停用、清空、覆盖 |
| 全局命令 | 居中 modal | 560–640px | ⌘K 搜索 |
| 长表单 | 右侧 drawer | 560–720px | 字段 > 8 个，或需要边看列表边填 |

**危险确认弹窗必须包含三件事**：
1. 标题写"将要发生什么"（"停用张经理的账号？"而不是"确认操作"）
2. `.danger-box` 写**后果一句话**（"停用后该成员将被立即踢出登录会话，历史记录保留"）
3. 主按钮是 `btn--danger-solid` 且文字是动词（"确认停用"，不是"确定"）

**禁止**：用 `window.confirm()`；弹窗内再套弹窗；危险弹窗与表单弹窗同尺寸同色（视觉上必须一眼区别）。

### 3.8 空态 / 加载 / 长任务

**空态四要素（缺一不可）**：
```
图标（44px 圆角方块，primary-50 底）
标题（13.5px 600）：说清"没有什么"
说明（12px）：说清"为什么空 + 下一步能做什么"
主行动按钮（btn--primary btn--sm）+ 次要帮助链接
```
容器：`虚线边框 + card-2 底`（`.empty`），不要用实线卡片（实线卡片 + 空内容 = 像加载失败）。

**加载三档**（按耗时，不按心情）：
| 耗时 | 形态 | 实现 |
|---|---|---|
| < 3s | 局部转圈 + 文案 | `.spin` + "正在解析评分办法…" |
| 3s–30s | 骨架屏（模拟布局形状） | `.sk` 块，**不要**用整页透明遮罩 |
| > 30s | 进度条 + 百分比 + **取消按钮** | `.bar` + 当前阶段名 + 已用时 |

**AI 生成类操作额外要求**：
- 必须显示"正在做什么"（不是"加载中"）：正在解析废标条款 3/12
- 必须显示"已用时"和"预计剩余"
- 必须可取消，取消后保留已生成部分
- 失败必须**留在原场景可重试**，禁止无声回到原按钮

### 3.9 提示 / 反馈

| 类型 | 形态 | 用于 |
|---|---|---|
| 页内 alert | `.alert--{red/orange/amber/blue/green/primary}` | 需要持续可见的重要状态（到期预警、不可导出原因） |
| Toast | 顶部居中，1.6s 自动消失 | 操作结果（"已保存""已删除"） |
| 行内错误 | 字段下方 `.help` 变红 | 表单校验 |
| 徽标 | `.badge--{...}` | 状态标记（8 档，见下） |

**Toast 文案规约**：动词开头 + 结果，不写"操作成功"，不带感叹号，不把错误码抛给用户。
- ✅「已删除项目」「已保存草稿」「生成失败，请稍后重试」
- ❌「操作成功！」「Error 500」

**警告文案规约**：说清**后果**，不说"注意/请留意"。
- ✅「未逐条应答将判废标」「停用后该成员将被立即踢出登录会话」
- ❌「请注意检查」「该操作有风险」

### 3.10 徽标八档（全站仅此八种）

| class | 语义 | 示例 |
|---|---|---|
| `badge--red` | 阻断 / 失败 / 废标 / 已过期 | 阻断、废标、不可导出 |
| `badge--orange` | 临期 / 需尽快 | 30 天内到期、46 天未跟进 |
| `badge--amber` | 待确认 / 需判断 | 待确认、未登记、评审中 |
| `badge--green` | 完成 / 通过 / 中标 | 已通过、中标、已完成 |
| `badge--blue` | 进行中 | 编制中、解析中、需求确认 |
| `badge--purple` | 特殊阶段 | 方案交流、答疑节点 |
| `badge--gray` | 归档 / 未开始 / 无 | 已归档、未开始、无偏离 |
| `badge--primary` | 品牌强调 | "今天"、当前默认 |

加 `.badge--dot` 会带前置圆点（用于"在线/离线"这类状态）。

### 3.11 步骤条（向导型页面必备）

- 顺序：**左到右**，7 步以内全部平铺，> 7 步用「3 步 + 折叠其余」
- 状态：`done`（绿实心 + 勾）/ `on`（primary 实心 + 外环）/ `warn`（amber）/ 未开始（灰描边）
- **已完成的步骤可点击回跳**，未开始不可点（防跳步造成数据缺失）
- 每步标题下加一行小字说"这一步要产出什么"（"解析确认 · 12 条废标项"）
- 流程页底部必须有固定操作区（上一步 / 下一步），不要只靠顶上按钮

### 3.12 图表（原型用纯 CSS，线上用 echarts）

- **排序**：横向条形按值降序，禁止随机顺序
- **禁止饼图超过 5 片**（用环形 + 图例列表）
- **必须标数值**（不要让人用眼睛量长度）
- 单位统一：金额「万/亿」，百分比 1 位小数
- 配色只从 `--chart-1..5` 取，**禁止**给不同语义的数据用同一个色
- 每个图表下方一行 `small muted` 写清「数据口径 / 更新时间 / 样本量」

## 四、布局骨架（4 种，禁止第 5 种）

### 4.1 骨架定义

```
① 仪表盘型 dashboards
   ph(标题+desc+actions) → stat-row/databar → split--main(左主内容 / 右 280px 辅信息)

② 主从型 master-detail
   ph → filterbar → split--l(左 300-380 列表) + 右详情
   或：ph → filterbar → 全宽表格（列表页）/ 独立路由详情页

③ 向导型 wizard
   ph → steps → 单任务区 → 底部固定操作条

④ 工具型 tool
   ph → 单一入口区（大上传/大输入）→ 运行态 / 结果区
```

### 4.2 外壳（Shell）固定结构

```
┌──────────┬──────────────────────────────────────────────┐
│          │ TopBar 52px：折叠 / 面包屑 / 模型标识 / 通知   │
│  Sidebar │          / 全局搜索 ⌘K / 外观 / 账号          │
│  236px   ├──────────────────────────────────────────────┤
│  深青     │ 多标签栏 38px（>1 个标签时才渲染）             │
│          ├──────────────────────────────────────────────┤
│  品牌     │ 屏内 Tab（同模块多屏时）                      │
│  5 分组   │ Content：max-width 1720 / padding 18 22       │
│  账号     │   ph → note → 内容 → 翻屏条                   │
└──────────┴──────────────────────────────────────────────┘
```

**侧栏分组（5 组，17 → 16 项）**：
```
今日 · 工作台     工作台总览
客户 · 线索       客户管理 · 情报中心
方案 · 标书 · 汇报 方案工作室 · 产品映射 · PPT 与报价 · 素材库 · 标书工作台 · 标书检查 · 格式刷新
资产 · 沉淀       知识库 · 资质台账 · 竞品分析 · 小智助手
系统 · 团队       模型配置 · 团队管理（仅管理员可见）
```

**为什么把「今日 · 工作台」单独成组**：它是每天第一站，不该和业务模块并列在"客户·线索"里。
**为什么把「AI 动态」从导航移除**：仅 1 条内容却占一个黄金位置；并入情报中心的「行业前沿」频道，路由保留防外链失效。

### 4.3 响应式断点

| 断点 | 行为 |
|---|---|
| ≥ 1440 | 完整布局；6 列指标收成 3 列 |
| 1280–1440 | 指标 4→2 列；左栏 300→260 |
| 1100–1280 | 侧栏折叠为 64px 图标条；左右分栏变上下 |
| < 1100 | 单栏；看板 2 列 |
| < 760 | 全部单列；表格横向滚动 |

**明确不承诺**：本产品不做手机端主战场（售前编制标书是桌面行为），< 760px 只保证"能看能点"。

### 6.2 每个 HTML 页面只有 4 个可变点

```html
<body data-mod="customer" data-screen="customer-list" data-base="../">
```
+ `<title>` + 内容区。外壳由 `shell.js` 从 `manifest.js` 渲染。

**这意味着**：新增一屏 = manifest 加一条 + 写一个 HTML。不需要动导航、不需要动路由表、不会文案漂移（线上现在的 4 处路由元数据漂移问题从此消失）。

### 6.3 从原型到线上（映射建议）

| 原型 | 线上对应 |
|---|---|
| `design.css` 的 `:root` 变量 | 已存在于 `src/index.css` 的 shadcn HSL 变量（映射表：`--primary #0E7C99` → `--primary 193 83% 33%`） |

| `.tbl` 系列 | `ui/DataTable.tsx`（已有，需补吸顶表头 + ⋯ 菜单列 + 分页条） |
| `.badge--*` | `index.css` 里 `@layer components` 的 `.badge-success/warning/danger/neutral`（需扩到 8 档） |
| `.empty` | `common/DataStates.tsx`（已有，需补主行动按钮与四要素） |
| `.mask/.modal/.drawer` | `ui/dialog.tsx`（Radix Dialog）+ 新增 Drawer（Radix Dialog 的 side 变体） |
| `manifest.js` 的 `nav` + `mods` | `src/lib/routeRegistry.ts`（已有，结构一致；把 `screens` 扩展为子路由） |

### 6.4 拆屏对应的路由改造建议

```
/customer-management            → 列表（保留原路径，防外链失效）
/customer-management/:id        → 详情（新增）
/customer-management/kanban     → 商机看板（新增）
/customer-management/followup   → 跟进队列（新增）
/customer-management/import     → 导入与体检（新增）

/bid-workspace                  → 项目列表（保留）
/bid-workspace/:id/import       → ① 导入招标
/bid-workspace/:id/parse        → ② 解析确认
/bid-workspace/:id/outline      → ③ 大纲编制
/bid-workspace/:id/draft        → ④ 正文编写
/bid-workspace/:id/deviation    → ⑤ 偏离表
/bid-workspace/:id/check        → ⑥ 交卷自查
```

## 八、常见错误速查（写之前先看这张表）

| 错误 | 正确做法 |
|---|---|
| 三个数字做三张大卡 | 用 `databar` 一行 |
| 「保存」做成主色按钮 | 保存是次要动作，主 CTA 应该是"下一步/提交" |
| 删除按钮和编辑按钮一样大一样色 | 删除收进 ⋯ 或做成红色描边 + 确认 |
| 空列表显示表头 + 空白 | 用 `.empty` 四要素 |
| 加载用整页遮罩 | 局部 `.spin` 或骨架屏 |
| 筛选放左侧竖排 6 组 | 一行主筛选 + 抽屉 |
| 表格一列挤到换行 3 行 | 截断 + title，或调整列宽 |
| 用 emoji 当图标 | 内联 SVG（1.7 线宽） |
| 弹窗写"确认操作" | 写"停用张经理的账号？" |
| 错误提示抛 `Error: 500` | 「生成失败，请稍后重试；若反复失败请联系管理员」 |
| 面板里再套卡片 | 用 `divider` 或 `hairline` 分组 |
| 每页自定义一套表格样式 | 全站 `.tbl` 一套 |
