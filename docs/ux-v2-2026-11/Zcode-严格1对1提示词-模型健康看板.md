# Zcode + DeepSeek V4.1 flash · 严格 1:1 提示词写法（以模型「健康看板」为例）+ 难落地清单

> 日期：2026-11-09（Asia/Shanghai）  
> 真源原型：`docs/ux-v2-2026-11/prototype/model/health.html`  
> 现网：`http://localhost:8000/model-config`（单页：平台卡 + 个人配置 + 右侧测试面板，**没有**独立健康看板）  
> 同模块另两屏：`model/channels.html`（通道与默认）、`model/test.html`（连通测试）  
> 制屏规范：`prototype/AUTHORING.md`、`docs/ux-v2-2026-11/02-设计规范与组件约定.md`

## 一、为什么现网「很多」对不上

原型把「模型配置」拆成 **3 个 SubTab**：

| SubTab | 原型文件 | 现网 |
|---|---|---|
| 通道与默认 | `model/channels.html` | 揉在同一页的 DefaultBanner + Platform + PersonalList |
| 健康看板 | `model/health.html` | **整屏缺失**（`modelHealth` 只是 localStorage 挂账，不是看板） |
| 连通测试 | `model/test.html` | 右侧 `TestPanel` 常驻，未独立成屏 |

所以不是「样式差一点」，而是 **信息架构未按 UX-v2 拆屏**。投标列表/建设清单已按任务书做过一轮；模型等其它模块大多仍是旧单页。

## 二、给 Zcode 写提示词的铁律（可复用到任意屏）

### 2.1 一次只喂一屏

DeepSeek V4.1 flash 上下文有限。**禁止**一次丢「全站 70 屏」。每次只贴：

1. 本屏 HTML（如 `health.html` 全文）  
2. `design.css` 里本屏用到的 class 片段（或写「类名必须对齐 AUTHORING，映射到现有 Tailwind token」）  
3. 现网入口文件路径 + 3～5 行现状说明  
4. 验收清单（勾选项）  
5. **明确不要做**列表（含难落地项）

### 2.2 提示词结构（固定 8 块，按顺序）

复制下面模板，只改「屏名 / 路径 / 区块表 / 禁止项」。

```text
【角色】你是小智工作站前端工程师。技术栈：React 19 + Vite + TypeScript + Tailwind/现有 shell 组件。不要换栈、不要新开无关设计体系。

【目标】按 UX-v2 静态原型 **视觉与信息架构 1:1** 还原「{屏名}」。不是「大概像」。

【真源】
- 原型 HTML：docs/ux-v2-2026-11/prototype/{相对路径}.html（下面已附全文）
- 规范：docs/ux-v2-2026-11/prototype/AUTHORING.md
- 色/字号对齐 design.css 令牌观感：主色约 #0E7C99、背景约 #F1F5F7、正文约 13px；可用 Tailwind 映射，但区块顺序与文案层级必须一致。

【现网入口】
- 路由：{路由}
- 主文件：{tsx 路径}
- 现状一句话：{例如：单页配置+测通道，无健康看板}

【1:1 必须对齐的区块（按 DOM 自上而下，缺一不可）】
1. …
2. …
（只写结构+文案标签+按钮文案，不要让模型自由发挥营销文案）

【数据规则】
- 禁止为凑 UI 写假数、假医院名、假费用。
- 没有真源的字段：显示「—」或整块空态；不要用原型里的演示数字（1284、98.7%、¥186.4 等）当默认值。
- 原型里的 .note「拆前/拆后」说明条 **不要** 做到现网。

【明确不要做 / 本轮不做】
- …
（把「难落地」整段贴这里，避免模型硬造）

【验收】改完后对照原型左右分屏，下列全部勾上才算完成：
- [ ] …
```

### 2.3 附文件方式（Zcode 粘贴顺序）

1. 先贴「提示词主体」（上表）  
2. 再贴 `health.html` 全文（或说「打开仓库内该文件，以文件为准」）  
3. 若 Zcode 能读仓：写绝对路径  
   `D:\重要文件\工作的小程序\xiaozhigongzuozhan\docs\ux-v2-2026-11\prototype\model\health.html`  
4. **不要**把 API Key、医院真名、Open Design 密钥贴进提示词

### 2.4 推荐拆成 3 次对话（模型模块）

| 次序 | 提示词焦点 | 依赖 |
|---|---|---|
| ① | 路由 + SubTab：通道与默认 / 健康看板 / 连通测试（只搭壳与切换，内容可先空态） | 无 |
| ② | 通道与默认 1:1（`channels.html`）——把现有 Platform/Personal 迁过去 | ① |
| ③ | 健康看板 **壳 + 空态 + 有数据时的表头**（见难落地：多数指标暂无「—」或隐藏） | ①；真指标另开后端包 |
| （可选）④ | 连通测试独立屏（从右侧 TestPanel 迁出） | ① |

不要指望 flash 一轮做完三屏 + 真数据管道。

## 三、可直接贴给 Zcode 的「健康看板」提示词（成品）

把下面整段复制到 Zcode（DeepSeek V4.1 flash），并让它打开同仓 `health.html`：

```text
【角色】你是小智工作站前端工程师。栈：React 19 + Vite + TS + 现有 Tailwind/shell。禁止换栈、禁止平行重写整站。

【目标】新增「模型配置 → 健康看板」屏，信息架构与视觉 1:1 对齐静态原型 docs/ux-v2-2026-11/prototype/model/health.html。

【现网】
- 路由目前只有 /model-config，页面在 src/pages/ModelConfig/ModelConfigPage.tsx：页头「模型配置」+ DefaultModelBanner + PlatformModelCard + PersonalConfigList + 右侧 TestPanel。
- src/lib/modelHealth.ts 只存确定性失效挂账（model_missing / model_disabled / auth / quota_exhausted），没有调用量、成功率、P95、费用、按功能分布。

【必须先做的壳】
1. 在模型配置下增加与原型一致的三个 SubTab：「通道与默认」「健康看板」「连通测试」。
2. 「健康看板」对应独立内容区（可先 /model-config?tab=health 或子路由，与现有路由风格一致即可）。
3. 本轮只把「健康看板」按下列区块搭齐；通道页/测试页可先占位，不要删掉现有配置能力。

【健康看板 1:1 区块（自上而下）】
A. 页头 .ph
   - 标题：健康看板 + 成功率徽标（有真数据才显示数字；无则只显示标题或「暂无统计」灰徽标）
   - desc：这一屏只回答：模型现在跑得好不好、慢在哪、花在哪。……（文案与原型一致）
   - meta：统计区间 / 采样次数 / 数据更新 —— 无真源则「—」
   - 右侧：时段 seg「24 小时 | 7 天 | 30 天」+ 通道下拉「全部通道 / …」；切换先改本地 state，无数据时下方走空态
B. 不要渲染原型 .note「拆前/拆后」条
C. 五格 stat-row：本期调用 / 成功率 / P95 延迟 / 本期费用 / 缓存命中
   - 布局与标签 1:1；数值无真源显示「—」，单位小字保留
D. 主栏「按模型」表：列 = 模型 / 通道 / 调用数 / 成功率 / P50 / P95 / 失败原因 Top1 / 费用
   - 表头、导出明细、按失败原因看 按钮保留；无数据时表格空态，禁止填入原型演示行
E. 主栏下两卡：「调用量趋势」「按功能维度」——可用简单 bar；无序列数据时显示空态文案，不要画假柱
F. 右侧「失败告警」：优先用 readModelHealth() 聚合成人话告警（未配置/模型下线/额度/鉴权）；无条目显示空态
G. 右侧「关键耗时」「费用结构」：无后端指标则整卡显示「暂无采集」或隐藏，禁止写死 0.8s / ¥186.4
H. 空态（筛某通道 0 次调用）：标题/说明/「去设默认模型」「换全部通道」文案对齐原型 fold 内 empty

【数据规则】
- 严禁把 HTML 里的 1284、98.7%、¥186.4、11-06 等演示数写进代码默认值。
- 能接的：modelHealth 挂账 → 失败告警人话化（可做）。
- 不能接的：调用量/费用/P95/缓存命中/按功能 —— 本轮 UI 壳 + 空态/—，并在代码注释标 TODO:metrics。

【改动范围建议】
- src/pages/ModelConfig/* 增加 tab 状态与 HealthBoard 组件（新建 src/components/model-config/HealthBoard.tsx）
- 样式优先 Tailwind 对齐 design.css 观感；表用现有 table 模式
- 不要改 PocketBase schema；不要为指标新建假 collection 塞演示数据

【验收清单】
- [ ] SubTab 三个名称与原型一致，健康看板可切换进入
- [ ] 页头标题/desc/时段 seg/通道下拉布局与原型一致
- [ ] 五格指标区存在；无数据为 — 或空，无演示数
- [ ] 「按模型」表列齐全；无演示行
- [ ] 失败告警能展示 modelHealth 真实挂账（若有）
- [ ] 无 .note 拆前拆后
- [ ] 原 /model-config 配置与测试能力仍可达（通道 Tab 或等价入口）
- [ ] npm/tsc 与现有 ModelConfig 相关测试不挂

【本轮明确不要做】见同文档「四、难落地清单」——那些不要硬实现真数。
```

然后另开一条短消息附上：`请打开并对照 docs/ux-v2-2026-11/prototype/model/health.html 全文。`

## 四、难落地清单（提前告诉模型 / 你自己排期）

### 4.1 健康看板 · 硬拦（没有数据管就不要 1:1 真数）

| # | 原型能力 | 为什么难 | 建议 |
|---|---|---|---|
| H1 | 本期调用 / 成功率 / 采样 1284 | 现网无按次调用明细仓；sidecar 也未统一落「每次 LLM 调用」台账 | UI 壳 +「—」；另开「调用台账」后端包 |
| H2 | P50 / P95 / 关键耗时 | 需在 gateway 记录 latency 分位；现仅 TestPanel 单次 elapsedMs | 同 H1；测试耗时不要冒充 P95 |
| H3 | 本期费用 / 预算 ¥500 / 输入输出占比 | 无计价与月预算模块；各通道价目不一 | 整卡「暂无费用采集」；勿写死人民币 |
| H4 | 缓存命中 31% | 无 prompt-cache 命中遥测 | 隐藏或「—」 |
| H5 | 按功能维度（方案/标书/助手/情报） | 每次调用需带 `feature` 标签并入库 | 先空态；埋点规范另定 |
| H6 | 调用量趋势 7 日柱 | 依赖按日聚合 | 空态；不要 CSS 假柱充数 |
| H7 | 导出明细 | 无明细可导 | 按钮可先 disabled + 旁注「暂无明细」 |
| H8 | 失败「可重试/已冷却/需处理」徽章语义 | 冷却在 session（modelFailover），挂账在 localStorage，口径不全等于原型 | 只映射已有 cls；别发明新状态机硬凑 |
| H9 | 「客户跟进建议」等功能名告警 | 需失败事件带功能 id | 有则显示；无则只显示模型/原因 |

### 4.2 全站 UX-v2 1:1 · 共性难落地

| # | 点 | 说明 |
|---|---|---|
| G1 | 原型演示数据 | AUTHORING/任务书铁律：禁止假数；很多屏「好看」靠假数，现网必须空态 |
| G2 | `.note` 设计说明 | 只给评审看，**禁止**进生产 |
| G3 | shell.js 外壳 vs React AppShell | 侧栏/顶栏/多标签由两套实现；1:1 指 **content 区**，不是重做整壳 |
| G4 | SubTab / 多屏拆分 | page-split 曾 stash；全站拆屏工作量大，按模块分批 |
| G5 | design.css 原子类 → Tailwind | 可映射观感，像素级逐 class 搬运成本高且易双轨；以区块+文案+主色为准 |
| G6 | flash 模型一次吃全 HTML+全 CSS+全仓 | 易漏约束、乱改无关文件；必须「一屏一提示词」 |
| G7 | 敏感信息 | 医院名、金额、密钥不得进提示词或演示 fixture |
| G8 | 图表库 | 原型是纯 CSS bar；上 recharts 等可以，但无数据时勿渲染假 series |

### 4.3 相对好做（可进第一轮提示词）

- SubTab 壳与路由  
- 页头标题 / desc / 按钮文案 / 表头列名  
- 空态文案与 CTA（去设默认模型）  
- 用现有 `modelHealth` 做人话失败告警列表  
- 把右侧 TestPanel 迁到「连通测试」Tab（结构 1:1 另贴 `test.html`）  
- 通道页折叠「本地不可用」灰卡（对照 `channels.html`，数据已有 `locallyUnusable`）

## 五、验收时你怎么盯 Zcode

1. 打开原型：`…/prototype/model/health.html`（或经 Vite 静态路径）  
2. 打开现网健康 Tab  
3. 只盯：**区块顺序、标题文案、列名、按钮文案、空态**；数字对不上且为「—」算合格  
4. 若出现 1284 / 98.7% / ¥186 等与原型一模一样的数 → **打回**（抄了演示数据）  
5. 若删了原配置能力 → **打回**

## 六、建议你下一步怎么用

1. 先贴本文 **第三节** 提示词做健康看板壳（本机 Zcode + deepseek-v4.1-flash）。  
2. 通道与默认、连通测试各再开一轮（换 HTML 真源 + 改区块表）。  
3. 真指标（H1–H7）单独立项，不要和 1:1 UI 绑死。  
4. 若要兄嘚代写「通道」「测试」两份同款提示词，直接说要哪一屏。
