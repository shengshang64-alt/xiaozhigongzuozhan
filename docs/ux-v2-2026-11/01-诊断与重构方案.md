# 小智工作站 · 全量功能与界面的诊断与重构方案

> 版本 v2.0 · 2026-11-08
> 基线：本地 `localhost:8000` 线上 **17 个路由**的实机走查（截图 + DOM 实测）
> 视角：产品经理（该不该有、该在哪）· UI 设计师（怎么排、怎么读）· 完美主义者（每个控件是否只有一种正确用法）
> 产出：**69 屏静态界面原型** + 本诊断书 + 设计规范书，见 `prototype/index.html`

## 一、先说结论：这个产品的问题不是"不好看"，是"没分层"

我把 17 个页面逐页打开、量了 DOM 节点数 / 滚动高度 / 按钮数 / 页内标题数，得到一张很刺眼的表：

| 页面 | DOM 节点 | 滚动高度 | 按钮数 | 页内标题 | 判定 |
|---|---:|---:|---:|---:|---|
| 客户管理 | 9,688 | **12,513px（15 屏）** | 857 | 17 | 堆叠型，必须拆 |
| 方案工作室 | 9,862 | 1,022px | **918** | **25** | 堆叠型，必须拆 |
| 情报中心 | 9,505 | 1,136px | 843 | 22 | 堆叠型，收进抽屉 |
| 模型配置 | 7,013 | **2,791px** | 832 | 14 | 堆叠型，拆 |
| 团队管理 | 6,710 | 902px | 838 | 14 | 行内操作收菜单 |
| 小智助手 | 6,368 | 922px | 714 | 11 | 结构合理 |
| 资质台账 | 6,105 | 1,898px | 682 | 10 | 内容型，吸顶筛选 |
| 竞品分析 | 6,103 | 1,641px | 683 | 10 | 内容型，吸顶筛选 |
| 知识库 | 5,660 | 2,052px | 653 | 10 | 内容型，吸顶筛选 |
| 标书检查 | ~1,100 | 1,030px | 61 | 9 | 健康，但头重脚轻 |
| 格式刷新 | ~1,200 | 1,491px | 143 | 15 | 健康，文案时机错 |

**判定标准**（我按 B 端工具的常识定的，和 Ant Design / TDesign 的实践一致）：

- 健康页面 ≈ **1,000–3,000 DOM 节点 / < 500 按钮 / < 15 个页内标题 / 滚动 < 1,500px**
- **内容型长**（表格、图表本身很长）→ 加吸顶筛选 + 返回顶部即可，**不必拆页**
- **堆叠型长**（多个功能模块平铺在一页）→ **必须拆页或收进抽屉**

按这个标准，17 个页面里有 **5 个是堆叠型**（客户管理、方案工作室、情报中心、模型配置、团队管理），其中客户管理与方案工作室最严重——单页 9,000+ DOM、800+ 按钮，这不是"页面长"，这是**把 5–6 个功能页塞进了一个路由**。

### 三个贯穿全站的根因

**根因 1：没有"一类决策一屏"的边界。**
每个页面都在试图同时服务多种互斥心智：
- 客户管理同时服务「找客户（列表）」「看客户（详情）」「推商机（看板）」「查表（表格）」「补数据（批量）」5 件事
- 情报中心同时服务「处理待确认（审阅）」「浏览全部（检索）」「看原文（阅读）」「管数据源（设置）」4 件事
- 方案工作室同时服务「选方案（列表）」「写方案（编辑器）」「列清单（建设清单）」「查漏（交付检查）」4 件事

**互斥心智同屏 = 用户每做一件事都要先在一片噪声里找到入口。** 这就是为什么页面会堆到 12,513px。

**根因 2：控件没有层级。**
- 一屏里出现 3–5 个同权重按钮（客户管理的「数据体检 / 批量补全 / 全量补全 / 导出」并列）
- 危险操作与主操作同权重（方案卡的「打开编辑 / 删除」平铺）
- 禁用按钮不说话（标书检查的「开始检查」灰着，不告诉用户先选对象）

**根因 3：反馈链路断裂。**
AI 生成类操作 30 秒到 3 分钟，但没有进度、不能取消、失败了无声回到原按钮。用户唯一能做的是**反复点击**——重复消耗 token、结果混乱。

**这三个根因，就是这次重构要修的东西。** 视觉只是结果，不是目标。

## 二、重构的三条总原则（后面每个模块都从这三条推出来）

### 原则 1：一类决策，一屏

判断标准：**这一屏里，用户需要做的"决定"是不是只有一类？**
- 「确认这条情报要不要转商机」——一类决定 ✔
- 「确认情报 + 顺便看看全部情报 + 顺便管数据源」——三类决定 ✘

拆屏不是把长页面切两半，而是**按决策边界切**。所以拆完之后，屏数从 17 涨到 69，但**每一屏都不需要滚动找东西**。

### 原则 2：四种骨架，不再有第五种

走查发现线上至少有 5 种页面骨架（统计卡+列表 / 左树右内容 / 大标题+上传区 / 左右对话 / 指标+图表+列表）。用户每换一页都要重新适应一次。

重构后全站收敛为 **4 种骨架**，且每种骨架的"页头—工具栏—内容—翻页"位置完全一致：

| 骨架 | 用于 | 结构 |
|---|---|---|
| **仪表盘型** | 工作台总览、健康看板、复盘 | 页头 → 指标卡行 → 主从区块（左主内容 / 右辅信息） |
| **主从型** | 客户列表/详情、情报审阅、知识库、素材库 | 页头 → 筛选条 → 左列表(280–380px) + 右详情(自适应) |
| **向导型** | 产品映射、标书七步、格式刷新、导入 | 页头 → 步骤条 → 单任务区 → 底部固定操作区 |
| **工具型** | 标书检查、连通测试 | 页头 → 单一入口区 → 运行态/结果区 |

### 原则 3：控件只有一种正确用法

- **按钮**：一屏只允许 1 个实心主色 CTA；次级描边；三级文字；危险红描边 + 二次确认
- **下拉**：全站自绘（不用原生 select），支持分组、项尾计数、勾选态
- **筛选**：常驻只留 3–4 个最常用，其余进「筛选」抽屉并显示生效数量；禁止两级筛选并存
- **表格**：吸顶表头、行尾 ⋯ 菜单收纳次要操作、>12 行必分页
- **弹窗**：表单类居中（≤560px），详情/预览类右抽屉（≤560px），危险类必须先说后果
- **空态**：图标 + 一句话 + 主行动按钮 + 次要帮助，禁止死白

（完整规范见 `02-设计规范与组件约定.md`）

## 三、逐模块诊断与拆屏决策

> 格式统一：**现状（实测）→ 为什么必须改（产品/布局/操作三视角）→ 拆成哪几屏 → 每屏解决什么**

### 3.1 工作台总览（首页）

**现状**：14 个区块、2,958px、需滚 4 屏。自顶向下：欢迎横幅 → 今日必看 → 投标节点 → 3 个统计数字 → 商机分布图 + 待办 → 最近商机动态 + 待跟进商机 → 胜负复盘 → 最新动态（17 条情报）→ 情报摘要（5 条）→ 进行中事项 → 我的项目跟进清单。

**产品视角**：首页应该只回答三个问题——*今天必须处理什么？我手上的项目卡在哪？下一步点哪里？* 现状三个都没答好：
- 「今日必看」只放了资质预警一条，情报、标书节点、待办散落在下方
- 「进行中事项」（最常用）被压到第 5 屏
- 「商机分布」「胜负复盘」在无数据时呈现「共 0 条」，**占了黄金位置却提供零价值**

**布局视角**：欢迎横幅吃掉首屏 1/4；「最新动态」与「情报摘要」内容高度重叠（都在展示情报流）；3 个统计卡信息密度极低。

**操作视角**：所有卡片同权重同圆角同阴影，扫视时没有视觉锚点。

**拆屏决策**：
| 屏 | 解决什么 |
|---|---|
| 总览 | 4 张预警指标（可点直达）+ 今日优先 3 任务 + 进行中事项（带七步微缩）+ 该唤醒商机 + 右栏快捷入口/节点/模型用量 = 一屏半内 |
| 待办中心 | 全部 7 条待办：按来源×优先级×时间分组，可批量改期/认领/关闭，回写来源页 |
| 投标节点 | 5 类硬节点（报名/答疑/保证金/递交/开标）月历时间轴，逾期标红 |
| 投标复盘 | 漏斗 → 落标归因聚类 → 单项目明细，三层下钻；无数据时首页只留一行提示 |

---

### 3.2 客户管理（最严重，12,513px）

**现状**：顶部 3 张统计卡 → 3 个视图 Tab（客户列表/商机看板/客户表格）→ 左列表（带「缺 N 项」黄角标）+ 右**一半面积是空白**的详情占位区。

**产品视角**：核心流程是*找客户 → 看画像 → 补资料 → 推商机*。断点：
- 「缺 3 项 / 缺 6 项」角标很有价值，但**点击没反应**——用户不知道缺哪 3 项、去哪补。一个有潜力的功能死在最后一公里。
- 顶部常驻「未配置任何可用模型 ⚠」——模型配置是系统级设置，不该在业务页顶部永久打扰。

**布局视角**：1600px 宽屏里一半面积在显示「请从左侧选择」；每张客户卡只有名称+地区+等级+缺失数，信息密度低；列表无「按最近跟进排序」的显性提示。

**操作视角**：「数据体检 / 批量补全 / 全量补全 / 导出」四个并列按钮，其中「批量补全」和「全量补全」的区别没有任何说明——用户不敢点。

**拆屏决策**（5 屏）：
| 屏 | 解决什么 | 关键改动 |
|---|---|---|
| 客户列表 | 找客户 | 全宽表格 7 列（名称/等级/地区/最近跟进/完整度/商机/操作）；3 张统计卡压成 1 行数据条；「缺 N 项」可点弹层逐项补全；半屏空白消除 |
| 客户详情（**独立路由**） | 看客户 | 四栏同屏：档案 / 联系人 / 商机 / 跟进时间线；**可直接发链接给同事**，返回保留筛选与滚动位置 |
| 商机看板 | 推商机 | 五列（线索→初步接洽→需求确认→方案交流→已投标）+ 列内合计金额 + 阶段停留天数 |
| 跟进队列 | 该唤醒谁 | 超 90/60/30 天三组 + 本周跟进计划 + 批量建跟进 |
| 导入与体检 | 补数据 | 4 步向导；「将影响 148 家客户、7 家手机号冲突、预计 2 分钟」**影响范围预算先行** |

### 3.3 情报中心（3,600px，信息密度失控）

**现状**：手动录入/批量管理工具行 → 4 张指标卡（29/40、980、40、0）→ 一大段蓝色说明文字 → 左侧 6 组筛选 + 中部筛选行 → 今日工作清单 → 搜索框+筛选下拉 → 情报卡片流。

**产品视角**：核心流程 *抓取 → 确认 → 打标 → 转商机/转标书*，但被拆散在三个区域（今日工作在中段、批量操作在顶部、转商机藏在每条里）。**处理 20 条待确认情报，视线要在 3,600px 里上下往返。**

**布局视角**：
- 「29/40」这种分数式写法与「980」「40」「0」三个纯数字并列，语义完全不同却长得一样
- 大段蓝色说明文字（数据源与抓取频率）属设置级信息，永久占首屏
- **左侧 6 组筛选 + 中部筛选行 = 两级筛选并存，用户不知道哪级生效**

**操作视角**：每条情报 5 个操作（AI 摘要打标/确认/编辑/标重点/原文）平铺一行，权重无差异；「编辑」（最低频）和「确认」（最高频）长得一样。

**拆屏决策**（5 屏）：
| 屏 | 解决什么 | 关键改动 |
|---|---|---|
| 审阅（核心） | 处理待确认 | 双栏主从：左 29 条待确认列表 / 右详情审阅；键盘 J/K 逐条 + Enter 确认；主 CTA「确认并转商机」实心，其余收 ⋯ |
| 浏览 | 检索全部 | 一行主筛选 + 高级筛选抽屉（带生效数）；紧凑表格 |
| 详情 | 读原文 | 清洗后阅读视图 + 关键实体抽取 + 转商机/转标书/标重点 |
| 行业前沿 | 原 /ai-hot 并入 | 按医疗信息化主题订阅；导航从 17 项减到 16 项 |
| 数据源 | 管设置 | 源健康度、成功率、失败原因（原首屏蓝色说明书归档于此） |

### 3.4 方案工作室（918 按钮 / 25 标题）

**现状**：建设清单/方案编制两 Tab → 大标题+说明 → 新建/导出 → 模板下载条 → 3 张统计卡（1/1/0）→ 类型筛选片+搜索 → 方案卡片 → 底部「方案类型说明」+「行业系统库（12 个系统标签）」两个知识卡。

**产品视角**：页面 60% 篇幅给了**新手教学**（类型定义、系统库标签、模板下载）。这些对第一次用的人重要，对每天用的老用户是永久噪音。正确做法是首次引导时展示，之后收进帮助。

**布局视角**：3 张等宽大卡装 3 个小数字，浪费 200px；方案卡只有 1 张却独占整行。

**操作视角**：卡片上「打开编辑 / 以此为底稿 / 入素材库 / 删除」四个平铺，**删除与打开编辑视觉权重相同**。

**拆屏决策**（4 屏）：
| 屏 | 解决什么 |
|---|---|
| 列表 | 数据条替代三卡；教学信息折叠为「📖 方案类型怎么选」；卡片只留「打开编辑」+ ⋯ |
| 编辑器（核心） | 三栏：左大纲树 / 中正文 / 右检查栏（需求覆盖 18/22 环形 + 事实接地 3 处待核 + 写作体检） |
| 建设清单 | 系统清单树 → 需求映射 → 金额汇总 → 转大纲（原本和编辑器挤在一起） |
| 交付检查 | 需求覆盖率 / 事实接地 / 导出门禁 三栏体检；「仍然导出」是危险按钮且记录风险 |

### 3.5 产品映射（向导被摊成杂货铺）

**现状**：大标题 + 长说明 → 3 个 Tab（记忆库/公司库/导入 ONE-LINK）→ 3 个来源 Tab（上传粘贴/从招标文件/从方案需求）→ 上传区 + 大文本框 → 底部一行小字「上传清单后此处展示对照结果」。

**产品视角**：这是**向导型任务**（上传清单 → 对照 → 导出），却被平铺成杂货铺：**两层 Tab 叠加**，用户分不清「记忆库/公司库」与「上传粘贴」的关系。

**布局视角**：上半屏全是输入区，下半屏一行小字说结果会显示在这里——**结果区没有任何视觉存在感**；页面 70% 空白，核心功能（对照结果表）完全没出现。

**操作视角**：文本框里的示例文本是真实内容还是演示？分不清；「带入技能 / 按粘贴文本对照」用灰色小字，看起来像禁用。

**拆屏决策**（4 屏）：选清单（三来源卡片化、示例用占位符样式）→ 对照（左右分栏：左原文行 / 右候选产品 / 中间置信度）→ 结果（结果表成为主角，带 A/B/C 覆盖评级与导出）→ 产品库（三个 Tab 收敛为一个资产页）。

### 3.6 PPT 与报价（两个业务挤两个 Tab）

**现状**：汇报 PPT / 报价清单两 Tab → 3 张统计卡 → 「医疗售前汇报 PPT 生产线」大标题卡 → 搜索 → 空态。

**产品视角**：PPT 和报价是**两个独立业务**，被硬塞进一个页面的两个 Tab：
- 报价清单的统计卡（总金额 0.00）在「汇报 PPT」Tab 下依然显示——**数据与上下文错位**
- 在「报价清单」Tab 里，页面标题仍是「医疗售前汇报 PPT 生产线」——**标题不随 Tab 切换**

**布局视角**：3 张统计卡全为 0，传达的是「你还没用过」，但展示方式像 3 个「失败的指标」。

**操作视角**：空态引导语是说明文字而非可点按钮——用户要读完一段话再去找按钮。

**拆屏决策**（5 屏，两条独立路径）：
PPT 线：**PPT 列表**（模板、页数、生成状态）→ **PPT 编辑器**（左页序 / 中画布 / 右属性与素材 + 底部一致性检查）
报价线：**报价清单**（排序、有效期）→ **报价编辑**（明细表 + 实时合计 + 毛利提示 + 折扣超限确认弹窗）→ **报价单预览**（对外版式 + 用印 + 发送记录）

### 3.7 素材库（抓取是动作不是视图）

**现状**：四个 Tab（素材总览/联网抓取/本地导入/库设置）→ 4 张统计卡（素材 0 / 磁盘 0B / 分类 0 / **回收站 4**）→ 搜索+筛选 → 空态。

**产品视角**：素材库的价值在**使用端**（PPT 生成时命中本地库），不在管理端。但：
- 「回收站 4」在库里是空的时出现，对用户是困惑而非信息
- 「联网抓取」作为 Tab 与「素材总览」并列——**抓取是动作不是视图**

**拆屏决策**（4 屏）：总览（单视图 + 使用排行 Top5 让价值可见）→ 导入（3 步向导 + 重复检测）→ 联网抓取（关键词+来源+版权提示）→ 库设置（分类/占用/回收站，清空需确认）

### 3.8 标书工作台（核心生产链，列表与流水线断裂）

**现状**：大标题「标书工作」→ 投标复盘卡（5 个基本全空的统计）→ 「投标全流程工作台」卡（说明 + 导出 CSV + 新建 + 模板下载条）→ 状态片 + 卡片/表格切换 + 搜索 → 项目卡片。**七步流水线全部内联在同一个页面里**。

**产品视角**：这是全站心脏，核心流程是七步流水线。最大问题：**项目列表页与七步流水线之间是断裂的**——
- 项目卡上只有「已开标 / 距开标 25 天」和「0/0 章成稿」，**没有显示项目处于七步中的哪一步**，用户必须点进去才知道该干什么
- 「投标复盘」卡放在列表上方，但中标率全为空

**布局视角**：顶部「标书工作」大标题 + 卡内大字「投标项目」形成**双重标题**；「0/0 章成稿」对进行中项目是失败表达（分母 0 说明大纲还没生成，用户读不出这层）。

**操作视角**：模板下载条是全局资源，却放在项目列表卡片里，每次进来都占一行。

**拆屏决策**（10 屏）：
| 屏 | 解决什么 |
|---|---|
| 项目列表 | 项目卡带**七步微缩进度条**（done/now/未开始），一眼看出卡在哪；模板下载收进 ⋯ |
| ① 导入招标 | 上传 + 自动识别信息（逐字段标"已识别/需确认"）+ 包件选择 + 重复项目拦截 |
| ② 解析确认 | 四类结果分栏确认：废标条款 12（3 待确认）/ 评分办法 22 点 / 技术参数 128（★9）/ 时间节点 5 |
| ③ 大纲编制 | 左大纲树 / 中章节编辑 / 右**评分点覆盖热力**（18/22，缺 4 红） |
| ④ 正文编写 | 三栏：章节树 / 正文+参数响应表 / 右栏废标风险 3 + 一致性 + 写作体检 |
| ⑤ 偏离表 | 128 条参数应答表，分组表头，分页 100 行，未应答 7 条单独可批量带入 |
| ⑥ 交卷自查 | 四道闸门（废标/一致性/暗标/格式）+ 问题清单 + 导出按钮禁用并说明原因 |
| ⑦ 组卷导出 | 组卷顺序拖拽 + 版式设置 + 导出清单（已过闸门 ✓） |
| 模拟答辩 | 评委问题预测 12 条 + 应答要点 + 讲标稿 + 倒计时 |
| 归档复盘 | 开标结果回填 + 中标率漏斗 + 废标归因聚类 + 结论回流知识库 |

### 3.9 标书检查（工具页做成复杂页）

**现状**：标题「标书检查中枢」→ 模式切换 → 左「上传文件」/ 右「选择标书项目」两个等宽大卡 → AI 复核 + 开始检查 → 下方 Tab + 一行引导文字。

**问题**：
- 上传与选项目是**互斥入口却并列**，用户要先想清楚「我的文件在哪」
- 「开始检查」灰着但**不告诉用户先选对象**——按钮哑巴了
- 模式切换是重要选项，却用两个灰色按钮低调处理
- **下方 60% 区域只有一行文字，整个页面头重脚轻**

**拆屏决策**（4 屏）：新建检查（单一大上传框内含两个入口 + 模式单选卡带说明 + 最近报告）→ 检查中（进度 + 规则包逐项 + 实时冒问题 + 可取消）→ 检查报告（问题分级 + 原文定位 + 导出批注 docx）→ 历史报告（可复访 + 两次对比）

### 3.10 格式刷新（好底子，两处浪费）

**现状**：步骤条（1 上传 → 2 选模板 → 3 预览 → 4 套用）+ 左栏（上传+模板+刷新范围）+ 右栏（预览对比空态 + 保存套用 + 微调配置）。

**这是全站布局最规范的页面之一**，三个具体问题：
- 右栏第 4 步有**约 200 字的密集小字说明**（保存逻辑与覆盖规则）——关键安全说明写成了没人读的长段落
- 「一键应用格式」和「导出刷新后文档」的先后关系没有视觉暗示
- 微调配置区默认展开，抢预览区位置

**拆屏决策**（2 屏）：上传与模板（安全长文 → 一句话 + 折叠「查看覆盖规则」）→ 预览套用（左右对比 + 带序号 ③④ 的按钮 + 套用时确认弹窗说明会备份 .bak）

### 3.11 知识库（两个搜索框 + 长警告）

**现状**：三按钮 → 团队知识库 2175 / 我的笔记 4825 两个大数字 Tab → 全文检索框 → 黄色 AnyTXT 警告条（含下载/端口/绑定等长指引）→ 左目录树 + 右文档卡片流。

**问题**：
- **页面上有两个搜索框**（顶部「搜索标题与正文关键词」+ 中部「正文全文检索」），用户不知道用哪个、结果有何区别
- AnyTXT 未启用的黄色警告条占很大面积，长文案包含大量操作指引——**设置问题打断检索主流程**
- 「2175 / 4825」视觉冲击强但无行动价值；目录树仅 20% 宽，长目录名被截断
- 文档卡缺少「最近在项目里被引用过」这种高价值信号

**拆屏决策**（6 屏）：文档库（单搜索入口 + 目录树可拖宽 + 卡片带「被引用 N 次」）→ 全文检索（结果分「标题命中 / 正文命中」两组）→ 知识原子（一等公民：可复用事实单元 + 冲突提示 + 引用次数）→ 原子审核（逐条采纳/改写/丢弃）→ 问知识库（命中可溯源，**未命中 vs 真无资料要区分**）→ 上传文档（含解析状态）

### 3.12 资质台账（业务价值最实，短板在分档）

**现状**：5 张统计卡（已过期 1 / 30 天内 3 / 90 天内 0 / 未登记有效期 25 / 总数 34）→ 红色预警条 4 项 → 搜索筛选 → 34 行表格。

**问题**：
- 5 张卡里「**未登记有效期 25**」是最行动导向的数字（25 张证书连有效期都没登记！），视觉上和其他数字完全一样
- 预警条列出 4 项，点击只跳到台账，**不能定位到那一行**——用户还要在 34 行里找
- 列宽不合理：证书名称被挤压换行 2–3 行，操作列两个图标占固定宽度
- 「未登记」灰色胶囊 25 个，满屏灰点稀释了真正的警报
- 编辑/删除图标 16px 热区太小；**无批量操作**

**拆屏决策**（3 屏）：台账（风险四档着色 + 未登记升为 amber 警报 + ⋯ 菜单 + 批量操作条）→ 预警处理（逐条处理：定位行/续期/标记不适用 + 受影响项目提示）→ 批量登记（选择 25 张 → 统一日期 → 预览影响）

### 3.13 竞品分析（行业研报 vs 应标参谋）

**现状**：3 个 Tab（市场总览/能力对标/厂商档案）→ 数据口径说明条 → 4 张市场规模卡（181.9 亿/42.2 亿/53.7 亿/23.7 亿）→ 五年中标金额排行条形图。

**产品视角**：售前用竞品分析的典型场景是**应标前**：「这标的对手可能是谁？强项弱项？历史中标价多少？」而现状「市场总览」回答的是**行业研究问题**（市场规模、运营商份额），与「我该投多少钱」的微观决策距离很远。

**拆屏决策**（4 屏）：**应标视角为默认 Tab**（输入医院/项目 → 历史中标厂商 Top3 + 价格区间 + 参数倾向 + 3 条应标建议）→ 市场总览（降级为第二 Tab）→ 能力对标（12 维度矩阵，可导出用于技术分）→ 厂商档案（中标记录 + 常用参数 + 报价区间 + 竞争话术）

### 3.14 小智助手（价值证明不足）

**现状**：3 个 Tab（会话/记忆/技能）→ 左侧会话列表 → 右侧对话区（欢迎语 + 3 个快捷问题 + 输入框）。

**问题**：
- 快捷问题不随页面上下文变化（在标书页唤起时应变成「这份标书还差几章？」）
- 会话列表全是「快捷会话 14 天前」这种**无信息标题**，无法找回历史
- 「记忆」和「技能」藏在顶部 Tab，多数用户从未点开——而这恰恰是助手区别于普通聊天框的核心资产
- 输入框旁**没有「我能做什么」的能力边界**，用户问一个答不了的就会流失

**拆屏决策**（3 屏）：会话（上下文感知快捷问 + 自动语义标题 + 4 张能力卡片 + 右栏能力边界说明）→ 记忆（42 条：可编辑/可失效/可看来源）→ 技能（6 个技能 + 输入输出示例 + 挂到流程节点）

### 3.15 模型配置（管理员低频页，让人紧张）

**现状**：当前默认模型横幅 → 公共模型区（**红色「本地不可用」**）→ 个人模型配置区（Open Design + 6 个模型，各带"设为默认/测试"）→ 右侧测试面板（未测试时是整块说明文字）。

**问题**：
- 「公共模型 本地不可用」的红色警告**永久悬挂**——这是已知且不可解决的环境限制（本地部署必然拿不到平台内置模型登录态），**它不是错误而是事实**，用红色呈现让管理员每次进来都心里一紧
- 「5 个配置未设默认模型…默认模型就会静默改变」语义过于技术化
- 「设为默认」这种高影响操作**没有确认和后果提示**（改默认 = 全站 AI 生成行为改变）
- 右栏未测试时是说明文字占位，浪费可展示运维数据的面积

**拆屏决策**（3 屏）：通道与默认（不可用模型改为**折叠灰卡**默认收起 + 默认模型链三层 + 「设为默认」二次确认说明影响范围）→ 健康看板（24h/7d 调用量、成功率、P95、费用、失败原因 Top1，按模型 + 按功能维度）→ 连通测试（首字延迟、流式、错误人话化：「该模型是平台内置的，只在线上部署可用」+ 一键切到可用模型）

### 3.16 团队管理（安全细节缺失）

**现状**：标题+说明 → 添加成员 → 成员列表 7 行（头像 + 姓名 + 状态徽章 + 角色下拉 + 启停按钮 + 编辑）。

**问题**：
- 列表里出现「???????????(???)」**乱码成员**——创建时对特殊字符/编码无校验与兜底
- 【QA】前缀测试账号与正式成员混在一个列表，无分组或过滤
- 「停用」是危险操作（导致成员无法登录）**却没有确认**
- 角色下拉三个选项（管理员/编辑/只读）**没有权限差异说明**
- 缺「最近登录时间」——管理员看不出哪些是僵尸账号

**拆屏决策**（3 屏）：成员（最近登录列 + 测试账号分组 chip + 名称异常兜底显示 + 停用二次确认）→ 角色权限（18 项 × 3 角色矩阵，允许/不允许/仅自己）→ 设置与审计（团队信息/登录策略/备份 + 操作审计日志）

## 四、跨模块流程的重排

原系统的模块间跳转是"断的"——情报转商机、商机转标书、标书归档回流知识库，都靠人手动搬。重构后定义 4 条显式流转：

```
① 线索流：情报确认 → 转商机（携带原文+来源，预填商机卡）→ 客户详情 → 建档补齐
② 生产流：产品映射（清单对照）→ 方案（引用原子）→ 标书①~⑦ → 标书检查（交卷闸门）
③ 汇报流：标书/方案 → PPT（从方案生成）→ 报价（从产品库导入）→ 报价单预览
④ 沉淀流：标书归档 → 复盘归因 → 知识原子 → 被下一份方案/标书引用
```

每条流转在原型中都用可点击的「→ 直达」标签表示，并在目标屏预填来源上下文（原型中以 `alert--primary` 的"来源上下文"条示意）。

## 六、不做什么（明确边界）

1. **不做响应式移动端专项** —— 原型按 1280–1920 桌面设计，<1100px 只保证侧栏折叠 + 单栏可读
2. **不改后端数据契约** —— 原型中的字段与线上 `bidTypes.ts` / `customerTypes.ts` 对齐，不发明新字段
3. **不引入新组件库** —— 继续用现有 Radix + Tailwind，`design.css` 的 class 可直接映射为 Tailwind 组合类
4. **不做视觉大换血** —— 保留医疗青蓝主色（#0E7C99）与深青侧栏，只做层级、密度、语义色的修正
5. **不删除任何现有路由** —— `/ai-hot` 从导航移除但路由保留，防外链失效

## 七、如果只做一件事

**把「一类决策一屏」落实下去。**

这是 12,513px 和 918 个按钮的根因，也是用户每天真正付出的成本。视觉细节（圆角、阴影、配色）都是可以后补的，但一瓶子里塞六个功能这件事，越晚改代价越大——因为每加一个功能，都在往已经堆满的页面上再堆一层。
