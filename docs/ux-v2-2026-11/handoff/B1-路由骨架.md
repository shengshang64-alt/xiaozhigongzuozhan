# B1 · 路由骨架（子路由 + 屏内 Tab）—— 全站最危险的一批

> 批次：B1 / 10　预计轮次：1–2
> 前置：B0（需要 `DataBar` 可不用，但 token 必须先落）
> 风险：**中高**（动外壳，17 个页面全部受影响）
> 粘贴顺序：CONTRACT.md → 本文件 → CHECKLIST.md

---

## 一、这一批要交付什么

**一句话**：让路由注册表支持「一个模块 = 多个子屏」，并在外壳里加一条**屏内 Tab 栏**；**现有 17 个页面一个都不改**，只是多了一个"模块下第几屏"的概念。

**这一批不许改任何页面文件。** 页面不改也能跑，因为第一屏的组件还是原来的。

---

## 二、为什么必须先做这一批

线上现在是**扁平 17 条路由**，且 `workspaceTabs.ts` 明确假设：

```ts
// 标签粒度 = 路由路径（本应用全是扁平顶层路径），同一路径只开一个标签
```

改成子路由后（`/customer-management/:id`），如果不改这个假设，**打开 5 个客户详情就吃掉 5 个标签位**（`TAB_LIMIT = 6`），标签栏直接爆掉。

所以 B1 要同时处理两件事：
1. 路由表支持「模块 → 屏列表」
2. 标签粒度从「路径」改成「模块」

## 四、任务 1：路由表支持子路由（`src/lib/routeRegistry.ts`）

### 4.1 现状

```ts
type RouteMeta = {
  path: string
  label: string
  icon: LucideIcon
  Component: LazyExoticComponent<ComponentType>
  loader: () => Promise<{ default: ComponentType }>
  adminOnly?: boolean
}

const ROUTE_DEFS: RouteDef[] = [
  def("/customer-management", "客户管理", Users, () => import("@/pages/CustomerManagement/index.tsx")),
  // …17 条
]

export const NAV_GROUPS = [
  { title: "客户 · 线索", paths: ["/", "/customer-management", "/intel-center"] },
  // …
]
```

`ROUTE_BY_PATH`、`hasRoute`、`labelFor`、`preloadRoute` 全部假设「path 是精确匹配的扁平路径」。

### 4.2 目标结构

新增一层「模块」概念，同时**保持向后兼容**（现有 API 一个都不删）：

```ts
/** 一个屏 = 模块下的一个子页 */
export type ScreenMeta = {
  /** 屏 id，与 docs/ux-v2-2026-11/prototype/assets/manifest.js 的 screen id 逐字一致 */
  id: string
  /** 屏内 Tab 文案，与 manifest.js 的 tab 逐字一致 */
  tab: string
  /** 相对模块路径的子段；第一屏为空字符串 "" */
  slug: string
  /** 完整路径（模块路径 + slug） */
  path: string
  Component: LazyExoticComponent<ComponentType>
  loader: () => Promise<{ default: ComponentType }>
  /** 仅管理员可见（沿用现有语义） */
  adminOnly?: boolean
}

export type RouteMeta = {
  /** 模块根路径，如 "/customer-management" */
  path: string
  /** 模块名，如 "客户管理"（侧栏 / 标签栏 / 文档标题用） */
  label: string
  icon: LucideIcon
  /** 该模块的所有屏，第一项必为模块根（slug === ""） */
  screens: ScreenMeta[]
  /** 兼容字段：等于 screens[0].Component（B2 之后逐步不再使用） */
  Component: LazyExoticComponent<ComponentType>
  /** 兼容字段：等于 screens[0].loader */
  loader: () => Promise<{ default: ComponentType }>
  adminOnly?: boolean
}
```

  path: string,

⚠️ **这一批只改路由定义，不创建这些 `import()` 里的文件。**
`import()` 指向不存在的文件会让 `tsc` 报错 —— 所以这一批的正确做法是：

**方案 A（推荐）：先只声明模块根屏，其余屏在 B2 起逐批补上**

```ts
def("/customer-management", "客户管理", Users, [
  { id: "customer-list", tab: "客户列表", slug: "", loader: () => import("@/pages/CustomerManagement/index.tsx") },
]),
```

这样 B0/B1 阶段线上行为**完全不变**（每个模块只有 1 屏、屏内 Tab 不显示），B2 起每批往数组里加一条 + 建对应页面文件。

> 这就是「渐进式」的关键：**先让骨架能承载多屏，再一屏一屏填**。

**方案 B（不推荐）**：一次性把所有屏的 import 写进去，同时创建 51 个占位页面文件。
理由：违反"一次只改一件事"，且占位文件会在后续批次反复改，徒增冲突。

### 4.4 必须保留的现有导出（一个都不能删）

```ts

export function hasRoute(path: string): boolean         // 改成支持子路由前缀匹配

export const NAV_GROUPS: { title: string; paths: string[] }[]  // 保持（paths 仍是模块路径）
```

### 4.5 新增导出

```ts
/** 模块路径 → 模块元数据 */
export const MODULE_BY_PATH: Record<string, RouteMeta>

/** 屏完整路径 → 屏元数据（含所属模块） */
export type ScreenWithModule = ScreenMeta & { modulePath: string; moduleLabel: string; moduleIcon: LucideIcon }
export const SCREEN_BY_PATH: Record<string, ScreenWithModule>

/** 取某个路径属于哪个模块（子路由返回模块根路径）；未注册返回 null */
export function modulePathOf(path: string): string | null

/** 取某个路径对应哪个屏（子路由返回屏）；未注册返回 null */
export function screenOf(path: string): ScreenWithModule | null

/** 取某模块的全部屏（给 ScreenTabs 用） */
export function screensOfModule(modulePath: string): ScreenMeta[]
```

### 4.6 匹配规则（**这是本批最容易做错的地方**）

```
输入 /customer-management           → 模块 /customer-management，屏 slug=""（客户列表）
输入 /customer-management/detail    → 模块 /customer-management，屏 slug="detail"
输入 /customer-management/unknown    → 模块 /customer-management，屏 = null（该模块下无此屏）→ 渲染 NotFound
输入 /not-a-module                   → modulePathOf 返回 null → 渲染 NotFound
输入 /（首页模块根）                   → 模块 "/"，屏 slug=""
```

**匹配实现要求**：
- 用**最长前缀匹配**（`/customer-management-2` 不能被 `/customer-management` 吃掉）
- 必须按路径段分割后比较，**不许用 `startsWith` 直接比字符串**（否则 `/customer` 会匹配 `/customer-management`）
- 尾斜杠归一化：`/customer-management/` 与 `/customer-management` 视为同一路径

## 五、任务 2：标签粒度从「路径」改成「模块」（`workspaceTabs.ts`）

### 5.1 现状

```ts
export const TAB_LIMIT = 6
// 规则：标签粒度 = 路由路径，同一路径只开一个标签
export function openTab(state, path) {
  if (!hasRoute(path)) return state
  const items = state.items.includes(path) ? state.items : [...state.items, path]
  return { items: evict(items, path, state.touched, path), active: path, touched: touch(state.touched, path) }
}
```

### 5.2 目标

```ts
// 标签粒度 = 模块路径。同一模块的多个屏共用一个标签。
// 理由：标签上限 6，若按屏开标签，5 个客户详情就会把标签栏占满。
export function openTab(state: WorkspaceTabsState, path: string): WorkspaceTabsState {
  const mod = modulePathOf(path)
  if (!mod) return state
  const items = state.items.includes(mod) ? state.items : [...state.items, mod]
  return { items: evict(items, mod, state.touched, mod), active: mod, touched: touch(state.touched, mod) }
}
```

### 5.3 连带要改的地方

`WorkspaceTabsState.active` 语义从「当前路径」变成「当前模块」。
`TabbedOutlet` 用它判断哪个标签面板可见 —— 必须一起改（见任务 4）。

`workspaceTabStore.ts` 的 `ensureTab(uid, pathname)` 调用点也要改成传模块路径，或让 `ensureTab` 内部自己转换。

**保持向后兼容**：`workspaceTabStore` 的对外 API（`ensureTab` / `activateTab` / `closeTabAt` / …）签名不变，内部转换。这样 `WorkbenchShell.tsx` **不用改**（少改一个外壳文件，风险更低）。

⚠️ 如果 `WorkbenchShell.tsx` 必须改，报告出来，我在写域里加它。**默认不允许改它。**

## 七、任务 4：`TabbedOutlet` 支持子路由

**现状**（关键部分）：

```tsx
if (!hasRoute(pathname)) return <NotFound />
return (
  <>
    {tabs.items.map((path) => {
      const meta = ROUTE_BY_PATH[path]
      if (!meta) return null
      const Page = meta.Component
      const active = path === tabs.active
      return <div key={path} hidden={!active} …>…<Page /></div>
    })}
  </>
)
```

**改动**：

1. `tabs.items` 现在是**模块路径**，`tabs.active` 也是模块路径
2. 每个标签面板要渲染**当前屏**的组件，而不是模块的 `Component`
3. 保活语义要确认：**同一模块切屏时，是否要保留上一屏的 DOM 状态？**

   **这一批的决定：不保留。** 同模块切屏 = 卸载上一屏、挂载新屏（因为每个屏是独立页面，各自拉数据）。
   跨模块切换 = 保留各模块最后停留的屏的 DOM（沿用现有保活逻辑）。

   实现：
   ```tsx
   // 每个标签记住「该模块最后停留的屏路径」
   const lastScreenByModule = useRef<Record<string, string>>({})
   useEffect(() => { const m = modulePathOf(pathname); if (m) lastScreenByModule.current[m] = pathname }, [pathname])
   ```
   ⚠️ 这个 `useEffect` 里更新 ref 是安全的（ref 不是 state，不触发 `set-state-in-effect`）。
   **不许用 `useState` 存这个映射** —— eslint 预算里 `react-hooks/set-state-in-effect` 已有 74 条，只许下降。

4. `hasRoute(pathname)` 要能识别子路由；识别不了的具体屏（`/customer-management/unknown`）要渲染 `NotFound`
