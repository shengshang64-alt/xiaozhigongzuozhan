## 三、知识库 6 屏

### 3.1 核心改造：两个搜索框合一

**原状态（全站最典型的"用户不知道用哪个"）**：
- 顶部「搜索标题与正文关键词」
- 中部「正文全文检索」

用户不知道两者区别、结果有何不同。

**目标（文档库屏）**：**一个搜索框**
**目标（全文检索屏）**：单框 + 结果分两组（标题命中 8 / 正文命中 34）

### 3.2 文档库（`/knowledge`）

| # | 改造 | 原状态 | 目标 |
|---|---|---|---|
| 1 | **单搜索入口** | 两个搜索框 | 一个（跨标题与正文） |
| 2 | **AnyTXT 警告压缩** | 黄色警告条含下载/端口/绑定等长指引，占大面积 | 一行可收起 + 「查看配置」链接 |
| 3 | **数字 Tab 弱化** | 「团队知识库 2175 / 我的笔记 4825」两个大数字 Tab | 移到目录树（一行计数） |
| 4 | **目录树可调宽** | 20% 宽，长名截断（"互联互…"） | 260px 可拖拽 |
| 5 | **文档卡加价值信号** | 格式/标题/摘要/标签/来源/时间 | 增加「被引用 N 次」徽标 |

### 3.3 全文检索（`/knowledge/search`）

单搜索框 + 范围 seg（全部/标题/正文/原子）
结果分两组：**标题命中**（8 条）/ **正文命中**（34 条，显示命中片段，命中词高亮）
左侧筛选：分类 / 来源 / 时间（chip）

**必须演示"未命中"状态**：
- `EmptyState`「没有找到『DRG 智能分组』相关文档」
- 两个按钮：换个词 / 去问知识库
- 一行说明：**「未命中 ≠ 库里没有」**，可能只在本地文件里（AnyTXT 未启用）

### 3.4 知识原子（`/knowledge/atoms`）—— 一等公民

**这是本批最重要的一屏。**

知识原子 = 可被方案/标书直接引用的最小事实单元。

| 区块 | 内容 |
|---|---|
| `DataBar` | 原子 1,842 · 待审核 312 · 本月新增 96 · 引用 Top3 |
| 表格 | 原子内容（一句话事实）/ 分类 / 适用场景 / 引用次数 / 来源文档 / 状态 / 操作 |
| 冲突提示 | 同一事实两个版本 → `badge-danger`「与 #A-1182 冲突」 |
| 右侧 | 「高频引用 Top5」chart-bars + 「冲突待裁决 3」 |

**原子类型**（取自现有 `kbAtoms.ts`，**不许自造**）：
fact / metric / case / qualification / policy / product_capability / play / script

### 3.5 原子审核（`/knowledge/review`）

左：待审核队列（312 条，列表 6 条）/ 中：当前原子详情（原文高亮 + 抽取事实 + 可编辑）/ 右：操作区（采纳/改写后采纳/丢弃/合并到已有）+ 进度「今日已审 18/312」

现有实现：`KbReviewPage.tsx`（21KB）/ `useKbReview.ts` / `kbReview.ts`（20KB）。**复用逻辑，重组布局。**

### 3.6 问知识库（`/knowledge/qa`）

左 1fr：对话区（3 轮问答，答案带 [1][2] 引用编号 + 来源卡片）
右 320：检索过程（召回 5 / 重排取 3）+ 说明

**必须区分两种"没答案"**：
- 「未命中」= 没检索到相关片段 → 建议换词或启用本地全文检索
- 「真无资料」= 检索到了但内容不覆盖 → 建议补充文档

现有：`kbQaSession.ts` / `QaDrawer.tsx`（抽屉版，本批做成独立屏）。

### 3.7 上传文档（`/knowledge/upload`）

## 四、资质台账 3 屏

### 4.1 台账（`/qual-certs`）—— 业务价值最实

| # | 改造 | 原状态 | 目标 |
|---|---|---|---|
| 1 | **五卡同权重 → 按危险度排序着色** | 已过期 1 / 30 天内 3 / 90 天内 0 / 未登记 25 / 总数 34，五张卡长得一样 | 红（已过期）/ 橙（30 天内）/ amber（未登记 25，文案「⚠ 25 张未登记，点击批量补录」）/ 绿（正常+总数合并成 DataBar） |
| 2 | **预警可定位到行** | 预警条点击只跳台账，还要 34 行里找 | 「定位」按钮 → 滚动到该行并高亮闪烁 |
| 3 | **有效期胶囊四档** | 25 个灰色胶囊稀释真警报 | 红（已过期）/ 橙（≤30 天）/ amber（未登记）/ 灰（正常） |
| 4 | **操作收 ⋯ 菜单** | 编辑/删除 16px 图标，热区太小 | `⋯` 菜单（编辑/查看扫描件/续期登记/删除） |
| 5 | **批量操作** | 无 | 底部批量条（批量登记有效期 / 批量导出 / 标记不适用） |

**证书数据**（AUTHORING 第 5 节口径）：总数 34 / 已过期 1 / 30 天内 3 / 未登记 25。

### 4.2 预警处理（`/qual-certs/alerts`）

左 340：预警列表 4 条（选中第一条）
右：详情 —— 证书信息 + **受影响项目 2 个**（各标「该证书是必备资格条件」）+ 三个动作卡（立即续期登记 / 标记本项目不适用 / 已换新证上传扫描件）

顶部 `alert--warning`：「这 4 项中任意一项过期，将导致 2 个在投项目失去投标资格」

### 4.3 批量登记（`/qual-certs/bulk`）

3 步：① 选择证书 → ② 填写有效期 → ③ 预览影响

左：25 张未登记表（可勾选）
右 380：统一填写（发证日期 / 有效期至 / 发证机构）+ 「按证书类型分别填写」开关
底部影响预览：「将更新 25 张，其中 3 张会自动进入 30 天内到期预警」+ 执行（主 CTA + 二次确认）

**关键**：写库前必须算影响，避免「补录完突然多出一堆红色」的意外。

现有：`qualsCore.ts` / `qualCertsTable.ts`。**复用。**
