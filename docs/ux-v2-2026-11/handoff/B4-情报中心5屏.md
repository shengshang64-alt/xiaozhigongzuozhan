## 三、任务 1：审阅屏（`/intel-center`）—— 核心屏

### 3.1 关键改造点

| # | 改造 | 原状态 | 目标 |
|---|---|---|---|
| 1 | **双模式分离** | 待确认/浏览/详情/数据源全在一页（3,600px） | 审阅屏只服务"处理待确认" |
| 2 | **两级筛选合并** | 左侧 6 组竖向筛选 + 中部横向筛选行并存 | 只留顶部一行状态 chip（全部 29 / 可转商机 6 / 采购公告 11） |
| 3 | **操作分层** | 每张卡 5 个操作平铺（AI 摘要/确认/编辑/标重点/原文） | 主 CTA「确认并转商机」实心，其余收 `⋯` |
| 4 | **键盘操作** | 无 | `J`/`K` 切换条目，`Enter` 确认，`X` 忽略 |
| 5 | **进度可见** | 无 | 顶部「今日已确认 12 / 29」+ 进度条 |
| 6 | **蓝色说明书移除** | 一大段介绍数据源与抓取频率 | 移到「数据源」屏 |

### 3.2 布局

左右分栏：左 380px 待确认列表 / 右自适应详情审阅面板。

**详情面板结构**（从上到下）：
1. 标题 + 元信息行（来源 / 发布时间 / 原文链接）
2. 正文（清洗后 3 段）
3. AI 摘要卡 + 关键词标签
4. 关联客户提示（如「厦门市中医院 · 同属中医系统 · 可把这条澄清作为触点」）
5. 「同类情报 3 条」
6. 底部三个动作：「确认并转商机」（主）/「仅确认」/「忽略」

### 3.3 键盘交互

**必须实现**（这是这一屏的核心价值，不是装饰）：

| 键 | 行为 |
|---|---|
| `J` / `↓` | 下一条 |
| `K` / `↑` | 上一条 |
| `Enter` | 确认当前条（并转商机） |
| `X` | 忽略当前条 |
| `Esc` | 退出键盘模式 / 清空选中 |

**注意**：键盘监听必须挂在**焦点在此屏时**，不许全站拦 `J`/`K`（用户在别处输入文字会被吞）。

实现建议：监听挂在列表容器上（`tabIndex={0}`），或判断 `document.activeElement` 不在 input/textarea 内。

### 3.4 「转商机」流程

点「确认并转商机」→ 打开抽屉或弹窗，预填商机卡（客户、商机名、来源=该情报、预算若可解析）→ 用户确认 → 创建商机 + 情报状态改为「已转商机」。

**不许**静默创建（用户必须看到预填内容）。

## 八、共用要求

### 8.1 三态齐全（每屏）

- `LoadingState` 或骨架屏
- `EmptyState`（带 action，如「换个关键词」「去数据源看看」）
- `ErrorState`（带 reason，说人话）

### 8.2 失败态必须区分「没抓到」与「抓到了但坏了」

R69 审计的教训：把「加载失败」显示成「没有数据」，用户会以为真没内容。
`ErrorState` 的 `reason` 必须说清是哪一种。

### 8.3 情报状态语义（8 档徽标）

| 状态 | `Badge` variant |
|---|---|
| 待确认 | `warning` |
| 已确认 | `success` |
| 已转商机 | `default` |
| 已忽略 | `neutral` |
| 可转商机 | `warning`（带 dot） |
| 采购公告 / 政策 / 行业 / 数据 | 用 `.badge-info` / `.badge-primary` 等（B0 已建） |
