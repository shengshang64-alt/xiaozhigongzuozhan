## 4. 给执行者的六条铁律（写进每批任务书，不许删）

1. **只碰任务书里明确列出的文件。** 没列的文件一律不改，哪怕看到明显 bug。看到就写进「顺带发现」，让 Lead 决定。
2. **设计不许自由发挥。** 静态原型里长什么样就实现成什么样；原型没覆盖的交互，停下来问，不许"我觉得这样更好"。
3. **不许删既有功能。** 拆屏是把一个页面的内容分到多个路由，不是删掉一半。任何"感觉没用"的功能，先保留、标 `TODO(ux-v2): 待确认是否砍`。
4. **不许把大文件继续拆成更大的文件。** 目标：每个页面组件 ≤ 400 行，每个 hook ≤ 800 行。超了就是没拆对。
5. **四门必须过。** 任何一门不过，不许说"完成"。数字必须如实贴，不许估算。
6. **不许改这五样东西**（红线，见 AGENTS.md）：
   - `.qoder/settings.json`、`.qoder/hooks/**`
   - 不执行 `git push` / `reset` / `clean` / `rebase`
   - 不删 `pocketbase/pb_data`
   - 不动 `.env` 等凭据文件，密钥不进代码与日志
   - 不删用户既有产物（已生成的标书正文/方案/PPT 数据）

## 5. 验收协议（Lead 用，执行者也要知道会被这样查）

### 5.1 机器验收（一票否决）

```powershell
cd D:\重要文件\工作的小程序\xiaozhigongzuozhan
node docs\ux-v2-2026-11\acceptance\verify-ux-v2.mjs --batch B2
```

脚本会检查：

| 检查项 | 通过标准 |
|---|---|
| 路由注册 | 本批所有屏都在 `routeRegistry.ts` 里注册，且 `label` 与 manifest 逐字一致 |
| 页面文件存在 | 每个屏有独立页面入口文件 |
| 组件行数 | 页面 ≤ 400 行、hook ≤ 800 行 |
| 硬编码色值 | 新增/修改文件里 `#RRGGBB` / `rgb()` 出现次数 = 0（token 除外） |
| 一屏一主 CTA | 每个页面组件里 `variant="default"` 的 Button ≤ 1（弹窗内不计） |
| 禁用按钮带原因 | `disabled` 的 Button 附近 200 字符内必须有解释文案 |
| 原型对齐 | 本批屏的 `data-screen` id 与 manifest 完全一致 |
| 未越界 | 改动文件清单 ⊆ 任务书声明的写域 |

### 5.2 人工验收（四问）

对每一屏问：

1. **打开这一屏，用户只做一件事吗？** 如果一屏里有两套统计卡或两个主按钮 → 打回
2. **主操作在页头右上、一眼能看到吗？** → 找不到 → 打回
3. **数据为空 / 加载慢 / 请求失败，三个状态都有明确出路吗？** 缺任何一个 → 打回
4. **和静态原型对比，信息少了没？** 少了就是偷偷删功能 → 打回

### 5.3 打回时的标准话术（Lead 复制粘贴用）


**最多打回 3 次。** 3 次不过，说明这批的拆法有问题，退回改任务书，不退回改代码。

## 6. 关键上下文（执行者必读，不要跳）

### 6.1 项目是什么

医疗信息化售前工作台。React 19 + TypeScript + Vite + Tailwind + Radix + PocketBase。
核心价值只有一条：**产出可对外交付的标书 / 方案 / PPT。**

### 6.2 三个端口

| 端口 | 服务 | 起法 | 停了会怎样 |
|---|---|---|---|
| 8000 | 前端 Vite dev | `start-local.cmd` | 页面打不开 |
| 7000 | PocketBase | 同上 | 全站数据空、`/api/*` 404；**JSVM hooks 不热加载，改 hook 必须重启** |
| 7001 | Node sidecar | `vibex-local/sidecar/server.mjs` | AI 生图/PPT 渲染报错，其它不受影响 |

⚠️ `npm run dev` 用的是根 `vite.config.ts`，**没有 `/__pb` 代理**，会表现为「界面能开但数据全空」。日常一律走 `start-local.cmd`。

### 6.3 现有可复用的组件 API（不要重造）

```tsx
// 按钮：variant = default(主) / destructive(危险) / outline(次) / secondary / ghost(三级) / link
// size = default(h-10) / sm(h-9) / lg(h-11) / icon
import { Button } from "@/components/ui/button"

// 徽标：variant = success / warning / danger / neutral / default / secondary / destructive / outline
import { Badge } from "@/components/ui/badge"

// 表格：自带排序 + 分页 + FAB 避让
```

### 6.4 路由注册表（唯一真源）

`src/lib/routeRegistry.ts` —— 路径、文案、图标、分组、懒加载器**全部一处定义**。
侧栏 `SidebarNav`、标签栏 `WorkspaceTabs`、面包屑、文档标题都从它取，**不许在别处再加映射**。

当前结构（扁平 17 条）：

```ts
const ROUTE_DEFS: RouteDef[] = [
  def("/customer-management", "客户管理", Users, () => import("@/pages/CustomerManagement/index.tsx")),
  // …
]
export const NAV_GROUPS = [
  { title: "客户 · 线索", paths: ["/", "/customer-management", "/intel-center"] },
  // …
]
```

**拆屏后要变成子路由**（`/customer-management/:id` 这种）。注意 `workspaceTabs.ts` 的假设是「标签粒度 = 路由路径，全是扁平顶层路径」，改成子路由后**标签粒度必须改成"模块级"**，否则打开 5 个客户详情就吃掉 5 个标签位。

### 6.5 设计真源在哪

```
docs/ux-v2-2026-11/
├── prototype/                    ← 69 屏静态界面（HTML，浏览器直接看）
│   ├── index.html                ← 总入口
│   ├── assets/design.css         ← 设计令牌 + 30 类组件（**实现时的样式对照表**）
│   ├── assets/manifest.js        ← 69 屏的 id / file / tab / desc（**验收比对的真源**）
│   └── AUTHORING.md              ← 组件速查
├── 01-诊断与重构方案.md           ← 为什么这么拆
├── 02-设计规范与组件约定.md       ← 令牌/按钮/下拉/筛选/表格/弹窗/空态/文案/验收清单
└── gallery.html                  ← 69 屏截图墙（看整体效果最快）
```

**实现时的用法**：写某个屏之前，先在浏览器打开对应的 `prototype/<模块>/<屏>.html`，照着它排；颜色/间距/字号去 `design.css` 查对应的 class 与 token。
