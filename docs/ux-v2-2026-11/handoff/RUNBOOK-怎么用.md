## 它开始跑偏时用这三句拉回来

```
1. 停下。你现在改的文件不在本批任务书的写域里，先说明为什么动它。
2. 回到 CONTRACT.md 第三节的六条铁律，逐条对照你现在做的事，指出违反了哪条。
3. 不要继续写代码。先用 5 句话复述「这一批要交付什么、验收标准是什么」，等我确认。
```

**跑偏的三个信号**：
- 开始改任务书写域外的文件
- 开始"优化"设计（改间距、换颜色、加原型没有的组件）
- 回报里出现「顺便」「顺手」「优化了」

## 常见卡点速查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `vite build` 报批量删除被拦截 | 缺 `CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD` 前缀 | 用 `$env:CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=100000; npx vite build` |
| `tsc` 报 `import()` 找不到文件 | 提前声明了还没建的屏 | 按 B1 方案 A：只声明模块根屏，逐批补 |
| eslint error 数超基线 | 新增了 `react-hooks/set-state-in-effect` 等 | 用 `useRef` 代替 `useState`+`useEffect`；不许改预算 |
| `onDemandHeavyLibs` 测试红 | `docx`/`xlsx`/`pptxgenjs` 被静态引入 | 必须保持 `await import(...)` 动态引入 |
| 页面打开后数据全空 | 用了 `npm run dev`（无 `/__pb` 代理） | 改用 `start-local.cmd` |
| 改 hook 没生效 | PocketBase JSVM hooks 不热加载 | 重启 7000 端口 |
| 一次改了 2000 行 | 没按批次走 | 停，回滚，拆更小的批次 |
