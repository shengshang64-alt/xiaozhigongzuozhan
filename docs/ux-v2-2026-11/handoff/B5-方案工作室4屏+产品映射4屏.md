### 3.2 方案编辑器（`/solution-studio/editor`）—— 核心屏

三栏：左 300 大纲树 / 中 1fr 正文编辑 / 右 340 检查栏

1. **需求覆盖 18/22**（环形）—— 4 条未覆盖需求可点
2. **事实接地检查** —— 3 处待核（数值 / 厂商名 / 资质）
3. **写作体检** —— AI 味 0.18、枚举密度、术语一致性

**顶部工具条**：方案名 + 自动保存状态 + 撤销/重做/预览/导出 docx（主 CTA）
**底部**：`alert--amber`「第 7 章仍缺 2 段结论，导出会提示」

⚠️ 「预览 / docx 静态不可达」的约束（项目有 `onDemandHeavyLibs.test.ts` 守卫）：
`docx` 库必须保持**动态 import**，不许改静态 import，否则测试会红。

## 四、产品映射 4 屏

### 4.1 关键背景

原页面把向导摊成杂货铺：**两层 Tab 叠加**（功能 Tab：记忆库/公司库/导入 ONE-LINK × 来源 Tab：上传粘贴/从招标文件/从方案需求）+ 结果区只有一行小字「上传清单后此处展示对照结果」。

### 4.2 ① 选择清单（`/product-mapping`）

| # | 改造 |
|---|---|
| 1 | 三张来源卡片并排：上传 Excel（推荐）/ 粘贴文本 / 从招标文件抽取 |
| 2 | 大 textarea，**示例用占位符样式**（灰色斜体 + 「示例：」前缀），不许看起来像真实内容 |
| 3 | 右侧「这些清单从哪来？」帮助卡 + 最近 3 次上传记录 |
| 4 | 主 CTA「开始对照（预计 20 秒）」 |

### 4.3 ② 对照（`/product-mapping/compare`）—— 核心屏

**明确的左右分栏**：
- 左：原文行列表（每行：序号 + 需求原文 + 置信度色条）
- 右：已匹配候选产品卡（产品名 / 型号 / 厂商 / 评分 / 为什么匹配）
- 顶部：进度「已对照 34 / 128 行」+ 进度条 + 暂停/跳过本行
- 右侧底部：「接受 / 换一个 / 标记未匹配」

**未匹配行**必须 `badge-danger`「未匹配 · 需人工」。

### 4.4 ③ 结果（`/product-mapping/result`）

**结果区是主角**（不再是"一行小字"）：

- 顶部 `StatCard` × 5：总行数 128 / 已匹配 121 / 未匹配 7 / A 级 84 / 覆盖得分 91.2
- 结果表：序号 / 需求原文 / 匹配产品 / 厂商 / 评分 / 覆盖评级(A/B/C) / 操作
- 右侧导出卡：导出 Excel / 导出评分覆盖表 / **带入方案大纲**（主 CTA）

### 4.5 产品库（`/product-mapping/library`）

原「记忆库 / 公司库 / 导入 ONE-LINK」三个 Tab 收敛为一个资产页，用 `seg` 切换三视图。
