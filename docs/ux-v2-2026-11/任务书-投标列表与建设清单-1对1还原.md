## 2. 屏 B · 建设清单（`solution/checklist.html` → 方案工作室清单屏）——**本任务主战场**

### 2.1 现状（差距大）

- 路由壳：`src/pages/SolutionStudio/checklist/SolutionChecklistPage.tsx`（已承认「原型三栏 vs 现网列表+详情」）  
- 组合：`ChecklistView` → 无 active 时 `ChecklistListPanel` + `ProductLibraryPanel`；有 active 时 `ChecklistDetailPanel`（宽表）  
- **双重标题**（PageHeader + ChecklistView 内 h2）  
- 无原型三步条、无需求原文栏、无知识库推荐卡、无右侧分项金额卡、无未勾选告警  

### 2.2 目标信息架构（必须 1:1）

```
PageHeader（建设清单 + 阶段徽标 + desc + meta）
  ph-actions: [导入需求原文] [导出清单 Excel]   ← 无「回方案列表/去编辑器」占主区；返回可用次级或面包屑
三步条 .steps：①录入需求(done/on) ②生成系统清单 ③转大纲
主区 split：
  左（宽）：系统清单卡（勾选行+金额） + 一键从知识库推荐卡
  右上：需求原文卡（分段 + 已映射/部分映射徽标）
  右下：金额汇总卡（设备/软件/实施/服务/税 + 合计 + 生成大纲 primary）+ 未勾选 amber 告警
```

「我的建设清单」列表 / 产品库：**不要**再作为该 URL 的主工作面。  
- 进入 `/solution-studio/checklist?solution=…`（或等价深链）时，直接进入**当前方案关联清单的工作面**（三栏）。  
- 多清单切换：可在页头 meta 旁放「切换清单」次级，或保留从方案列表进入时已选定的 checklist；勿默认落在「列表+产品库」双栏。  
- 产品库维护入口可放到「＋ 加系统」旁的次级「从产品库追加」，不要占半屏。

### 2.3 逐块规格

#### B1 · 页头

- 标题：`建设清单` + 阶段徽标（有真阶段用真值；否则用方案阶段或「立项阶段」仅当产品已定义该枚举——**禁止写死假阶段**；无枚举则只保留标题，徽标可省略并在 PR 说明）。  
- desc：与原型一致——「把客户需求原文转成**可报价的系统清单**，再一键转成方案大纲。清单独立于编辑器：它服务立项与报价，不参与正文写作。」  
- meta：`客户 {医院}` · `系统 {n} 项` · `合计 {金额} 万`（金额格式与原型「698.0 万」一类，一位小数）。  
- 动作：  
  - 「导入需求原文」——打开粘贴/上传需求原文流程（可复用新建向导里录入需求的能力，但结果要落到本屏「需求原文」卡，而不是只开向导另起炉灶）。  
  - 「导出清单 Excel」——调用现有 `exportChecklistXlsx`。  
- **删除**与 ChecklistView 重复的第二套 h2「建设清单」大标题。

#### B2 · 三步条（真实状态，禁止写死）

| 步 | 完成判据（建议，可按现有字段微调但需写进 PR） |
|---|---|
| ① 录入需求 | 需求原文非空（段数 ≥1） |
| ② 生成系统清单 | 清单行 ≥1；副文案「进行中 · n 项已确认 m 项」用勾选数 |
| ③ 转大纲 | 已从该清单生成过方案大纲 / 用户点过生成且成功 |

交互：可点击已完成步回看；未解锁步禁用并 toast 原因。  
样式对齐原型 `.steps` / `.step.done` / `.step.on`。

#### B3 · 左卡「系统清单」

- 每行：`checkbox` + 系统名 + 右侧 mono 金额。  
- 勾选控制是否计入合计与是否进入大纲（与原型「未勾选不写进正文」一致）。  
- 头：标题 + `n 项 · 已勾 m 项` + 「＋ 加系统」。  
- 底：分项汇总一行小字「设备 … · 软件 … · 实施 … · 服务 … · 税 …」（与右卡同源计算）。  
- **不要**用现网那种 10 列表格作为主交互；数量/单价编辑可：  
  - 点击行展开行内编辑，或  
  - 右侧/抽屉详情  
  但主视图必须是勾选清单树/列表，观感 1:1。

#### B4 · 左卡「一键从知识库推荐」

- 按钮：「从知识库推荐系统」「参考同类立项清单」。  
- 下方「推荐理由」列表：有检索/推荐 API 或本地规则则显示真实理由；**暂无能力时**：卡片保留，理由区空态「暂无推荐，请先完善需求原文或知识库」，**禁止**写死原型里的三条演示文案。

#### B5 · 中卡「需求原文」

- 按段展示；每段徽标：已映射 / 部分映射 / 未映射（按该段是否关联到清单行）。  
- 无原文时：空态 + 主按钮「导入需求原文」。  
- 映射关系若现网无模型：允许最小增量（段 id ↔ line_id[]）；不要为了躲映射而删掉该卡。

#### B6 · 右卡「金额汇总」

- 行：设备 / 软件 / 实施 / 服务（3 年）/ 税 + 分隔 + 合计大字。  
- 分类规则：用现有 `category` / 产品类型字段映射；映射表写进代码注释；无法归类进「软件」或「未分类」并在 PR 说明。  
- 主按钮：「生成大纲」（唯一 primary）；副文案：「按勾选的 m 项生成大纲，未勾选项不写进正文」。  
- 接现有 `onStartSolution` / `checklistToOutline` 流程。

#### B7 · 未勾选告警

- 存在未勾选系统时显示 amber alert：`{k} 项未勾选（名称…）会在大纲里缺少对应章节…`  
- 全勾则隐藏。
