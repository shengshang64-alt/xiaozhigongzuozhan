# 16 · 交付级作战方案：从「技术全绿」到「真正能交付」

> 制定：WorkBuddy（以主导者身份）· 2026-10-12
> 依据：`AI-ITERATION.md` v3.2 既有体系 + `docs/09/10/13/15` 既有审查 + **本次实测取证**（测试全跑、账本全读、服务直连、素材核对）
> 定位：**不是第二套规则**。既有三层接线（rules / agents / driver）与专项轮 D 全部保留，本文件只做两件事——**修正目标函数**、**解锁闸门**。

## 一、结论先行

系统**不是质量差，是目标函数错了**。

278 轮迭代把「技术自洽」做到了满分——本次实测：`vitest` **185 文件 / 2116 用例全绿**、`tsc -b` 零错、`vite build` 3 秒成功、backlog 86 项中 74 项已 closed。但同一时间：

| 事实 | 来源 | 说明 |
|---|---|---|
| 扫描件（扫描版招标 PDF）**进不来** | docs/10 §4.2 自评「当前最大输入缺口」 | 真实招标文件大量是扫描件 → **交付链第一步就断** |
| 知识库 **423 篇静默不可见**（6000 硬上限）、首屏 40–61 秒 | AI-ITERATION.md §3 / `kbCore.ts` MAX_PAGES=30×200 | 素材是真实的，但**用户看不到** |
| 方案编制页 **无真实数据可回归**（`solutions` 集合为空） | AI-ITERATION.md §3 · E-2 | 模块存在，**但没被真实数据跑过** |
| docs/06 九项新能力 **一项未做** | AI-ITERATION.md §3 | 全是 C 类，卡在闸门 |
| 安全评分 **4.0/10**（身份头自证 / IDOR / 老路由明文 Key） | docs/09 | 本机可控，**联网即高危** |

**一句话诊断**：现有闭环的判据是「代码有没有问题」，而你要的判据是「**这份标书/方案/PPT 能不能直接发给客户**」。两者之间的落差，就是那 423 篇不可见的文档、那份进不来的扫描件、那个从没被真实数据跑过的方案页。

## 二、根因：为什么迭代自己跑不动了

不是 AI 不努力，是**规则把路堵死了**。

`AI-ITERATION.md` §7「四类工作与放行门」规定：

| 类 | 内容 | 放行 |
|---|---|---|
| A 类 · 修 | 确定缺陷 | ✅ 自动执行 |
| B 类 · 优化 | 性能/文案/一致性/UI | ✅ 自动执行 |
| **C 类 · 升级** | **新增产品能力、新数据模型、新依赖** | ❌ **先写方案，等用户确认** |
| D 类 · 记录 | 本轮范围外 | 只记账 |

> 「**剩下的全是 C 类 = 停止自动推进**，把 C 类汇总成建议清单交还用户。」

**于是形成了一个自我封死的循环**：
1. A/B 类在一两轮就修完 → 选题枯竭
2. 能选的全是 C 类 → 需要用户确认 → 停下等人
3. 用户不确认（或不知道怎么确认）→ 记入 backlog → 下一轮还是没得做
4. 最后只能做「P3 defer 的技术债」→ 账面 86 项 74 项 closed → **看起来收敛了，其实交付链没动**

另有两条次生拖累：
- **既有文档漂移**：`docs/09` 断言「零测试网、不具备无人值守条件」——而实测已有 2116 个用例。**文档与代码对不上，会误导每一轮的选题与判断**（docs/09 自己把这条列为「最该先做的第 5 件事」）。
- **双账本断裂**：`.loop/ledger.json`（主账）与 `.nightrun/state.json`（夜跑）互不相通；`.loop/autoloop-state.json` 显示驱动器 `total_rounds_run: 0`、最后运行 2026-09-24 —— **执行层从未真正跑通一轮**，R33–R278 实为 IDE 内手动轮次。

## 三、四大交付链卡点（按「卡住第几步」排序，不按技术严重度）

> **排序原则换掉**：既有体系用 S0–S5（技术严重度）排序。对「能不能交付」而言，正确序是**「卡在交付链的第几步」**——第一步断了的，比第五步难看的，优先级高一个数量级。

### 卡点 1 · 输入侧：扫描件进不来（P0，交付链第一步）
- **现象**：真实招标文件以扫描 PDF 为主，现有 `pdfjs` 抽不到文字层 → 解析链路直接空转
- **证据**：docs/10 §4.2「扫描件是当前最大的输入缺口」；已核实方案 `ocrmypdf/OCRmyPDF`（MPL-2.0 ✓，加文字层后 pdfjs 立即可用）
- **影响**：**不修，后面 90% 能力在真实场景下用不上**

### 卡点 2 · 检索侧：纯词法 BM25，「找不到」（P0，决定内容质量上限）
- **现象**：`kbCore.ts` 仅 IDF + BM25 + 短语邻接；说人话的查询（「智慧病房建设方案」）召不回写法的不同的文档
- **证据**：docs/10 §4.1 已给正确解法（**两阶段**：文档级向量粗排 11ms → BM25 候选集内精排），并实测**否决**了全库块级向量化（268ms / 292MB，本机不可接受）
- **影响**：检索不到 → 生成时引不到素材 → 只能泛泛而谈或编造 → **正是「内容不可交付」的根源**

### 卡点 3 · 生成侧：PPT 模板/母版保真未落地（P1，交付物外观不合格）
- **现象**：`r167-ppt-template-driven-export`（用户上传公司模板）、`r169-ppt-template-master-fidelity`（真正复用母版/版式）均未做
- **影响**：售前交付的 PPT 必须套公司模板，**套不上就等于交付物不合格**
- **同类**：`r149-deck-pagecount-unenforced`（目标 3 页模型给 6 页照单全收）

### 卡点 4 · 验收侧：没有「交付级」端到端验收（P0，元问题）
- **现象**：现有门禁是 `pnpm build / lint / test`（全绿），**但没有一条「从真实文件到可发送交付物」的端到端判据**
- **影响**：所有模块都「测试通过」，却没人回答「这份东西能不能发给客户」

**跨模块附带卡点**：驾驶舱「进行中的项目」恒显空（docs/13 §3.2，有 7 个活跃项目却显示「还没有」）；身份/密钥安全（docs/09 第 1 项，联网演示前必须修）。

## 四、作战路线（四阶段）

### 阶段 0 · 建立交付级验收基线（**零 AI 成本，立即开始**）
为四大模块各定义一条端到端路径，用**真实素材**实机跑通，产出「断点地图」：

| 模块 | 交付路径（端到端） | 硬判定（可机器判定） |
|---|---|---|
| **标书** `/bid-workspace` | 真实招标文件 → 解析（评分办法/★条款/技术要求）→ 逐条响应 → 偏离表 → 废标自查 → 导出 Word | ★条款**零漏答**；逐字引用**零改写**；编造=0；导出物**无占位残留**（`XX医院`/`待补充`/`{{项目名}}`） |
| **方案** `/solution-studio` | 医院需求 → 大纲（覆盖全部建设范围）→ 逐章生成 → 引用有据 → 导出 | 建设范围**全覆盖**（含服务类条目）；每章**可溯源**到素材；无空章 |
| **PPT** `/ppt-quote` | 大纲 → 逐页内容 → 配图 → 按公司模板导出 | 页数=目标页数；母版/版式保真；数字与报价**一致**；无占位残留 |
| **知识库** `/knowledge` | 导入（含扫描件）→ 检索 → 引用 → 问答 | 全库**无静默不可见**；首屏 **< 3 秒**；问答**带来源**且可回取原件 |

> 阶段 0 的产物是**一张断点地图**：每个模块「能跑到第几步、断在哪、证据是什么」。这张图是后续所有轮次的选题来源——**不再依赖 backlog 池**。

### 阶段 1 · 解锁闸门（需你一次性授权，见第六节）
把 docs/06 九项 + docs/10 首批四项 + docs/13 九项 + 本次断点地图，合并重编为**一份「交付链任务队列」**，按卡点顺序排列，**一次性预授权**。此后 Qoder 可连续轮转，不再每轮停下等人。

### 阶段 2 · 不间断迭代（我作为主导者驱动 + 逐轮独立审查）
- **模块轮转**：标书 → 方案 → PPT → 知识库 → 跨模块贯通（忠于既有 mod 9 设计）
- **每轮真跑**：`qoder-loop.mjs` 驱动，我逐轮核对**产出是否真落盘**（不采信 AI 自证：对比 `ledger` + `reports/` + `git diff` + 交付物文件实际存在）
- **门禁升级**：在既有 `build/lint/test` 之上，加**交付级门禁**（上表硬判定）
- **停机条件**：连续 2 轮无产出 / 连续 2 次环境失败 / 未登录 → 停机并告警（沿用驱动器既有设计）

### 阶段 3 · 无人值守（可选，需你确认）
接 WorkBuddy 定时任务（如每晚自动起跑 N 轮），次日早晨汇总：跑了哪些轮、改了什么、交付物在哪、**你怎么自己点几下验证**（符合手册 §11 对非程序员的要求）。

## 五、交付级验收标准（取代软性自评）

新增一道**独立于 AI 自评**的判定，只有三项全过才算「可交付」：

1. **产出物存在且完整**：导出的 .docx/.pptx 真实落盘，可打开，无占位残留、无空章、无截断
2. **内容可追溯**：每条断言都能回取到素材原件（沿用既有 L2 逐字比对：改写/漏答/编造三类硬指标**必须为 0**）
3. **人能验收**：报告必须给出「**你自己动手点几下就能验证**」的路径（手册 §11 既有要求，继续执行）

> 与既有体系的接口：阶段 0 的断点地图写入 `.loop/ledger.json` 的 backlog（带证据与卡点编号）；L2 逐字比对沿用 `scripts/eval-fixtures.mjs` 与 `专项轮D-售前实战模拟.md`，**不另造一套**。
