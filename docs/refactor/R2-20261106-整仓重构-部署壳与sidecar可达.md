## 二、R2 到底修的是什么（一句话）

**不是「功能坏了」，是「坏得很安静」。**

同事在自己电脑上打开 `http://<你的机器IP>:8000` 时，浏览器里的 `127.0.0.1`
指的是**同事自己那台电脑**——那台机器上没有 sidecar。于是：

| 功能 | 同事机上的实际表现 | 用户以为 |
|---|---|---|
| 标书导出 Word（后端路径） | 静默退回浏览器路径 | 导出成功（但大文件受限） |
| 大文件解析（>6 万字 / >20 段） | 静默退回浏览器切段 | 解析成功（但素材丢了） |
| 本机全文搜索（AnyTXT） | 「后端服务未启动（7001）」 | 我 sidecar 没开 |
| AI 插画 / PPT 渲染质检 | 「绘图服务不可达」 | 同上 |

四条**全都指向一个假原因**（用户以为是自己没启动服务），而真原因是
「前端在让同事的浏览器去连他自己」。

## 三、本轮改动

### 3.1 新增：`src/lib/sidecarBase.ts`（地址解析唯一真源）

口径按优先级：

1. **显式配置** `VITE_SIDECAR_BASE` → 只用它（部署方已明确指定，不再猜）
2. **同源 `/__sc` 前缀** → 永远可用（dev / preview / 将来的 Caddy 都适用）
3. **`http://127.0.0.1:7001`** → **只在页面本身就跑在本机时**才追加

第 3 条是这个文件存在的理由：它不再是「默认值」，而是「本机才有的兜底」。
远程页面（`isRemotePage()`）**绝不**把它放进候选列表——这就是根治。

配套三件事：

- **候选梯子**：`/__sc` 若 404（出口没配），自动换下一个候选并记住可用基址，用户无感
- **重试边界**：只有 404/502/503/504 和网络拒绝才换地址；**服务端 500 不重试**
  （生图/导出是花钱接口，请求已落地就不能再打一遍——在测试里钉住了）
- **降级文案**：`describeSidecarUnavailable()` 分三种情况说三种修法（详见 §4）

### 3.2 新增：`vite.proxy.ts`（出口反代唯一真源）

此前 `/__pb` 的定义只写在 `vibex-local/vite.local.config.ts` 里，
根 `vite.config.ts`（`npm run dev` / `vite build` + `preview`）**根本没有代理**——
这就是 AGENTS.md 里那句「`npm run dev` 界面能开但数据全空」的由来，长期靠文档劝人别用。

本轮把 `/__pb` + `/__sc` 两条前缀收进 `vite.proxy.ts`，**两个配置的 `server` 与 `preview` 四处共用**。
如果只给日常那份加 `/__sc`，那么「改走 build 产物」这条部署路径上增强服务又会静默 404——
R2 就等于白做。所以四处必须同源。

`/__sc` 的反代超时给到 **300 秒**：导出大文档、PPT 渲染质检实测可达 1–4 分钟，
反代先超时会让前端看到「后端不可用」而实际后端还在干活——这是最难查的一类假降级。

### 3.3 改造：4 个客户端模块接入单一真源

| 文件 | 原先 | 现在 |
|---|---|---|
| `src/lib/sidecarClient.ts` | `const BASE = "http://127.0.0.1:7001"` | 走 `sidecarFetch` |
| `src/lib/anytxtClient.ts` | 同上（6 处 fetch 各带手写超时） | 走 `sidecarFetch`（超时改为统一参数） |
| `src/pages/PptQuote/aiImageProvider.ts` | 自带一份 `VITE_SIDECAR_BASE ?? 127.0.0.1` | 走 `sidecarFetch` |
| `src/pages/PptQuote/deckRenderClient.ts` | 同上 | 走 `sidecarFetch` |

顺带把 anytxtClient 里两句写死端口的文案（「连不上后端服务（7001），请确认 sidecar 已启动」）
换成 `describeSidecarUnavailable()`——**那句话在同事机上 100% 是误导**。

### 3.4 新增：`scripts/health/verify-exit.mjs` + `npm run verify:exit`

R2 的验收句是「另一台内网机打开增强功能不再默默降级」。这件事**不能靠在本机点一遍**——
本机的 `127.0.0.1` 恰好就是服务器，写死地址的 bug 在本机永远复现不出来（所以它活了一个月）。

正确验法是从**出口地址**出发验两条同源前缀：

```
node scripts/health/verify-exit.mjs http://192.168.1.3:8000
```

输出三项逐条 ✓/✗，不通时给的是「该修哪一层」（前端没起 / PB 没起 / 出口没配该前缀），
而不是一句 `fetch failed`。

见 §4。

## 四、回归网设计（为什么这 16 例）

按「失败形态」组织，不按覆盖率凑：

| 组 | 钉什么 | 例数 |
|---|---|---|
| ① 地址口径 | 回环判定 5 种写全 / 本机有兜底 / **同事机绝不出现 127.0.0.1** / 显式配置只用它 / URL 拼接无双斜杠 | 5 |
| ② 出口口径 | 两条前缀都在且能剥 / 目标端口与默认同源 / **反代超时 ≥ 240s** / **dev 与 preview 四个位置都接了同一份** | 4 |
| ③ 降级文案 | 本机说「未启动」/ 同事机说「出口没配」且**不许让用户去自己电脑找 sidecar** / 配错地址时点名该地址 | 3 |
| ④ 候选梯子 | 404 换候选并记忆 / **500 不重试**（花钱接口）/ 全挂时抛错带真因 | 3 |
| ⑤ 源码哨兵 | 四个模块不许再出现硬编码 `127.0.0.1:7001`（注释里提旧地址是允许的） | 1 |

**反证**：把 `sidecarBaseCandidates()` 里 `if (!isRemotePage()) list.push(...)` 的守卫去掉
（即恢复成「永远把 127.0.0.1 当候选」）→ 用例
「**同事机**（页面来自内网 IP）：只剩同源 /__sc，绝不出现 127.0.0.1」立刻变红。
