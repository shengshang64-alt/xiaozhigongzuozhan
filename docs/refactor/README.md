## 关键结论速览

### 这个产品是什么

面向医疗信息化行业的 **AI 驱动售前与投标全流程协作平台**——把"从一条情报线索到一份能投出去的标书"这条链路收敛成有数据、有护栏、有闭环的系统。12 个业务模块，62 条 AI 提示词，36 个数据集合。

### 重构的总方针

**不是重写，是分层。** 保持业务行为 100% 等价，把"能跑的代码"变成"能维护十年的代码"。

### 五个必须解决的结构性问题

| # | 问题 | 目标 |
|---|---|---|
| 1 | `bidTypes.ts` 370KB / `useBidWorkspace.ts` 301KB 巨型单体 | 抽离 + 分层，体积降 ≥60%，模块可独立测试 |
| 2 | 62 条提示词埋在业务代码里 | 抽到 `prompts/` 目录，纯搬家、逐字符等价 |
| 3 | 36 份重复 CRUD + 并发丢字段 | CRUD 工厂 + 乐观锁 |
| 4 | 零回归测试网（12 模块 8 个无测试） | 三层测试网 + 3 份招标文件 fixture 金标准 |
| 5 | 身份可伪造 / IDOR / 明文密钥 | 按第 1 批清单止血 |

### 五个批次

```
第 1 批 · 安全止血   → 密钥掩码、IDOR、权限门、temperature=0、可中断、按钮可达性
第 2 批 · 口径一致   → 成本确认下沉、totalItems、模式块扩段、缓存事务
第 3 批 · 回归基线   → vitest 骨架、fixture 金标准、契约测试、台账对账
第 4 批 · 模块分层   → 提示词抽离、消除反向依赖、features/ 迁移
第 5 批 · 后端收敛   → CRUD 工厂、乐观锁、schema 版本化、知识库性能
```

**顺序不可调换**：第 3 批的回归基线是第 4、5 批的前提——没有它，任何改动都无法证明"行为等价"。

### 一条最重要的铁律

> **"这个改动会不会让『已经生成的内容』或『已经存下的数据』变得不一致？"**
> 会 → 停下来问用户。不会 → 可以自己做。
