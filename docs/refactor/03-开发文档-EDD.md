## 1. 编码规范

### 1.1 TypeScript

| 规则 | 要求 |
|---|---|
| 严格模式 | 保持 `strict: true`；**不得**用 `any` 绕过（既有 `: any` 逐步收敛，新增零容忍） |
| 未使用检查 | `noUnusedLocals` / `noUnusedParameters` **已开启**——删代码时必须连带清理引用，否则构建失败 |
| 类型导出 | 类型与提示词构造器分文件存放；类型文件不含运行时代码 |
| 联合类型 | 状态类字段用字符串字面量联合（如 `type Stage = 'lead' \| 'contact' \| ...`），禁止裸 `string` |
| 断言 | 禁止 `as any`；`as` 断言必须有紧邻注释说明为何安全 |
| 非空断言 | `!` 仅在同函数内已显式校验时使用，并在上一行注释依据 |
| 枚举 | 用 `const` 对象 + `as const` 或字面量联合，不用 `enum` |

### 1.2 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 组件 | PascalCase | `ComplianceMatrixPanel` |
| Hook | `use` + PascalCase | `useBidWorkspace` |
| 纯函数 | camelCase，动词开头 | `buildTenderParseMessages` |
| 常量 | SCREAMING_SNAKE_CASE | `PIPELINE_STEPS` / `BID_PROMPT_VERSION` |
| 类型 / 接口 | PascalCase，无 `I` 前缀 | `BidProjectRecord` |
| 布尔 | `is` / `has` / `can` / `should` 前缀 | `isTerminalStage` |
| 文件名 | 组件 PascalCase；逻辑与工具 camelCase；提示词 `<动作>.ts` | `bidFiles.ts` / `parse.ts` |
| 事件处理 | `handle` + 对象 + 动作 | `handleStepConfirm` |
| 私有实现 | 不加下划线前缀，靠模块边界（`index.ts`）控制可见性 | — |

**禁止**：`a` / `b` / `temp` / `data2` / `obj` / `item1` / `flag` / `res` / `ret` 这类无信息量命名。

### 1.3 React

| 规则 | 要求 |
|---|---|
| 组件形态 | 仅函数组件 + Hooks；禁止 Class 组件 |
| 副作用 | 所有副作用显式声明依赖；禁止用空依赖数组掩盖依赖缺失 |
| 派生态 | 能推导的值不另存 state；用 `useMemo` 而非 `useEffect` 同步 |
| 渲染性能 | 列表渲染必须稳定 `key`（禁止用数组下标作为可重排列表的 key） |
| 循环内 | 禁止在渲染循环中创建对象 / 数组字面量 / 内联函数（必要时 `useCallback`） |
| 受控组件 | 表单统一受控；失焦与提交均需校验 |
| 错误边界 | 每个路由级页面必须有错误边界，单模块崩溃不得导致整站白屏 |
| 清理 | 所有 `useEffect` 中的订阅 / 定时器 / AbortController 必须清理 |

### 1.4 注释规范

| 要求 | 说明 |
|---|---|
| 密度 | ≥ 每 10 行 1 行功能性注释 |
| 内容 | 解释**为什么**这样写、约束是什么、边界如何处理；不复述代码在做什么 |
| 文件头 | 复杂模块必须有文件头：职责、关键约束、依赖关系 |
| 改动标注 | 「原因 / 影响范围 / 回滚方案」三要素写在改动处或提交信息中 |
| 禁止 | 废弃代码注释、`// TODO` 无负责人无期限、调试残留、被注释掉的旧实现 |

**示例（正确）**：
```ts
// 本地解析分支必须优先于服务端：招标文件含商业机密，上传即违约风险。
// 已知限制：扫描版 PDF 无文字层，此处会得到空文本，需在上层给出明确提示而非静默失败。
if (isScannedPdf(text)) {
  throw new LocalizeError("PDF_NO_TEXT_LAYER")
}
```

### 1.5 错误处理

| 规则 | 要求 |
|---|---|
| 禁止静默失败 | 每个 `catch` 必须有处理动作（提示 / 降级 / 重试 / 上抛），**禁止空 catch** |
| 禁止裸 `catch {}` | 至少记录上下文与部分标识 |
| 分支闭环 | `if` 必须有 `else` 或提前 return；`switch` 必须有 `default` |
| 错误分级 | 用户可感知错误给中文提示；开发者错误带上下文上抛 |
| 降级策略 | 分区降级优先于整页失败；降级时必须界面可见 |
| 错误码 | 统一枚举，禁止魔法字符串 |

### 1.6 常量与配置

| 规则 | 要求 |
|---|---|
| 魔法数字 | 一律抽常量并命名（如 `DUP_THRESHOLD_DEFAULT = 0.35`） |
| 固定字符串 | 枚举化或常量（如 `LOST_REASON_CODES`） |
| 超时 / 阈值 | 集中在模块常量区，附注释说明取值依据 |
| 业务规则 | 配置化优先，不硬编码在分支里 |
| 环境差异 | 走配置，不用 `if (isDev)` 散落判断 |

### 1.7 安全编码

| 规则 | 要求 |
|---|---|
| 外部输入 | 一律清洗与类型校验；`zod` 已可用，优先 schema 校验 |
| 注入防护 | 拼接 SQL / 过滤表达式 / HTML 时必须转义；禁止字符串拼接构造查询 |
| 越权防护 | 写操作前校验归属；高危操作校验角色 |
| 脱敏 | 密钥 / 令牌仅显示后四位；日志禁打隐私 |
| 备份 | 批量操作前 dry-run；文件操作走编辑工具，不用批量删除命令 |

```

```

### 2.2 模块边界规则（强约束）

| 规则 | 说明 |
|---|---|
| **单一出口** | 模块只能通过 `features/<模块>/index.ts` 对外暴露；禁止 `import ... from '../<其他模块>/内部路径'` |
| **禁止反向依赖** | 模块间依赖必须单向。已知违例：`bidTypes.ts` 反向依赖 `SolutionStudio/solutionTypes`，**必须在第 4 批消除** |
| **跨模块共享下沉** | 两个以上模块要用的东西，下沉到 `shared/`，不放在任一模块内 |
| **prompts 独立** | 提示词不得与业务逻辑混放；公共底座放 `prompts/base/` |
| **体积上限** | 单文件 ≤ 300 行（纯数据 / 类型 / 提示词文件除外，但必须单独目录管理并保持单文件主题单一） |

### 2.3 迁移策略

**禁止一次性 `git mv` 全目录。** 正确做法：
1. 先建 `features/<模块>/` 骨架与 `index.ts` 空出口。
2. **一次搬一类**（先搬 `types/`，跑 build；再搬 `prompts/`，跑 build；再搬 `domain/`…）。
3. 每次搬完同步更新引用，**禁止留兼容 re-export 过夜**（会掩盖未完成迁移）。
4. 每批结束跑全部门禁（第 4 节）。

## 3. 测试规范

### 3.1 三层测试网

| 层 | 范围 | 目标覆盖 | 工具 |
|---|---|---|---|
| **L1 单元测试** | `domain/` 与 `shared/lib/` 下所有纯函数 | **分支覆盖 100%** | vitest |
| **L2 契约测试** | 全部自定义 API 路由（请求结构 / 响应字段 / 错误码 / 权限） | 每路由 ≥1 正例 + ≥1 负例 | vitest + 接口直调 |
| **L3 回归 fixture** | 提示词输出（关键字段零漂移） | 3 份历史招标文件金标准 | vitest + 固定输入 |

每个纯函数必须覆盖：

| 类别 | 必测用例 |

| 异常路径 | 非法类型 / 缺失字段 / 超长输入 |
| 并发（如适用） | 同函数并发调用的幂等性 |
| 破坏性 | 恶意输入不得抛未捕获异常，必须有明确返回 |

### 3.3 L3 fixture 回归集（**放开一切自动化重构的前提**）

**构建要求**：
```
tests/fixtures/
├─ tender-a/                 3 份历史招标文件
│  ├─ source.pdf             原始文件
│  ├─ golden.json            ★ 人工确认过的金标准解析结果
│  └─ README.md              该样本的特点与坑
├─ tender-b/
└─ tender-c/
```

**金标准关键字段**（任一漂移即阻断放行）：
- ★▲ 条款清单（条目 + 页码）
- 废标 / 无效标条款清单
- 评分办法（评分项 + 分值 + 合计）
- 关键时间节点（截止 / 开标）
- 预算 / 最高限价

**放行规则**：
```
改动提示词 → 跑 fixture 解析 → diff 金标准
  ├─ 关键字段全一致 → ✅ 放行
  └─ 任一字段漂移   → ❌ 阻断，输出差异报告（漂移字段 / 原值 / 新值 / 疑似原因）
```

### 3.4 测试代码规范

| 规则 | 要求 |
|---|---|
| 命名 | `describe('被测单元')` + `it('应…当…时')`，中文可读 |
| 断言 | 一个 `it` 只断言一个行为；避免多断言混装 |
| 数据 | 测试数据内联或 fixture，禁止依赖线上接口与真实数据 |
| 隔离 | 测试之间无状态耦合；禁止依赖执行顺序 |
| 禁止 | `test.skip` 长期存在、注释掉断言、仅跑 happy path |
| 诚实 | 未覆盖的部分在测试文件头注释中明确声明 |

## 4. 构建与验证规范

### 4.1 命令

```bash
pnpm build      # tsc -b && vite build —— 最强单一校验
pnpm lint       # eslint
pnpm test       # vitest run
```

**退路**（pnpm 预检卡死时）：
```bash
npx tsc -b && npx vite build
```

### 4.2 门禁矩阵（每批必过）

| 门禁 | 判据 | 失败处置 |
|---|---|---|
| G1 类型与构建 | `pnpm build` 零错误 | 立即修复，不得提交 |
| G2 静态检查 | `pnpm lint` 无**新增**错误 | 新增必修；历史遗留单独列出 |
| G3 单元测试 | `pnpm test` 全绿 + 新增逻辑有新测试 | 补测试 |
| G4 实机冒烟 | 涉及界面：真实浏览器走查，控制台 0 error；涉及接口：无 401/5xx、无脏数据、无重复创建 | 修复后重走 |
| G5 AI 输出质量 | 涉及 AI：至少 1 次真实生成，确认未跑偏 / 未幻觉 / 口径一致 | 回滚提示词改动 |
| G6 数据一致性 | 同一指标在各页面取值一致；接口返回与界面显示一致 | 定位单一口径真相源 |
| G7 fixture 回归 | 触及提示词：3 份 fixture 关键字段零漂移 | 阻断放行 |
| G8 可回滚 | 改动独立可回滚；改动前有原始内容快照 | 先补快照再动手 |

### 4.3 实机验证方法

**已封装的辅助脚本**：`_qa/ab.sh`（含自动登录）。

**已知经验（必须遵守）**：
1. agent-browser 会话**不跨 bash 调用保持**——每次调用都要重新 open + 登录；同一调用内 ref 才有效。
2. 必须用 `agent-browser click @ref`；在 `eval` 里写 `.click()` 对 Radix 按钮**不可靠**，会造成"点了没反应"的假阳性。
3. 若浏览器不可用，退而用接口直调（带身份头）+ 代码静态核对，但**必须在报告里注明验证方式降级**。

### 4.4 环境相关硬约束

| 约束 | 说明 |
|---|---|
| PocketBase 路径参数 | `--dir/--hooksDir/--migrationsDir` **相对 exe 目录解析**，必须传绝对路径 |
| PocketBase 改 hook | 改 `pb_hooks/*.pb.js` 后**必须重启**才生效 |
| Vite 子进程 | 必须清空 `NODE_OPTIONS`（否则 safe-delete 守卫中断 dev server） |
| Vite 缓存目录 | 本地配置使用独立 `node_modules/.vite-xzlocal`，避免与根配置混版 |
| React 单例 | 本地配置 `dedupe: ['react','react-dom']`，防双 React 导致白屏 |
| 代理 | `/__pb` → `127.0.0.1:7000`，**必须 rewrite 去前缀** |

## 5. 版本控制与变更管理

### 5.1 分支与提交

| 项 | 规范 |
|---|---|
| 分支 | 每批一个分支：`refactor/batch-N-<主题>` |
| 提交粒度 | 一个逻辑改动一次提交；禁止把不相关改动混提 |
| 提交信息 | `<类型>(<范围>): <做了什么>` + 正文含**原因 / 影响范围 / 回滚方案** |
| 类型 | `fix` / `perf` / `refactor` / `test` / `docs` / `chore`（不含 `feat`——重构期间不新增功能） |
| 红线 | 禁止 `--no-verify` 跳过钩子；禁止强推已共享分支 |

### 5.2 台账机制（解决"done 注水"）

**每轮开工强制对账**，三处状态源全读并合并：

| 来源 | 内容 | 用法 |
|---|---|---|
| `.loop/ledger.json` | 主账本（round / backlog / closed / noProgressStreak） | **主账本**，本轮在此记账 |
| `.loop/MORNING.md` + `.loop/reports/` | 最近轮次结论与未结项 | 未结项并入主账本 |
| `docs/` 下未落地需求（`05` 三模式设计 / `06` 功能缺口 / `09` 重构建议） | 需求侧落差 | 未落地项并入主账本 |

**对账纪律（针对已发生的问题）**：
- 台账标 `done` 的项，**必须能在代码里找到对应改动**。找不到 → 台账回退为 `open`，并记录"注水"事实。
- 台账描述过时的（如"加载上限 6000"实际已升至 12000）→ 先修描述再动手。
- 无人值守模式：报告写入 `.loop/reports/YYYY-MM-DD-HHmm.md`，一句话结论追加到 `.loop/MORNING.md` **顶部**。

### 5.3 ADR（架构决策记录）

任何架构级决策（分层方式、依赖引入评估、范式变更）必须新增 ADR，写入 `02-设计文档-SDD.md` 第 8 节，格式：
```
### ADR-00N · <决策标题>
**决策**：…
**理由**：…
**代价**：…
**重建条件**：…
```

## 6. 重构实施路线图（逐批任务清单）

> **总原则**：先止血 → 再口径 → 再基线 → 再分层 → 最后收敛后端。
> 每批 ≤10 项；每项独立可验证、可回滚；一批做完再开下一批。

---

### 第 1 批 · 安全止血（最高优先级）

**目标**：把"联网即高危"和"资金风险"止住，并修复日常体验断点。

| # | 任务 | 类型 | 验收判据 |
|---|---|---|---|
| 1.1 | 下线或加身份门遗留 `GET /api/model_configs`，`api_key` 一律掩码 | A | 该路由响应体不含完整密钥；未授权访问返回 401/403 |
| 1.2 | 知识库 `kb_docs` / `kb_qa_pairs` 的 PATCH / DELETE 补归属校验 | A | 用他人 uid 请求返回 403 |
| 1.3 | `personal` 可见性文档在服务端 `list` 路由按调用者 uid 过滤 | A | 直接调 API 读不到他人个人文档 |
| 1.4 | 高危路由（项目删除 / 模型配置写 / 知识库删除 / 导出）加 `role === "admin"` 判定 | A | viewer / editor 调用返回 403 |
| 1.5 | 6 处判定类调用点补 `temperature=0`（偏离表 / 废标 / 覆盖审计 / 事实核查 / 查重 / 交卷体检） | A | 同一输入连续两次调用，判定结果一致 |
| 1.6 | 批量生成"停止"接 `AbortController`，取消时 abort 在飞请求 | A | 取消后无后续出站请求；`user_cancelled` 不报错 |
| 1.7 | 解析配置弹窗加 `max-height: 94vh + overflow-y: auto` | A | 883px 视口下"开始解析"按钮可见可点 |
| 1.8 | 新建方案 / 新建客户长表单补 sticky footer | A | 提交按钮始终可见 |

## 7. 风险评估与回滚预案

### 7.1 批次风险矩阵

| 批次 | 主要风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| 1 | 安全改动误伤正常流程 | 中 | 中 | 权限负例测试 + 既有正例回归；每项独立提交 |
| 1 | `temperature=0` 改变输出风格 | 低 | 中 | 判定类任务本就应确定性；跑真实样本确认 |
| 2 | 提示词扩段改变生成内容 | **高** | **高** | 必须 G7 fixture 闸门；先跑 3 份样本比对 |
| 2 | 成本确认下沉导致调用被拦 | 中 | 中 | 确认状态持久化；避免重复弹窗影响效率 |
| 3 | fixture 金标准本身不准确 | 中 | 高 | 金标准必须人工逐字段确认，不得由 AI 直接生成后即用 |
| 4 | 提示词抽离引入字符差异 | **高** | **高** | 逐字符等价迁移 + 每次只搬一个 + G7 闸门 |
| 4 | 拆分巨型 vm 引入回归 | 高 | 高 | 先抽离后拆分；每步跑 G4 主流程冒烟；小步提交 |
| 5 | CRUD 工厂迁移改变接口行为 | 中 | 高 | 一次一集合；迁移前后接口响应 diff 对比 |
| 5 | 乐观锁导致正常写被拒 | 中 | 中 | 冲突返回 409 且前端可重试；不做静默失败 |

### 7.2 通用回滚预案

| 层级 | 手段 |
|---|---|
| 单文件 | `git revert <commit>` 或恢复备份文件 |
| 单任务 | 每项任务独立提交 → 单独 revert，不影响同批 |
| 整批 | 分支回退：`git checkout <批次分支起点>` 或切回主干 |
| 数据 | 改动前对 `pb_data` 做快照；涉及数据的操作先 dry-run |
| 提示词 | 保留旧构造器文本副本，回滚即刻恢复 |

**铁律**：验证不过 → **先回滚，再重新分析**；禁止在失败状态上叠加改动。

### 7.3 停机点（必须停下来问用户）

- 触碰第 4 节任一红线
- 属于 C 类（新增能力 / 新增数据模型 / 新增页面 / 改交互范式）
- 剩余工作全部为 C 类 → 停止自动推进，汇编建议清单交还用户
- 连续 3 轮无可推进项（`noProgressStreak`）
- 发现"改动前后行为不一致"且无法判定哪个是对的
