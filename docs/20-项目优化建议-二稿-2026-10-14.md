### 2.1 P0-1｜门禁诚实性加固（`7e4741f`）

**问题**：autoloop 采信状态文件里的 `verdict=pass`，**不校验四项门禁是否真的都是 pass**；`eslintBaseline` 与实际基线还可能各自漂移。结果就是"本轮文件 pass / 全仓被在途文件挡"这种**假绿**可以一路写进账本。

**改了什么**（`scripts/autoloop.mjs`）：
- 新增 `verifyStateIntegrity(state)`：`verdict=pass` 时，**四门必须齐全、且每项严格 `=== 'pass'`**；`eslintBaseline` 与 `gatesBaseline.eslint` 必须**同源**。命中即判"自我豁免"。
- 新增 `--verify-state`（零费用、不跑门禁，只校验状态自洽）；`doRun` 每轮开头自检，不合法即 `writeStop` 停机；`--check` 并入该检查。
- 新增 `gatesBaseline { tsc: 0, eslint: 151 }`；`ESLINT_BASELINE_FALLBACK` 160 → 151；新增 `TSC_BASELINE = 0`；老状态无新字段时按 `eslintBaseline` 回落。
- `commitArtifacts` 加 `git add .loop`，返回 `leftoverPaths`，`doRun` 把残留写回 `state.leftover`（**门禁不许"顺手把残留藏进未提交区"**）。

**实测取证**：`--verify-state` 在修复前 **exit 1** —— 精准抓出 R40 的"本轮文件 pass / 全仓被在途文件挡"假绿；修状态文件后 exit 0。随后 `--check` exit 0、`--dry-run` exit 0、`--gate-only` → **四门 PASS**。

**为什么值**：这是**"让机器不再骗自己"**。门禁的价值 = 可信度；不可信的门禁比没有门禁更危险（它会给你假的安全感）。

## 3. P1-2 结论｜PocketBase 身份取值的 `require()` 实验：已终结

一稿把"能否用 `require()` 共享跨文件的鉴权工具函数"列为待拍板实验。**本轮已用独立 :7099 探针实测完成，结论明确，无需再做**：

| 假设 | 实测结论 |
|---|---|
| `require()` 在 handler 内可用 | ✅ 可用，且**模块跨请求缓存**（同一模块只加载一次） |
| 能否依赖**文件级** `const/var/function` | ❌ **全部 ReferenceError** —— 每个 handler 在**不同的 VM 隔离**里执行，文件顶层作用域不共享 |
| `globalThis` 跨隔离共享 | ❌ 不生效（同样被 VM 隔离挡住） |
| 唯一可行方案 | ✅ `routerUse((e) => { ...; e.set("rhUserId", uid); return e.next() })` 中间件 + handler 内 `e.get("rhUserId")`（**已验证**） |

**现状规模**：34 个 `.pb.js` / **182 处内联 `x_rh_user_id` 取值**（其中 131 处是同一表达式）。

**处置建议**：单开一轮，把身份判定收敛到"**中间件注入一次 + handler 读取**"这一个实现上，避免 182 处副本各自演进。**关键教训**：不要试图用文件级 `function` 去共享（会被 VM 隔离打回）。

> 这条正好呼应一稿 P1-3（身份字段模型收敛）—— 二者应合并成同一条"**身份从 182 处收敛到 1 处**"的工作线。
