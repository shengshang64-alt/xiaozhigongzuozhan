# 标书工作台 ComposeStep 三点优化方案（用户反馈驱动）

> **反馈来源**: 用户实机截图 + 三条具体意见  
> **涉及文件**: `src/components/bid-workspace/ComposeStep.tsx`（1752 行）、`BidPipelineStepperEnhanced.tsx`、`DeviationPanel.tsx`、`TechParamResponsePanel.tsx`  
> **方案性质**: 布局重构 + 交互重排，**不动业务逻辑**

---

## 问题 1：章节导航太丑 —— 从"灰底列表"到"文档大纲树"

### 现状（截图可见）

```
┌─ 章节导航 共22章 ─────────────┐
│ ○ 开标一览表                  │
│ ○ 投标函                      │
│ ○ 投标人资格声明书            │
│ ○ 授权书                      │
│ ○ 投标分项报价表              │
│ ○ 投标响应表                  │
│ ○ 中小企业声明函              │
│ ...（22 行等高灰行，滚动条）   │
└───────────────────────────────┘
```

**丑在哪**：
1. 22 行等高列表**没有任何信息层级**——商务章（开标一览表/投标函…）和技术章（方案正文）混排，用户找不到"我该写哪"
2. 每行只有 ○/✓ 两种状态，**看不出"写了一半"的章节**（实际上有 11 章是部分成稿）
3. 行高过大（约 40px/行），一屏只显示 8 行，22 章要滚 3 屏
4. 左侧色条（绿/灰）太细，扫视时分不清
5. 和右侧"快速工具"四张彩色卡并排，视觉重心被工具卡抢走——**用户来这里是为了写正文，不是来用工具**

### 优化方向

**A. 分组折叠**：按标书天然结构分三组（从 `bid_chapters` 的 part 字段或标题规则推导）：
```
▼ 商务部分（8 章 · 已完成 8/8）✓ 全绿
   开标一览表 / 投标函 / 资格声明书 / 授权书 ...
▼ 技术部分（11 章 · 已完成 3/11）
   第13章 总体设计方案 ● 编写中
   第14章 功能模块设计 ○
▶ 其他（3 章）
```
- 组头显示「完成度 + 迷你进度条」
- 默认展开"当前正在写的组"，其余组折叠

**B. 行级三态**：✓ 完成（绿）/ ◐ 部分成稿（蓝，带字数如"1.2k字"）/ ○ 未写（灰）

**C. 行高压到 28px**，一屏可见 14 行；hover 显示「写/续写/精修」快捷按钮

**D. 视觉降噪**：快速工具从 4 张彩色大卡**降级为一行图标按钮**（📚引用素材 📊插图 🤖AI助手 💾草稿），把视觉重心还给章节树

**E. 当前编辑章节**整行蓝色高亮 + 左侧 3px 蓝色竖条

### 优化后的结果

用户 3 秒内定位到"我还没写的技术章"；章节树成为页面视觉主角；工具区不再喧宾夺主。

## 问题 2：偏离表太突兀 —— 从"正文下方长条"到"独立页签"

### 现状（源码 1522-1559 行）

偏离表（DeviationPanel）+ 技术参数响应表（TechParamResponsePanel）**两个大面板直接塞在正文编辑器下方**，且上面还有一条蓝色提示"技术偏离表就在下方"。问题：
1. **发现性靠一条突兀的蓝色横幅维持**——这本身就是"位置不对"的自证
2. 技术参数响应表有 400 条数据（截图 2），一展开就把正文顶出视口——**写作上下文被冲散**
3. 偏离表是**交付物**（最后要导出 Word 的），和"写作过程"混在一页，心智不一致

### 优化方向

**方案：第 3 步内部加页签（Tab）**，把"编制"和"响应表"分开：

```
┌──────────────────────────────────────────────────────┐
│ [📝 章节编制]  [📋 偏离与响应表]  [🧩 素材与工具]      │  ← 步骤内 Tab
├──────────────────────────────────────────────────────┤
│  章节树 + 正文编辑器（当前默认）                        │
└──────────────────────────────────────────────────────┘
```

- **「章节编制」Tab**：章节树 + 正文编辑器（用户 90% 时间在这）
- **「偏离与响应表」Tab**：技术偏离表 + 技术参数响应表两个面板（截图 2 的内容整体搬入），Tab 上带角标「待确认 116」（来自响应表的待人工确认数）
- **「素材与工具」Tab**（可选，第三期再做）：素材库/插图/AI 助手

**联动保留**：偏离表里的「定位到章节」点击后自动切回「章节编制」Tab 并滚动到对应章（jumpToResponseNode 已有此能力，只需补 Tab 切换）

**顶部蓝色提示横幅删除**（位置对了就不需要它了）。

### 优化后的结果

写作页回归纯粹（章节树+编辑器）；响应表成为独立工作面，400 条数据随便滚不干扰写作；待确认数在 Tab 上常驻可见。

## 问题 3：商务部分太乱 —— 从"散装章列表"到"按招标要求组卷"

### 现状

商务章（开标一览表/投标函/资格声明书/授权书/分项报价表/响应表/中小企业声明函…）和技术章混在一个长列表里。用户反馈"很多招标文件是有投标文件响应的要求的"——即**招标文件本身就规定了投标文件的组成和格式**（如"第一章 投标函格式""第二章 法定代表人授权书格式"），但当前商务章是系统按通用模板生成的，**没有对齐具体招标文件的格式要求**。

### 优化方向（分两层）

**第一层（布局层，本次必做）：商务/技术分区**

配合问题 1 的分组折叠，商务部分独立成组，且组头增加一个**「组卷检查」入口**：
```
▼ 商务部分（8 章 · 8/8）         [📋 组卷检查]
```
点开「组卷检查」弹窗，按招标文件要求逐项核对：
- ✓ 投标函（已包含，格式符合第五章要求）
- ✓ 法定代表人授权书（已包含）
- ⚠ 分项报价表（已包含，但未按"附件三格式"填报价格构成）
- ✗ 中小企业声明函（招标文件要求提供，当前缺失）→ [一键补入]

**第二层（数据层，可选增强）：招标格式提取**

在解析阶段（`parse_report`）增加一路"投标文件格式要求"提取：
- 从招标文件中识别"第X章 投标文件格式""附件X XXX格式"等章节
- 输出结构化清单：`[{ name: "投标函", formatRef: "第五章", required: true, included: true }, ...]`
- 商务组卷检查直接消费这份清单，而不是硬编码 8 个通用商务章

> 第二层依赖解析能力，工作量较大。**建议本次只做第一层（布局+组卷检查框架，数据先用规则推导），第二层单独立项**。

### 优化后的结果

商务部分从"散装列表"变为"按招标要求组卷的核对清单"；用户在写技术方案前就能确认商务卷是否齐套、格式是否对得上招标要求——**直接降低废标风险**。
