## 给你的拍板要点（请逐条回：同意 / 改成… / 不做）

1. **交付定义**：交付 = **可重复部署 + 主链路可验收 + 可运维可回滚 + 有上手材料 + 遗留问题透明**。不是「功能都在」。
2. **交付对象设默认值（可改）**：主用户 1 人（管理员）+ 同事 ≤10 人；同时在线 ≤5；Windows 主机 + 局域网；单团队单库；**不承诺**公网、跨团队隔离、离线编制、手机编制主战场。
3. **功能分三级**：Level A 核心交付（7 个路由必须「可演示、可交给同事、断点已知」）/ Level B 可用即可 / Level C 保留入口。**三级清单见 §3，这是「V1.0 有什么」的唯一口径。**
4. **质量门可测量**：主链路成功率 ≥95%、无声失败 0 容忍、首屏 ≤3s、AI 首响应 ≤10s、密钥 100% 服务端、备份恢复演练 ≥1 次通过（§4）。
5. **缺陷分级发布门**：P0=0 才可交付；P1=0 或全部有文档化绕过；P2 ≤10 且登记（§5）。
6. **分期交付**：交付 1（阶段 1 后）内部可用 → 交付 2（阶段 2 后）团队可用 → 交付 3（阶段 3 后）完整版；每期有独立 DoD 子集（§7）。
7. **验收方式**：按验收脚本逐条走 + 3 个真实场景演练 + 证据截图 + 上盛与 1 名同事双人签字（§6）。
8. **本文件与 Z0 同级**：D5 的「设计冻结」口令同样覆盖本文件；冻结后若改交付标准，视为改章程。

## 1. 一句话

**交付 = 明天换一台干净的 Windows 机器，按手册装得起来、跑得通、同事用得明白、坏了能回滚、遗留问题写得清楚。**

## 2. 交付对象与使用场景（验收边界）

| 项 | 默认假设（可改） | 不承诺 |
|---|---|---|
| 用户 | 管理员 1 人 + 同事 ≤10 人 | 跨团队、外部访客 |
| 并发 | 同时在线 ≤5，编制高峰 3–5 人 | 公网级并发 |
| 网络 | 局域网（同网段可访问） | 公网暴露、跨城市办公 |
| 环境 | Windows 主机；PB + 前端 + sidecar 同机或同网段 | Linux 服务器交付（可跑但不在验收范围） |
| 数据 | 单团队单库；真实标书脱敏后入库 | 多租户数据隔离、账号级权限（D0：以后） |
| 终端 | 桌面浏览器为主；手机「能看能点」 | 手机编制、独立 App、离线编制 |

**含义**：凡是超出上表的场景，一律回答「不在本轮交付范围」，不临时扩面。

## 3. 功能交付标准（17 路由分级 · V1.0 唯一口径）

### Level A · 核心交付（必须达到「可演示、可交给同事、断点已知」）

| 路由 | 交付判定（四条全过） |
|---|---|
| `/bid-workspace` 标书工作台 | ① 七步主流程可走通并导出；② 大纲/正文刷新不丢；③ 超时与失败有可见提示且可重试；④ 后 4 步有默认入口 |
| `/solution-studio` 方案工作室 | ① 大纲生成成功/失败均有明确状态；② 正文可生成并保存；③ 刷新不丢 |
| `/knowledge` 知识库 | ① 已入库要点问得到；② 引用可见；③ Markdown 表可渲染；④ 未命中与真无资料可区分 |
| `/assistant` 小智助手 | ① 长回答有进行中态；② 超时/503 说人话；③ 不推荐未配置的模型 |
| `/customer-management` 客户管理 | ① 建档/编辑/查询可用；② 列表加载 ≤5s；③ 与标书/方案可互链 |
| `/intel-center` 情报中心 | ① 周报可生成；② 源失败可见原因；③ 关页不丢已完成数据（全自动抓取属阶段 3） |
| `/model-config` 模型配置 | ① 默认通道指向 Open Design；② 「平台内置」本地不可用有明确标签；③ 配置保存生效 |

### Level B · 可用即可（能开、主操作通、空态不白屏、错误不静默）

`/` 工作台 · `/ppt-quote` PPT 与报价 · `/materials` 素材库 · `/bid-check` 标书检查 · `/format-tool` 格式刷新 · `/qual-certs` 资质台账 · `/competitors` 竞品分析 · `/product-mapping` 产品映射

判定：打开正常、主按钮有响应、失败有提示、不出现白屏与死循环；允许功能浅，不允许骗人（假成功、假数字）。

### Level C · 保留入口（不投入，不消失）

`/ai-hot` AI 动态 · `/team` 团队管理（admin 入口）

判定：入口在、能开、空态有说明；不因「交付」而补功能。

### 明确不交付（延续 D0）

账号隔离落地、独立移动 App、整站 UI 重画、甲方招标编制、企微深度自动化、全自动投标、站内 IM、多租户 SaaS、公网部署。

## 4. 质量门（可测量，不靠感觉）

| 维度 | 指标 | 验收方式 |
|---|---|---|
| **可靠性** | 主链路（解析→大纲→正文→导出）抽测 100 次或一周真实使用，成功率 ≥95% | 抽测记录 / 使用日志 |
| **无声失败** | **0 容忍**：任何 AI/解析/导出失败必须可见、可重试、可解释 | 逐页点验失败态 |
| **性能** | 首屏 ≤3s（局域网）；AI 任务首响应 ≤10s（不要求完成）；1 万字解析 ≤5 分钟或显示进度 | 计时记录 |
| **数据安全** | 密钥 100% 在服务端；真实标书/客户敏感数据不入库不入聊天；脱敏检查表过一遍 | 配置审查 + 抽查 |
| **备份恢复** | 每日自动备份；**至少 1 次恢复演练**在隔离端口跑通 | 演练记录（含耗时） |
| **可观测** | 失败有日志（路由+错误码+时间+操作），能回答「同事说又失败了」 | 抽样查日志 |
| **可维护** | 每包回归测试绿；tsc/eslint 门禁绿；单文件 >5000 行登记在案 | CI/门禁输出 |
| **上手成本** | 新同事按 1 页手册 30 分钟内能独立完成「建项目→生成大纲→导出」 | 1 名同事实测计时 |

**任一项不达标 → 不算交付完成**；缺证据（截图/记录/计时）按未达标处理。

---

## 5. 缺陷分级与发布门

| 级别 | 定义 | 例子 | 交付门 |
|---|---|---|---|
| **P0 阻断** | 数据丢失、无法启动、导出损坏、密钥泄露 | 刷新丢大纲（历史）；导出乱码；pb_data 损坏 | **必须 0** |
| **P1 严重** | 主链路失败且无绕过；同事完全用不了 | 增强层全不可达；问答永远不命中 | **0，或 100% 有文档化绕过** |
| **P2 一般** | 体验缺陷、慢、文案差 | 加载慢、空态丑、提示含糊 | **≤10 且全部登记** |
| **P3 建议** | 锦上添花 | 动效、配色微调 | 不设上限，登记即可 |

**发布门 = P0=0 且 P1 达标 且 P2≤10 且 §4 全部达标 且 验收脚本全绿。**

## 6. 验收流程（谁、怎么验、留什么证据）

1. **验收人**：上盛（主验收）+ 1 名同事（同事视角，验「别人能不能用」）。
2. **验收方式**：
   - 按**验收脚本**（§8）逐条执行，结果填表；
   - **3 个真实场景演练**：① 新建标书全流程（解析→大纲→正文→导出）；② 知识库问答命中并引用；③ 同事机打开页面并使用增强功能；
   - 每个场景留**截图或录屏**作为证据。
3. **验收记录**：一页表（场景 / 步骤 / 预期 / 实际 / 证据 / 结论）。
4. **不通过处理**：缺陷回填 → 修复 → 只复验失败项 → 更新记录；不重跑全量。
5. **签字**：上盛 + 同事双签；日期入档。

## 7. 分期交付（每期独立 DoD 子集）

| 期 | 时点 | 交付给谁 | 必过子集 |
|---|---|---|---|
| **交付 1 · 内部可用** | 阶段 1 后 | 上盛自己 | Level A 中 `/bid-workspace` `/solution-studio` `/knowledge` `/assistant` `/model-config`；§4 可靠性/无声失败/性能；1 页手册；备份可恢复 |
| **交付 2 · 团队可用** | 阶段 2 后 | 同事 ≤10 人 | 追加：统一出口可用、sidecar 可达、Level A 全部、Level B 全部；恢复演练通过；同事实测上手 ≤30 分钟 |
| **交付 3 · 完整版** | 阶段 3 后 | 全员 | 追加：情报服务端化（关页可跑、源失败可重试）、助手借一招试点；缺陷门槛全达标 |

**规则**：上一期未过 DoD，不进入下一期的交付动作；阶段可以并行开发，但「交付」必须逐期过门。

---

## 8. 交付物清单（缺一不算交付）

1. **代码**：冻结分支 + 变更说明（脱敏，不含真实标书/密钥）。
2. **部署包**：一键启动脚本（PB + 前端 + sidecar + 统一出口）+ 配置模板（含占位符说明）。
3. **运行手册（1–2 页）**：启动 / 停止 / 备份 / 恢复 / 升级 / 回滚 / 常见故障 3 条。
4. **上手手册（1 页）**：给同事的「打开→建项目→七步→导出」图文。
5. **验收脚本**：可执行步骤 + 预期结果 + 证据要求（本文件 §6 落地版）。
6. **遗留问题清单**：已知半残 + 影响 + 绕过方式 + 计划窗口（诚实清单，不藏）。
7. **数据边界说明**：什么能入库、什么必须脱敏、什么不能进聊天。
8. **备份与恢复记录**：备份策略 + 最近一次恢复演练结果。

## 9. 明确不做（本文件）

1. 不因「交付」把 D0 非目标重新拉进来。
2. 不做公网部署、多租户、账号隔离落地。
3. 不追求「零缺陷」——追求「P0=0、P1 可控、遗留透明」。
4. 不用「功能清单」代替「验收证据」。
5. 不在设计冻结前改业务代码兑现本文件。

## 11. 风险（提前认）

1. **标准过严导致拖延**：用分期 + 分级对冲；P2 允许 ≤10 个带病交付。
2. **标准形同虚设**：缺截图/计时/签字按未达标处理；验收表不填完不签字。
3. **「同事视角」被跳过**：交付 2 必须有 1 名真实同事参与，不允许管理员自验。
4. **遗留清单变成免责声明**：每条遗留必须写「影响 + 绕过 + 计划」，否则视为未登记。
