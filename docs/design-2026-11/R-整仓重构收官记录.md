### R1 · 标书内核拆分（换底盘不换发动机的第一刀）

拆的是 God Hook 里「零 React / 零 AI / 零 hook 状态」的两层：

- `bidRecord.ts`（记录层）：库列归一化 + 大纲草稿留档 + 商机排序
- `bidBodyText.ts`（正文取数层）：正文双模式 / 审计节摘录 / 条款归章

**搬走的 6 个主函数做了函数体字符串比对，逐字相等**（差值仅 `export ` 前缀）。
导出 API 经 re-export 全保留，页面与既有测试 import 零改动。

**刻意没拆的**：领域动作层（`llmGenerate` / `parseSectionVia*`）。它依赖 11 个模块级可变变量、
由 hook 内 `useEffect` 异步同步；拆它必须先设计依赖注入与生命周期归属——那是另一片的事。

### R2 · 部署壳 + sidecar 可达

修的不是「功能坏了」，是「**坏得很安静**」：同事在自己电脑打开 `http://<服务端IP>:8000` 时，
浏览器里的 `127.0.0.1` 指的是**同事自己那台机器**，于是导出 / 大文件解析 / 本机搜索 / AI 生图 /
渲染质检五条增强功能全部静默降级，界面只显示「已完成」。

- 新增 `src/lib/sidecarBase.ts`：取址口径收成一处。**远程页面绝不把 `127.0.0.1` 当候选**（根治点）
- 新增 `vite.proxy.ts`：`/__pb` + `/__sc` 两条前缀，**dev 与 preview 四处共用**
- 新增 `npm run verify:exit`：从出口地址验两条前缀，同事机不必先点一遍才知道通不通
- 顺带修掉 D3 的一个老坑：根 `vite.config.ts` **此前根本没有 `/__pb` 代理**——
  这正是 `AGENTS.md` 那句「`npm run dev` 界面能开但数据全空」的由来

### R3 · 半残主链路收口（五项「界面在说假话」）

| 项 | 原来怎么骗人 | 现在 |
|---|---|---|
| 模型配置 | 「平台内置，登录后即可使用」+ 可设为默认；本机拿不到登录态必然失败 | 红字说清真因、逐行「本地不可用」徽标、**禁用设为默认** |
| 方案自动保存 | 失败时 state 回 `idle` → 从「保存中」直接消失，**看起来像存好了** | 新增 `failed` 档，常驻「保存失败·未落库」+ 服务端真因 |
| 助手长答 | 三个超时数字散着、无关联；文案易误报 | 口径集中（网关 300s / 客户端 330s / 最多 3 次调用），30/60/120s 三档，**长答文案禁止说「服务不可用」** |
| 知识问答 | 「有要点说找不到」只有推断、无实测 | 真实库 7004 篇实测 **8/8 命中**，每条带可追溯出处 |
| 情报抓取 | 只在页面打开时跑，文案却写「后台定时抓取」 | 如实说「本页打开期间抓取、关页停止」+ 计划任务试点脚本 |

### R4 · 横切与边界清理（本片）

1. **再拆一轮巨型 hook**（行为守恒，搬前逐字校验、搬后补测）：
   - `useKnowledge` 目录树构建（45 行 `useMemo`）→ `kbFolderTree.ts`（+13 例）
   - `useKnowledge` 问答会话持久化（反序列化 + 落盘 + 清空）→ `kbQaSession.ts`（+11 例）
   - hook 里只留 `useEffect` 时序，**依赖数组不变、重算时机不变**
2. **幽灵模型推荐清零**（D3 §3.2「禁止推荐用户未配置的模型」的另一面）：
   - 默认模型横幅：没有可用模型时不再硬编码「平台内置 gpt-5.5」，如实说「未配置可用模型」
   - 删除默认配置的确认框：本机域不再承诺「自动回退平台内置」（那是死路），改说真因 + 可执行动作
   - 测试面板：不再说「平台内置与个人模型都支持测试」（本机测它必然失败，不是配置问题）
   - 代码注释里「平台 gpt-5.5 兜底」这类会误导后来者的陈述同步更正
3. **新增横切断言网**（7 例）：把上面三条钉死，含源码哨兵（注释里提旧写法允许，代码里不许回退）
