## 3. 阶段 1 · 止血（对应原包 1–3，名称可仍叫包 1–3）

对齐 D1「必须补」中的编制稳定与知识进正文，以及冒烟严重项。

| 包 | 内容（摘要） | 验收一句 | 粗人天 |
|---|---|---|---|
| 包 1 AI 可靠性 | 网关超时/503 文案；禁止推荐未配置模型；方案大纲失败可见；助手长答策略（超时体感） | 再跑短冒烟：失败说人话 | 1–2 |
| 包 2 标书稳定 | 大纲草稿落库或等价持久；刷新不丢；明显数字不一致先修致命几处 | 大纲生成后刷新还在 | 1–2 |
| 包 3 知识问答 | 已入库要点问得到；引用可见；问答 Markdown 表可渲染 | 用一篇演示 md 问答命中 | 1–1.5 |

**不做进阶段 1**：换栈、拆 `useBidWorkspace` 万行大重构、情报服务化、账号隔离、整站 UI。

## 4. 阶段 2 · 部署壳

| 项 | 内容 | 验收 |
|---|---|---|
| 统一出口 | Caddy/Nginx 或 start 脚本等价：前端+PB+sidecar 同源可达 | 同事机浏览器增强功能不再默默降级（或明确提示降级原因） |
| sidecar 基址 | 去掉「写死对方 127.0.0.1」陷阱 | 配置或相对路径经出口 |
| 可选 | `vite build` + 静态托管替代纯 dev 当生产 | 内网打开 build 产物主流程通 |

**风险**：改启动方式需短时停工作站/Harness（你已可重启）；先备份 `pb_data` 与 Harness 配置。
