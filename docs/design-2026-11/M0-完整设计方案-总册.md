## 1. 背景与根因（为什么不是「再堆功能」）

### 1.1 现状一句话

售前在浏览器打开本机/局域网 `:8000`，页面经 Vite 代理打到 `:7000` PocketBase；大文档/生图打 `:7001` sidecar；AI 经 PB 模型网关转发 Open Design；Harness 外置经 MCP 碰工作站数据。17 个路由、三组导航，业务内核（方案/标书七步/PPT/报价/客户/情报）已深。

### 1.2 半残事实（冒烟 + 审计 + 2026-11-05 实测）

| 事实 | 证据 | 状态 |
|---|---|---|
| AI 长请求撞 120s 网关超时，失败常显示为「模型挂了」 | 冒烟、`latencyBudget.test.ts`（SAFE_LATENCY_MS < 120s） | 待修 |
| 大纲草稿刷新即丢 | **已修复**（2026-11-04，localStorage + `decideOutlineDraft` + 行为回归测试） | ✅ 已修 |
| 素材注入曾「17 个有正文项目开启数 0」 | docs/23 旧审计；**现 `material_boost` 默认已为 true**（`bidTypes.ts:3998`） | ⚠️ 部分过期 |
| 知识问答「有要点说找不到」、Markdown 表不渲染 | 冒烟、docs/23 | 待修 |
| 侧车地址写死 127.0.0.1，同事浏览器打自己电脑 | code_analysis | 待修（阶段 2） |
| 情报关页即停；29 源约 21 失败 | 冒烟 | 待修（阶段 3） |
| 数据身份共用 `local-user`，可见性仅前端过滤 | code_analysis | 本轮不做（D0） |
| `useBidWorkspace.ts` 万行（实测 10,509 行 / 553 KB） | 实测 | 长期债，本轮不拆 |

### 1.3 根因（三条）

1. **需求漂移**：原设计按「单机自用」，实际已是「约 10 人团队 + 局域网/移动体感」；
2. **平台层欠账**：身份、部署出口、失败可感知规范写了但没按优先级落地；
3. **工程方式**：巨型模块 + 多 AI 并行改仓，缺少冻结的「先能用」顺序。

**结论**：换栈/重写解决不了上面三条；**顺序 + 门禁 + 交付标准**才能。

## 3. 总体架构（D3）

### 3.1 目标形态

```
浏览器 ──→ 统一出口（Caddy，同源） ──→ 前端(静态/build) / PocketBase(:7000) / sidecar(:7001)
                                    PB ──→ Open Design（Key 在 pb_hooks）
Harness（外置） ── MCP ──→ PB 约定集合 + 通知表
```

- **一个入口**：同事只认出口地址；PB/sidecar 不直接暴露。
- **一个内核**：业务后端仍是 PB，不另起第二套。
- **一条 AI 通道**：只走 Open Design；「平台内置 gpt-5.5」标为本地不可用，不当默认成功路径。
- **一条助手轨**：Harness 永远外置，经 xz-mcp 读写约定集合；不内嵌。**冻结修订**：阶段 1 起 Harness **同时**作为本机仓**唯一业务改码通道**（按 S1 开工包）；「不内嵌」不变。

### 3.2 边界表（修订版）

| 容器 | 现状 | 目标 | 本阶段 |
|---|---|---|---|
| 前端 | Vite dev `:8000` | build 静态 + 出口 | 阶段 1 止血，阶段 2 托管 |
| PocketBase | `:7000` 本机 | 经出口 | 引擎保留；身份占位「以后」 |
| sidecar | `:7001` 写死 127.0.0.1 | 基址可配置 / 经出口 | 阶段 2 |
| 统一出口 | **缺失** | Caddy 单二进制（Windows 优先） | 阶段 2 |
| 身份 | `local-user` 共用 | PB 原生 auth + 行级归属 | **以后** |
| Harness | 本机外置 | 保持外置 + MCP | 不动 |

### 3.3 三条实现边界（本次新增，防实现时拍脑袋）

1. **统一出口怎么落**：Windows 环境用 **Caddy 单二进制**（启动脚本托管），不用 Nginx；验收必须包含「PB 实时订阅（SSE）与 `/__pb` 前缀经反代正常」——否则多标签/实时刷新会悄悄坏。
2. **情报服务化落库路径**：**PB hooks 定时触发 → sidecar（crawlee）抓取 → 经受限 token 调 PB API 写回**。同时把 sidecar 边界从「不碰库」修订为「**不直连库，可经受限 API 写约定集合**」。
3. **向量落点（知识库两阶段检索）**：**文档级向量存 SQLite（sqlite-vec 扩展，随 PB data 目录备份）**；embedding 统一走 Open Design 网关（Key 在服务端），生成时机=入库时异步补齐；**不做全库块向量化**（docs/10 已实测否决）。

## 4. 产品方案（D4/D6）

### 4.1 17 路由分级（V1.0 唯一口径，D7 §3）

- **Level A 核心交付（7）**：标书工作台、方案工作室、知识库、小智助手、客户管理、情报中心、模型配置
- **Level B 可用即可（8）**：工作台、PPT/报价、素材库、标书检查、格式刷新、资质台账、竞品分析、产品映射
- **Level C 入口保留（2）**：AI 动态、团队管理（admin）

### 4.2 三条主链路断点（本轮聚焦）

| 链路 | 断点 | 本轮动作 |
|---|---|---|
| 项目获取 → 投标交付 | 解析超时、后 4 步无人走、导出小错 | 包 1/2：失败感知 + 后 4 步默认入口 |
| 知识沉淀 → 复用 | 问不到、注入曾为 0、表不渲染 | 包 3：检索验证 + 注入默认 + 渲染 |
| 情报 → 商机 | 前端驻留、失败源无闭环 | 阶段 3：服务端跑 + 逐源历史 |

### 4.3 UI 原则（D6）

不改壳：维持三组导航与 Workbench 多标签；只修**文案/空态/错误/长任务反馈**；长任务必须可见进度或可取消；费用确认保留；数字同屏一致。

## 5. 技术选型（D2，锁定）

| 层 | 结论 | 一句话理由 |
|---|---|---|
| 前端 | React 19 + TS + Vite | 业务与测试已绑此栈，换 UI 框架=重写标书/方案/PPT |
| 数据/API | PocketBase + pb_hooks | 单团队本地/局域网匹配；集合与钩子已承载领域数据 |
| 增强层 | Node sidecar（可降级） | 与前端同语言族；重 OCR/版面按需加 Python 工具进程 |
| 形态 | Web 为主，可后加轻 PWA | 半残不来自缺桌面壳；PWA 成本低但**依赖 HTTPS（阶段 2 之后）** |
| 模型 | Open Design 主通道 | 密钥服务端；用户可自配 OpenAI 兼容通道 |

**否决**：Python/Go 主后端 · Dify/FastGPT/RAGFlow/LightRAG/KAG · NocoDB/Teable 替台账 · Electron 主壳 · 内嵌 Harness · AGPL 本体集成。
