## 2. 五个对标面

### ① 标书编制稳定性 / 速度

- **我们现状（半残）**：业务深度强（七步齐全），但冒烟显示：长请求撞 120s 网关超时、解析千字级仍要数分钟、大纲未确认前只在内存（刷新即丢）、方案大纲失败可无提示；docs/23 显示用户大量停在正文后、后 4 步几乎不走。
- **业界常见做法**：易标/OpenBidKit 等对标「解析项清单 + 合规检查清单」（docs/10 引 BidMaster-Pro 21 项、OpenBidKit 解析项）；产品型 AI 工作台强调可感知失败、草稿持久化、长任务可续跑（docs/12 对 Dify trace / AutoGPT 运行卡为形态参考，非引本体）。旧文未单独测商业标书 SaaS 的超时策略 → **旧文未覆盖，本轮结论：忽略细比，盯自身超时与草稿**。
- **结论：必须补（进里程碑，非本周写码）**  
  止血优先：超时文案与失败可感知、大纲草稿落库、交卷清单把后 4 步默认串起（对齐 docs/23 P0）。不借「再堆提示词/再堆生成能力」。

### ② 知识复用能否写进正文

- **我们现状（半残/缺口）**：知识库能入库、能问答雏形，但 docs/23：**17 个有正文的项目里 `material_boost` 开启数曾为 0**——素材几乎没进过正文；冒烟仍见「文档里有要点，问答说找不到」、Markdown 表未渲染。检索仍偏词法，语义盲区在（docs/10）。
- **业界常见做法**：两阶段混合检索（文档级向量粗排 + BM25 精排，docs/10 实测否决全库块向量化）；Dify 的知识库 Annotation（人工修正问答优先命中，docs/12）；kotaemon / Langchain-Chatchat 作交互参考但不引系统（docs/10）。
- **结论：必须补（进里程碑，非本周写码）**  
  借一招形态：默认开启素材注入 + 问答命中可引用；工程上走 docs/10 的两阶段检索，**不整站上 RAGFlow/LightRAG/KAG**。

### ③ 多人 / 权限

- **我们现状（缺口）**：团队角色有壳，数据身份共用 `local-user`，个人可见性仅前端过滤（code_analysis）；约 10 人同库同记忆。D0 已拍板：**账号隔离以后再说**。
- **业界常见做法**：PB/自建系统用原生 auth + 行级归属；完整多租户平台（NocoDB/Teable/Twenty）docs/10 已否——双系统双权限。旧文未做「商业售前协同 SaaS」细拆 → **旧文未覆盖细功能表，本轮不展开**。
- **结论：继续忽略（本轮）**  
  写入架构「以后」即可；本轮设计与紧随开发窗口不落地账号隔离（与 D0 一致）。演示清场/测试标记仍可按路线图近期项考虑，不等于账号隔离。

### ④ 情报是否服务端跑

- **我们现状（半残）**：情报中心能开、能出周报，但抓取依赖前端页面驻留，关页即停；冒烟 29 源约 21 失败、摘要混导航碎片（路线图三.1、冒烟）。
- **业界常见做法**：docs/10 推荐 Node 同栈 `crawlee` + 计划任务；docs/12 借 n8n 的「逐源运行历史 / 失败原因 / 重试退避 / 手动触发」**产品形态**，不引 n8n 本体；合规边界：只公开页、不绕反爬（路线图明确不做）。
- **结论：必须补（进里程碑，非本周写码）**  
  服务端/计划任务跑 + 运维 UI 形态；引擎不换成 firecrawl 本体（AGPL 警示，docs/10/12）。

### ⑤ 助手能否改页面

- **我们现状（缺口）**：桌宠/整页助手能聊、能只读拉站内数据；**不能改页面状态**（无页面动作注册/工具调用）；Harness + xz-mcp 已外置接入，可读写工作站约定集合，但是另一条助手轨（code_analysis、D0）。
- **业界常见做法**：Open WebUI 并排出稿与反馈；PowerToys 式命令面板升级动作入口；anthropics/skills / prompts.chat 提示词资产化（docs/12）。完整 Agent 平台（AutoGPT/Dify/Open WebUI 本体）明确不引。旧文对「对话直接改标书大纲树」无成熟开源对标结论 → **旧文未覆盖完整竞品实现，本轮借形态不借系统**。
- **结论：借一招**  
  优先：命令面板动作化 + 助手/技能「采用」写回扩展；页面级工具调用进里程碑后段。Harness 保持外置，不把 Harness 嵌进工作站。

## 3. 总表

| 对标面 | 我们一句话 | 主要参照（旧文已核实） | 结论 |
|---|---|---|---|
| ① 标书稳定性/速度 | 深但超时/丢草稿/后 4 步荒 | BidMaster 清单形态；失败可感知（非某 SaaS 实测） | **必须补** |
| ② 知识进正文 | 库在、注入曾接近 0；问答不稳 | docs/10 两阶段检索；Dify Annotation 形态 | **必须补** |
| ③ 多人/权限 | 角色有、数据未隔离 | PB auth；否 NocoDB 等 | **继续忽略**（D0） |
| ④ 情报服务端 | 关页即停、失败源多 | crawlee；n8n 运行历史 UI | **必须补** |
| ⑤ 助手改页面 | 只读联动；Harness 外置 | 命令面板/技能采用；不引 Agent 平台 | **借一招** |

**明确声明**：上表是能力对标决策，**不是**把竞品功能整表搬进路线图。医疗开源产品线矩阵（docs/14）继续服务方案话术，不进本表「必须补」。
