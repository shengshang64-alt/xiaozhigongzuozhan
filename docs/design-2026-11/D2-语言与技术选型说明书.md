## 给你的拍板要点（请逐条回：同意 / 改成… / 不做）

1. **锁定保留现栈**：前端 React 19 + TypeScript + Vite；数据 PocketBase（SQLite + pb_hooks）；增强层 Node sidecar；文档导出继续浏览器端为主。  
2. **客户端形态**：主产品继续 **Web**（本机/局域网）；允许后续加**轻 PWA**；**不**把 Electron/Tauri 收回为主产品壳。  
3. **明确否决（本轮及紧随开发窗口）**：不换 Python/Go 作主业务后端；不整站替换为 Dify / FastGPT / RAGFlow / LightRAG 等；不以 NocoDB/Teable 替换台账；不把 Harness 内嵌进工作站（保持外置 + MCP）。  
4. **与「以后 / 冻结」的关系**：账号隔离不驱动换栈；包 1–3 止血在现栈上改，不借选型重开底座。  
5. **D2 你点头后**：D3 按本栈画目标架构；任何「换语言/换底座」提案视为改章程，需你重开 D0/D2。

## 1. 为什么先锁栈（一句话）

半残主因是**主链路可靠性、草稿与失败可感知、部署出口、知识注入、情报触发方式**，不是「React 不行」或「PB 不行」。换栈会丢掉领域规则、测试网与售前已熟的操作路径，**性价比最差**（D0 §4、docs/10 第六节同向）。

## 2. 四层对照

### 2.1 前端

| 项 | 内容 |
|---|---|
| **现状** | React 19 + TS + Vite 8；Tailwind + Radix/shadcn；react-router；页面巨型 hook（ADR 既有）；浏览器端 docx/pptx/xlsx/pdfjs/mermaid 等 |
| **备选** | Vue/PPTist 系；Next.js 全栈；微前端拆包；纯服务端渲染壳 |
| **推荐** | **继续 React + Vite + TS + 现壳/路由** |
| **理由** | 业务与测试已绑在此栈；重库懒加载红线（R124）已建立；换 UI 框架 = 重写标书/方案/PPT，与「保留业务内核」冲突 |
| **否决** | PPTist（Vue + AGPL，docs/10）；为「好看」整站重画（D0/D6：先不改壳）；上 Next 强行 SSR——本机局域网工具收益低、迁移成本高 |

### 2.2 PocketBase（数据与 API）

| 项 | 内容 |
|---|---|
| **现状** | PocketBase + SQLite；pb_hooks 持有模型 Key、网关与业务路由；约 36–40 集合；前端经 `/__pb` 代理 |
| **备选** | 自研 Express/Fastify + Postgres；Supabase；Firebase；NocoDB/Teable 当主库 |
| **推荐** | **继续 PocketBase + pb_hooks**；平台项（身份、统一出口）在其上增量，不换引擎 |
| **理由** | 单团队本地/局域网形态匹配；集合与钩子已承载领域数据；换库等于数据迁移 + 重写钩子 + 冻结期无业务收益 |
| **否决** | NocoDB/Teable/Twenty 当主数据面（docs/10：双系统双权限）；为「以后账号隔离」提前换 Postgres——隔离是身份模型问题，PB 原生 auth 可演进（D0：以后再做） |

### 2.3 Sidecar（增强层）

| 项 | 内容 |
|---|---|
| **现状** | Node HTTP `:7001`；LibreOffice/大文档/AnyTXT/生图等；可降级；**不碰数据库**；地址曾写死 127.0.0.1 导致同事浏览器不可达（code_analysis） |
| **备选** | 全部改 Python 侧车为主；Go 重写；取消 sidecar 纯浏览器；并入 PB 单进程 |
| **推荐** | **继续 Node sidecar 为增强层**；重 OCR/版面等按 docs/10 **按需加 Python 工具进程**（OCRmyPDF/docling 等），不把主业务迁到 Python |
| **理由** | 与前端同语言族、现有模块在；「可降级」设计正确；同事不可达是**部署出口**问题（D3/D5），不是语言问题 |
| **否决** | 用 Python/Go **替换**主业务与 PB 钩子；把模型 Key 与核心写入逻辑只放进无鉴权侧车；取消增强层逼浏览器硬扛大文档 |

### 2.4 客户端形态（Web vs Electron / Tauri / PWA）

| 项 | 内容 |
|---|---|
| **现状** | 已从 Electron 迁到 Web；`start-local` 起 PB + Vite 开发服；局域网可打开页面 |
| **备选** | Electron/Tauri 重做壳；独立移动 App；轻 PWA；纯云 SaaS |
| **推荐** | **Web 为主**；**可选轻 PWA**（离线缓存/桌面图标级，不做完整离线编制）；移动端以响应式「能看能点」为界，不做独立 App（D0） |
| **理由** | 半残不来自缺桌面壳；Electron 迁出成本已付；桌面壳解决不了网关超时、大纲丢、sidecar 出口；PWA 成本低、可后加 |
| **否决** | 主产品改回 Electron/Tauri（D0）；多租户公网 SaaS；本轮独立移动 App |

## 4. 与「账号隔离以后」「包 1–3 冻结」的关系

- **账号隔离**：不改变本说明书推荐栈；将来若做，优先 PB 原生 auth / 行级归属与 xz-mcp 鉴权对齐，**仍不借机换底座**。  
- **包 1–3 冻结**：选型结论**不授权**现在改 `useBidWorkspace` 等业务实现；冻结后若按 D5 开工，止血在现栈上做。  
- **Open Design**：继续作为工作站 AI 主通道约定（密钥不进文档）；与「用什么前端框架」正交。  
- **Harness + xz-mcp**：外置助手轨；工作站仍是业务数据与编制主场。
