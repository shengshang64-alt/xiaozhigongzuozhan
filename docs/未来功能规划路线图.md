# 售前工作台 · 未来功能规划路线图

> 起草：2026-09-27，基于首轮全面质量走查（docs/质量台账.md）、既有缺口盘点（docs/06）、架构现状与医疗信息化售前业务纵深。
> 总原则：**真实严谨 > 自动化程度**——每项新能力先回答"数据从哪来、错了怎么发现"，宁可少自动化，不可多静默错误。

## 二、业务纵深（1~2 月，直接提升"拿下项目"能力）

### 1. 资质与人员证书台账 + 到期预警（最高优先）
- 依据 docs/06：**证书过期直接废标**，是当前最大业务缺口；且 kbPolicy 默认脱敏导致 AI 用不上资质原文。
- 建设：结构化台账（证照名/编号/有效期/适用项目/对外可用性）+ 到期三档预警（90/30/7 天）+ 标书工作台"资质核验"步骤（生成前自动检查引用的资质是否有效）。
- 验收：投标导出前，引用到过期/缺失资质时强制拦截并明示。

### 2. 招标文件倾向性/排他性参数识别
- 解析阶段新增"排他条款"检测：指定品牌、指定业绩年限、奇葩资质组合，输出《倾向性风险清单》供售前决策投/不投。
- 验收：历史已投项目回放，倾向性条款召回率人工评估 ≥80%，且每条可定位到原文页码。

### 3. 业绩合同台账 + 同类业绩自动匹配
- 结构化业绩（项目名/甲方/金额/年份/验收文件），投标时按招标要求自动匹配"同类业绩"并生成证明材料清单。
- 验收：给定评分办法，匹配结果与人工挑选一致性抽查 ≥90%。

### 4. 投标日历 + 保证金台账
- 开标时间、保证金缴纳/退还、原件携带，全部进日历与驾驶舱提醒（复用现有 FollowUpReminderCard 机制）。

## 三、平台能力（2~3 月，为规模化和"给医院看"服务）

### 1. 情报采集服务化
- 现状痛点：抓取靠前端页面驻留触发（关页面就停），jina 免费档限流导致正文缺失。
- 建设：PocketBase cron 或独立抓取进程（pb_hooks cronAdd 若 lint 解禁，或 Windows 计划任务调 tick）；每个源独立的失败退避策略；正文抓取通道可配代理池/付费 jina key。
- 验收：连续 72h 无人值守，源成功率 ≥85%，错标率 0（抽查口径）。

### 2. AI 成本与用量透明化
- token 用量落库（llm 任务已有 usage，只差存储）；每页面/每操作的成本画像；月度用量报表。
- 验收：任意一次生成可在"用量明细"里查到模型、token、耗时、费用。

### 3. 医院演示模式（关联真实性原则）
- 一键切换"演示数据集"：内置一套完整的虚构但自洽的医院数据（标注"演示"水印），与生产数据物理隔离（rh_user_id 隔离即可，不动 schema）。
- 验收：演示模式下从驾驶舱到标书导出全链路可走通，退出后生产数据零污染。

### 4. 检索升级：词法 BM25 → 混合检索
- 现状 kbCore 是纯词法（IDF+BM25+短语邻接），已够用但语义盲区存在（" HIS"匹配不到"医院信息系统"不在词表时）。
- 建设：轻量 embedding（个人模型接口带 embedding 的即可）做二路召回 + 现有词法融合，保持 kbPolicy 脱敏策略不变；embedding 缺失时自动降级纯词法。
- 验收：20 条真实问答对比测试，混合检索命中率 ≥ 词法基线 +15%。

### 5. 审计日志（给医院看的另一面：可追溯）
- 关键动作（导出标书、删除、确认情报、AI 生成）记录 who/when/what，管理员可查。
- 验收：任意一份导出的标书可追溯到生成时用的模型、提示词版本与引用来源。

## 四、明确不做（防止发散）

- 不做多租户 SaaS 化改造（当前单团队本地部署是合理形态）。
- 不做自有爬虫集群/绕过反爬（合规风险，抓不到就手动录入兜底）。
- 不做即时通讯/协同办公（有企业微信/钉钉了，做好消息推送集成即可）。
- 不追求全自动投标（人工确认环节是严谨性的护城河，只做"人工效率放大器"）。
