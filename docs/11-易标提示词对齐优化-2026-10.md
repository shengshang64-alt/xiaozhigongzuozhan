> 对标来源：[OpenBidKit_Yibiao（易标投标工具箱）](https://github.com/FB208/OpenBidKit_Yibiao) main 分支（v2.20.2 更新日志 + `client/src/shared/prompts/*`、`outlineGenerationTaskV2.cjs`、`contentGenerationTask/Agent.cjs`、`bidAnalysisTask.cjs`、`content-generation/受限HTML生成规范.md`、`使用说明/更新日志/v2版本更新日志.md`、系列设计文章）。
> 本轮性质：提示词内容对齐（B 类流程——PROMPT_VERSION +1、快照重录、全量门禁），不改任何流程编排与数据结构。

## 二、本轮变更（易标 v2.16→v2.20.2 最新口径）

### 1. 解析通道：评分项 vs 评分要求语义区分（易标 v2.17.2 修复项 + 最新 techRequirements 分类原则）
- `wholeParse.ts` TECH_SCORE_TASK / BIZ_SCORE_TASK：注入「技术评分项=需在技术方案中一一响应、展开编写的具体评分内容；技术评分要求=约束评分/解释评分/定义扣分或判定规则的通用规则，禁止填入 items」的分类原则与判断依据；拿不准宁缺勿编。
- `sectionParse.ts`（T12 检索通道）tech_score / biz_score 同口径注入，PROMPT_VERSION 4→5。
- 收益：防止「偏离扣分总则/符合性要求」被当成评分项建章、进评分映射与评标对账（易标实测踩过的坑）。

### 2. 正文共享规则（`bidTypes.ts`，四章/节/续写/改写生成器自动生效）
- BID_STYLE_RULES +2（易标正文写作最新口径）：
  - 「落点具体」：每节落到实施措施/执行条件/责任分工/交付成果，禁止通篇概括。
  - 「伪标题禁令」（易标 v2.16.10）：正文内禁止重复标题行、引导语；编号列举仅用于步骤/流程/时间顺序，禁止在小节内再造与大纲重复的层级。
- FULLTEXT_GUARD_RULES +1（易标 v2.17「全局事实稳定性」）：
  - 「事实克制」：事实表是全文统一口径不是写作清单，禁止为覆盖事实增加无关段落、禁止各章重复罗列项目概况/人员/设备/制度。

### 3. 素材融入不提及来源（`bidChapter.ts` / `bidSection.ts`，PROMPT_VERSION 3→4）
- 【知识库参考素材】【定向参考素材】【团队写作资料】三条规则句与两个注入段头改写：融入时整理为本项目方案表述，正文不出现「知识库/素材/来源文档/自有资料/内部资料」等来源字样。
- 变更理由：投标正文是正式对外文件，来源痕迹应留在工作台与注入块（替换 17D 的「引用处注明来自自有资料」）；来源标注仍保留在注入块标记头，工作台内可追溯性不变。

### 4. 大纲门禁二审维度（`outlineGate.ts` PROMPT_VERSION 1→2，易标 v2.20.2 目录多轮复核 + outline_review 审核维度移植）
- 「重复与空泛」细化：近义、含义重叠、仅换一种说法均须指出；不同专业分支下确有独立含义的同名标题不机械判重。
- 新增「节点归属」评审维度：叶子放错章节须指出并给建议归属。

### 5. 编排 AI 配图画面差异化（`orchestration.ts`，易标 v2.18）
- aiImageEnabled 条件块追加：相邻 AI 配图候选主体不得相同（机房全景/设备特写/终端细节/完成状态交替），景别错开，禁止同构图只换文字。
- 顺手修复：条件块硬编码序号 10/11/11 重号问题改为动态编号（`extraRuleNo()`），组合开启时序号不再重复。

### 6. 废标自查前置定位（`voidCheck.ts` PROMPT_VERSION 2→3，易标三轮制「分析→检查→定稿」第一轮的单轮化）
- 新增「检查前置定位」：比对前先通读结构、定位资质/业绩/授权/报价/技术响应等重点材料章节与附件位置，再逐条比对；材料齐全性优先在定位位置与目录/附件清单处核对。
- 不做两轮/三轮流程改造：现有单轮已带 9 条防误报硬规则（结构性线索、同义词检索、公司经验补查），翻倍 token 成本换边际收益不划算，只吸收其「先定位后比对」的精髓。

## 三、明确不采纳项（与本项目架构/原则冲突或已覆盖）

| 易标能力 | 不采纳原因 |
|---|---|
| 受限 HTML 正文格式（yibiao:block、figure/template、布局名额 single/imageText/threeImages/fourImages） | 本项目正文为纯文本 + 结构化 figures JSON 契约（docx 生成链路不同），整套 HTML 规范不通用 |
| Pi Agent / OpenCode 智能体运行时、工作区文件式任务（outline V2 六阶段 agent 工作流） | 本项目为直调 LLM + 本地校验闭环；评分承接 [响应:Rx] 标注 + outlineGate 评审循环已覆盖同一目标 |
| HTML 图表类型（甘特/泳道/RACI/鱼骨等，配图类型对照表） | 依赖其本地转图服务；本项目 mermaid + AI 图 + 结构化 spec 图型已覆盖当前需求，后续可单独评估 |
| 事实缺失「允许 AI 补充设定并保持一致」档 | 违反本项目「真实严谨 > 自动化」总原则，维持【待填写】单档 |
| 目录阶段自动调整小节数量 | 已有 leafTarget 反推 + outlineGate 叶子体量带评审，等价覆盖 |

# 附：标书配图四类需求落地（2026-10-06 第二批）

> 需求：①系统截图（HTML+CSS 静态界面 / 用户上传 / 从材料取）②项目架构图（上传模板 / 自动生成）③流程图（同架构图）④项目实施甘特图（自动生成）。

## 现状盘点（本轮前的配图管线）

- 图型 5 种：architecture / flow / demo（结构化 SVG）、mermaid（本地渲染）、image（AI 位图/外链），统一 `figureToPng` 进 Word；智能编排（表格/配图/事实/焦点）+ AI 位图补图阶段均已就绪。
- 缺口：mermaid 白名单**无 gantt**（甘特图不可用）；demo 界面示意过于示意（不像系统截图）；无用户自有图片的上传/模板复用通道。

## 本轮落地

### ① 甘特图自动生成（需求④，全链路）
- `mermaidFigure.ts`：渲染白名单放行 `gantt`（本地渲染/导出/修复循环全兼容）。
- 编排（`orchestration.ts`）：新增可选图型 `"gantt"`——实施计划/进度/里程碑类内容优先编排甘特图，非进度类禁止。
- `bidTypes.ts`：OrchestrationFigureType 联合类型、标签表（甘特图）、两个净化白名单（批量编排 + 存量编排反序列化）同步。
- 章/节生成契约（`bidChapter.ts`/`bidSection.ts`）：gantt 契约——`figures 输出 {"type":"mermaid","code":"gantt …"}`，dateFormat+section 分期 2-5 期+after 链；总工期必须与全局事实一致，无日期依据用示意起点并在图注标注「进度为示意编排」（防编造日期）。
- `BidFigure`：gantt 源码识别为「甘特图」标签。
- 归属判断、邻接同类型错开、全文配图上限择优等既有编排逻辑自动兼容 gantt。

### ② 系统截图写实化（需求①「HTML+CSS 静态界面」的等价落地）
- `BidFigure.demoSvg` 重写：窗口标题栏（三色圆点+居中标题）+ 左侧菜单（首项选中态）+ 页头（模块名+操作按钮）+ 指标卡行 + 数据表（表头列名取 LLM 输出的模块名，数据行用中性骨架条）——语义内容来自模型输出、数据区不编造业务数值。
- 与既有 demo 契约完全兼容（sidebar/main 结构不变），老项目配图自动获得新渲染。

### ③ 上传截图 + 图模板库（需求①②③的「我自己提供/模板复用」半边）
- 新增 `figureAssets.ts`（零 schema，localStorage 登记表，上限 60 条）：模板登记/去重/删除/按文件名猜类别（架构→architecture、流程/甘特/计划→flow、其余→screenshot）。
- `useBidWorkspace`：`uploadChapterFigure`（aigc 直传→persistMediaUrl 落 PB→插入当前章 figures→自动登记模板库）、`insertFigureTemplate`、`removeFigureTemplateById`；插入为 `{type:"image"}` 图，同名替换不堆叠，导出 Word 走既有 image 链路。
- 新增 `FigureInsertTools` 组件（上传按钮 + 模板库 Dialog，按类别分组、缩略图预览、一键插入本章/移除登记），挂在 ChapterEditor 新增的 `figureToolbar` 槽位（标书工作页注入，方案编制页不受影响）。
- 使用路径：项目 A 上传一张「医院总体架构图」→ 自动进模板库 → 项目 B 一键插入；或把历史标书里的系统截图批量传进来复用。
