## 二、交付清单

### 任务 1.1 首页信息架构重构

**新结构**（首屏 5 模块，其余零删除收进折叠区）：

```
┌─ 紧凑欢迎条（问候 + 日期 + 今日行动摘要一行）        CompactWelcomeBar
├─ 三张关键指标卡（资质预警 / 情报待确认 / 最近投标截止） NewKeyMetrics
├─ 今日优先任务（前 3 项，逾期红/今日橙/进行中蓝）      PriorityTasksBoard
├─ 快捷操作四入口（新建商机/导入招标文件/查询资质/添加待办） QuickActionButtons
├─ 进度速览双栏（工作台进行中 / 今日动态）              CompactProgressPanel
└─ 更多工作台模块（默认折叠；展开=改版前完整首页）        原 11 个模块原样保留
```

**关键设计决策**（规范示例代码与真实代码库的三处对齐）：
1. **真实数据替代 mock**：规范示例是硬编码数组（metricsData/tasks），实际实现全部接 `useHome` 既有数据（mustSee / qualRisk / intelPendingCount / activeWork / activityEvents / projects），**零新增网络请求、零新增后端改动**；派生逻辑收敛到 `homeLayout.ts` 纯函数层（可脱离 React 单测）。
2. **设计令牌替代裸色值**：规范示例用 `#EF4444` 等硬编码色，实际用全站语义令牌（destructive / warning / primary），自动兼容暗色模式与个性化配色。
3. **折叠区保证零破坏**：「不要删除已有业务逻辑」用「整体折叠」实现——待办增删改、项目详情弹框、商机漏斗等 11 个模块原样保留在「更多工作台模块」内，展开即回到改版前首页。

新增文件：`src/pages/Home/homeLayout.ts`（+test）、`src/components/home/{CompactWelcomeBar,NewKeyMetrics,PriorityTasksBoard,QuickActionButtons,CompactProgressPanel}.tsx`（前两者带 render 测试，四个面板组件全带测试）
修改：`HomePage.tsx`（新组合）、`useHome.ts`（仅增量暴露 `nowTick` 心跳，满足 react-hooks/purity）

### 任务 1.2 术语治理

- `scripts/check-prohibited-words.js`（`npm run check:terms`）：扫描 src 全部 .ts/.tsx（含注释），禁用词表：作战/制胜/决胜/杀手锏/利器/赋能/抓手；`ALLOW_FILES` 白名单逐条写明放行理由。
- **白名单的核心结论**：多数命中是「功能内容」而非文案——反 AI 套话链路（bidProseLinter 规则表、三处提示词禁词表）里的「赋能/抓手」正是产品要拦截的词；竞品数据里「AI 赋能临床」是事实转述。改了它们 = 破坏功能。
- 已清理 8 个文件的非功能性注释（routeRegistry / BidNodesCard / PipelineStepper / OpportunityLinkBar / kbAssemble / kbTaxonomy / BidWorkspacePage / TabbedOutlet.test）。
- 交付 `docs/术语规范表.md`：禁用词替换表 + 统一术语 + 白名单理由 + 遗留待办。

**唯一遗留**：`BidWarRoom.tsx` 的「作战室/投标作战室」两处 UI 文案——该文件存在另一会话未提交改动（BidWorkspace 大改），本轮不裹挟编辑，已在白名单留档，建议该文件落地后改为「项目速览/投标项目速览」。

### 任务 1.3 交互反馈

- 新增 `src/components/common/LoadingOverlay.tsx`（relative/fullscreen 两态，role=status 可读屏播报）。
- MaterialLibrary「清空回收站」从 `window.confirm` 收敛到全站统一 `ConfirmDialog`（danger 态）——全站最后一个原生确认框。
- 删除二次确认主链路此前已覆盖（38 处 ConfirmDialog 在用），本轮浏览器 E2E 复验：待办删除弹确认 → 确认后删除成功。
