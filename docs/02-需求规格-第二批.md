## 分项规格

### R-201 多人登录与权限管理（P0）

**用户价值**：10 人团队共用，数据归属可区分、可管控；模型消耗可归因到人。

**现状**：本地部署绕过鉴权（`X-Rh-User-Id: local-user` 固定身份），`users` auth collection 已存在但 0 记录；
全部 pb_hooks 自定义路由只认请求头、不验 token——存在越权风险（安全红线）。

**方案（分两阶段，均可回滚）**：
- 阶段 A（本轮）：
  1. `users` 扩展字段：`display_name`（姓名）、`role`（admin/editor/viewer）、`team_shared`（是否共享团队数据，默认 true）；
  2. 登录页：邮箱+密码 → PocketBase 原生 `POST /api/collections/users/auth-with-password` → token 存内存+sessionStorage；
  3. 前端 `vibexAuthHeaders()` 改造：登录态下同时带 `Authorization: Bearer <token>` 与真实 `X-Rh-User-Id=<users.id>`；未登录跳登录页；
  4. 服务端新增共享鉴权辅助（JSVM 公共函数）：`authFromContext(e)` 验 token 并返回用户记录；先接入写入类路由（solutions/quotes/bid_projects/customers/opportunities 的 POST/PATCH/DELETE）；
  5. 权限矩阵：admin=全部+用户管理；editor=业务数据增删改；viewer=只读+收藏。前端按 role 隐藏入口，服务端强制校验（鉴权不走前端）。
- 阶段 B（下一迭代）：全部 30 个 hook 路由接 `authFromContext`；个人数据（收藏/偏好/跟进）按真实 userId 隔离；用户管理页（admin 建号/禁用/重置密码）。

**验收标准**：
- [x] 未登录访问任何页面 → 重定向登录页；错误密码提示中文「账号或密码错误」；
- [x] admin 创建的账号可登录，右上角显示真实姓名与角色徽标；
- [x] viewer 调 POST /api/solutions 返回 403（服务端拦截，非前端隐藏）；
- [ ] 存量 `rh_user_id=local-user` 数据不丢：迁移脚本把 local-user 归属给首个 admin，且保留原值可回滚（迁移可逆，符合 2.1-6）；→ 阶段B
- [x] 退出登录清空 token；`npm run build` 通过。

**阶段A完成情况（后端 commit d1e580b，13/13 链路断言全绿；前端本轮完成）**：
- 后端：`team_auth.pb.js` 复用 PB 原生 `users` auth（密码哈希/token 由 PB 签发），`team_members` 档案集合（name/role/active），
  `/api/team/{status,setup,me,members}` 五路由，`routerUse` 全局中间件对 viewer 的写请求服务端 403。
- 前端：`teamAuth.ts`（会话/token 封装）+ `TeamAuthGate.tsx`（本地域整站门禁：checking→setup/login→granted，WorkbenchShell 包裹）；
  `TopBarShell` 角色徽标（admin 绿/editor 中性/viewer 醒目「只读」）；`/team` 成员管理页（列表/添加/改角色/启停，非 admin 无权限卡，自己那行禁操作），侧栏「团队管理」入口按 admin 显隐。
- 数据隔离（个人收藏/跟进按真实 userId）与 local-user 归属迁移留待**阶段B**。
- 已建测试账号：`admin@team.local`（管理员）、`viewer@team.local`（只读）；本轮端到端又建 `e2e-editor@team.local`（编辑，可停用）。

**依赖**：无外部依赖（PocketBase 自带 auth）。**风险**：hooks 鉴权改造面大 → 阶段 A 只接写入路由，读路由保持现状（数据敏感度低、内网部署）。

### R-205 PPT 图文并茂与本地 PPT 资产化（P1）

**默认假设**：配图来源=①内置医疗图标/插画素材库（零成本）+②AI 生图（走现有 aigc 通道，计费确认）+③用户上传；
