## 2 · 问题 → 根因 → 修法 → 验证

### 2.1 B13：比值法临界价漏乘下浮率（金额级错误）

**问题**
`fullScoreTargetPrice()` 回答的是标书工作里最值钱的一个问题：「我要报多少钱，价格分才能拿满」。在**均价做基准价 + 比值法打分 + 有下浮率**的招标里，它给的数偏大。实测实例（对手 1000/2000/3000 万，下浮 3%，满分 10 分）：

- 代码给临界价 **2000.00 万**
- 真值临界价 **1920.79 万**
- 按代码那个数报回去，实际只得 **9.7 分**（不是满分）

**根因**
均价口径下**我方报价自己也在样本池里**，报高会把基准价一起抬起来，所以临界价必须解一个自洽不动点。修复前 `src/pages/BidWorkspace/priceScoreModel.ts` 里两个分支写法不一致：

- 偏差法分支（原 :384-388）解了不动点：`p = (1-fl)·S/(n+fl)` ✓
- 比值法分支（原 :381）直接 `price = sum / n` —— 这是 **fl=0 特例**，把下浮率整个丢了 ✗

漏的原因是下浮率只被当成「偏差法才需要的东西」，其实基准价计算 `computeBaseline()` 对均价类口径**一律**乘 `(1 - floatPct/100)`（:264），与打分是比值法还是偏差法无关。

**修法**（`priceScoreModel.ts:380-390`，删 3 行加 4 行）
两个分支合并成一个：比值法满分条件是 `min(1, base/p)=1` 即 `base ≥ p`，偏差法满分条件是 `dev=0` 即 `p=base`，把 `base=(1-fl)(S+p)/(n+1)` 代进去，**两者化到同一个式子** `p = (1-fl)·S/(n+fl)`。所以删掉比值法那条特判，统一走已验证正确的不动点解；`fl=0` 时它自然退化回 `S/n`（旧行为不变），提示文案按 kind 分写。

新增单测：`src/pages/BidWorkspace/priceScoreModel.test.ts:265`（1 例，钉三件事 —— 闭式解数值、报回去真得满分、旧错答案 2000 万得 9.7 分作回归对照）。该组合此前 33 例全未覆盖。
