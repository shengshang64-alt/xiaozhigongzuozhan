## 一、问题：R50 的可见性闸门，数字是空的

R50 把「工具没看到的内容」从系统里赶了出去：`mode=retrieval`、`input_complete=false`、不可见条款一律 `partial + needs_review`。但 R50 自己登记的边界是：

> 检索质量只在构造样本上测过。切片 4 应带一份真实十万字级标书跑一遍。

构造样本是人造的短文本，`clause_hit` 接近满分是**正常的**，也正是它无法回答的问题：
**换成真实十万字级标书、133 条真实条款，这套检索到底能看见几条？**
如果答案是「十几条」，那么 R50 交付的不是「可见性诚实」，而是「诚实地说我看不见 90% 的条款」——止血带而已。这个数字必须被量出来，并固化成可复跑回归。

## 二、做法：真实标书 → 可复跑回归夹具（三步）

### 1. 夹具生成器（`scripts/azhongyi-real-fixture.mjs`）

只读 PocketBase（项目 id `mfl6howomsw5i0l`），拉取安中医项目的招标文件与投标正文，产出两份夹具：

| 产物 | 内容 | 是否入库 |
|---|---|---|
| `.probe/az-fixture/azhongyi.full.json` | 全量：tender 152,053 字 / bid 138,810 字 / 133 条款 | 否（含真实院名，仅供本机测量） |
| `src/pages/BidWorkspace/__fixtures__/azhongyiRealBid.json` | 脱敏子集：tender 32,957 字 / bid **47,103** 字 / 18 章 / 133 条款（第 3 章整章保留，其余每章截 1,900 字） | 是 |

**本轮对生成器的 3 处加固**（旧版脱敏不彻底）：

1. 脱敏范围从「只处理招标侧」扩到**投标正文章节内容也脱敏**——旧版投标正文里残留真实院名；
2. 新增行级脱敏 `scrubLabelLines` / `LABEL_LINE`：地址 / 联系人 / 电话 / 邮编 / 传真标签行只留占位；地址续行（「与X路交口」「…室」「…号楼」）整行删除；
3. 新增地址与路口正则：`（…交口）` → `（某路口）`、`…路N号` → `某市某路 000 号`。

脱敏自检（实测）：`安徽中医药大学=0`、`第一附属医院=0`、`梅山路=0`、`张老师=0`、`李工=0`、无手机号、无真实固话；占位符为 `某省级三甲中医医院` / `2026DEMO00001`。

### 2. 真实回归测试（`src/pages/BidWorkspace/bidVisibilityRealBid.test.ts`，27 例）

断言**行为不变量 + 下限**，不把命中率写死成精确值（否则检索一改进测试就红，等于用测试冻结缺陷）：

| 段 | 断言 |
|---|---|
| §0 | 夹具自洽与脱敏（18 章 / 47,103 字 / 133 条款、旧口径分布、脱敏形状） |
| §1 | `mode=retrieval` / `input_complete=false` / 注入 ≤ 20,000 / 未注入如实计量 / note 写明「输入完整：否」「未注入」「不得当作投标文件中不存在」 |
| §2 | 未覆盖章片段确实不在注入素材里（且原文确实存在）；覆盖章片段带来源标头 |
| §3 | 召回基线 **`hitFloor = 40`**（当前 56/133）；命中条款必带 sources；未命中逐条点名 |
| §4 | 旧口径对照：`clipText(12000)` 只覆盖开头 3 章却自称 `input_complete=true`（**不得回归**）；新路径必须覆盖更多章 |
| §5 | 端到端：模型只答可见条款 → `sanitizeDeviationRows` + `markInvisibleDeviationRows` → 不可见一律 `partial + needs_review=true`；导出无内部文案；体检上报 |
| §6 | `buildDeviationMapMessages` 的 user 消息含真实证据包、不含未注入章片段、空证据给显式占位 |
| §7 | 全量夹具（`.probe/` 存在时跑，否则 `skipIf`）：139k 字下 `needs_review > 100` |

### 3. 顺带修出的真实缺陷：`deviationCommitHits` 的两类命中共用上限

**位置**：`src/pages/BidWorkspace/bidTypes.ts` · `deviationCommitHits`

- **原缺陷**：负偏离（`deviation_undercommit`，**在 `GATE_FATAL_RULES` 质量闸黑名单里**）与「本次不可见」（`deviation_invisible_review`）**共用同一个 30 条上限**。长文场景下不可见动辄上百条，会把负偏离整批挤出 `hits` → 交卷体检判为「无废标级命中」，**闸门形同虚设**。这是 R50 引入可见性规则时带出来的新风险，只有真实长文才能暴露。
- **现实现**：先收集负偏离（≤30），再收集不可见（独立 ≤30）。实测：全量 6 条负偏离 + 30 条不可见；子集 29 + 30。

## 三、真实测量结果（`.probe/az-test/measure.txt`，本机实测原文）

### 全量（138,810 字 / 133 条款 / 预算 20,000）

```
mode=retrieval  input_complete=false   18 章 / 56 段，仅注入 6 段 ~19,542 字，未注入 119,268 字
clause_hit = 13/133 (9.8%)             覆盖 第1/3/5/6 章
  source[交货和服务要求] 6/79   source[技术评分要求] 5/27
  source[响应文件要求]   1/26   source[售后服务]     1/1
旧口径 clipText(12000)：只覆盖 2 章，却 input_complete=true、clause_hit=133/133
legacy 82 条 deviation → 可见证据仅 6 条
```

### 脱敏子集（47,103 字 / 133 条款）

```
mode=retrieval  input_complete=false   18 章 / 21 段，注入 7 段 ~19,944 字，未注入 27,159 字
clause_hit = 56/133 (42%)              覆盖 第1/3/5/6/7 章
  source[交货和服务要求] 37/79   source[响应文件要求] 14/26
  source[技术评分要求]   4/27    source[售后服务]     1/1
旧口径 clipText(12000)：3 章 / 12 字前缀字面命中 7/133
端到端模拟：total=133 / full=26 / partial=78 / deviation=29 / needs_review=77
commitHits = 30 条（旧代码会全是 invisible，负偏离被整批挤掉）
```

**两个数字分别说明了什么**：

- **9.8%（全量）是真问题**：在 138k 字 / 20k 字预算下，检索只看见 133 条条款中的 13 条。R50 的可见性报告如实说出来了（这是它该做的），但**靠 13 条证据去判 133 条条款的响应性，业务上不可接受**。
- **42%（子集）说明瓶颈是「预算 ÷ 正文长度」而不是检索算法本身**：同一套算法，正文缩短到 47k 后命中率涨到 4 倍以上。所以解法方向是**压缩单位证据、提高预算、或先摘要再取证**，而不是重写打分。
- **漏在哪是确定的**：第 4、8、9–18 章是全量下完全未覆盖的章（子集下第 2、4、8–18 章），已逐章点名，下轮可直接照着补。

## 六、未覆盖边界 / 已知不做

- **R50 的召回率问题本身本轮不修**：本轮只负责「把数字量出来并固化成回归」。修法（预算策略 / 两阶段取证 / 章节摘要树）需单开一轮，已登记 backlog `B25-long-bid-retrieval-recall`。
- **夹具是「每章截断」的子集，不是全量入库**：入库夹具刻意截断（全量为 139k 字、含更多可识别信息），因此**子集的 42% 不代表真实生产召回率**，生产值以本报告全量 9.8% 为准。测试 §7 在全量夹具存在时才跑，就是为了不让这个区别被忘掉。
- **夹具依赖本地 PocketBase 项目 `mfl6howomsw5i0l`**：生成器只读该实例；换机需先有同一项目，否则只能跑入库的脱敏子集（测试本身不依赖 7000）。
- **只测了 1 份标书**：安中医 1 例 + 133 条款。样本量为 1，结论强度有限；下轮补第二份不同结构（如纯条款清单型）的标书才能真正说明「检索器」优劣。
- 切片 4 / 切片 5（Flash 选型实测、交付金丝雀）**本轮仍不做**。
