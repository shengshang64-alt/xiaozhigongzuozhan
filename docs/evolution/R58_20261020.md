## 二、问题 → 根因 → 修法 → 验证

### 问题 1：项目 CRUD 是用户最常用的入口，却只有 grep 覆盖

`/bid-workspace` 首页就是项目列表，新建 / 重命名 / 删除是第一步动作；但 R57 侦察时这些句柄
（`createProject` / `updateProject` / `softDeleteProject` / `restoreProject` / `setProjectArchived` / `deleteProject`）
没有任何行为测试——它们的行为只靠十几处「读源码 + 正则」哨兵钉住字符串，不钉行为。

**根因**：R57 之前全仓 `renderHook` 命中 0 次，行为网是 R57 才从零铺起来的第一层，只来得及覆盖最痛的两个点（计费红线、大纲失败可诊断），项目 CRUD 排在 R57 自报的扩展顺序第一顺位、尚未轮到。

**修法**：新增 `src/pages/BidWorkspace/useBidWorkspace.projectCrud.test.tsx`（6 例），沿用 R57 的 3 旁路 mock（`pbJsonRequest` / `sonner` / `MemoryRouter`），不 mock 任何业务逻辑、零 AI、不触网。

**验证**：6 例全绿（见 §四）。

### 问题 2：行为网要能抓住真实回归，不能是「碰巧没断言到」的真空

R57 立下的纪律：行为网的用例必须做「删实现即变红」，否则无法区分「真的跑通了这条路径」与「只是碰巧没断言到」。

**修法**：做两条反向验证（字节级备份 + `finally` 还原，脚本在 `.probe/r58_rev_verify.cjs`，不入库）：

- **A**：删 `useBidWorkspace.ts` 里 `createProject` 的 `applyProjectState(record)` → 用例①「新建后自动打开为当前项目」变红（vitest exit 1）。
- **B**：删 `updateProject` 里的 `void persistProject(next, { ...patch, stage: nextStage }, opts?.quiet)` → 用例③「重命名 PATCH 落库」变红（vitest exit 1）。

**验证**：两条都变红，且还原后 `useBidWorkspace.ts` 字节一致（脚本自检 `restored === orig` 打印 PASS）。锚点均为唯一命中（`applyProjectState(record)` 1 处、`void persistProject(next, ...)` 1 处）。

## 三、新增测试守的 5 条契约（用户点几下就能对应上）

| # | 契约 | 断言（`useBidWorkspace.projectCrud.test.tsx`） |
| --- | --- | --- |
| ① | 新建项目：填名 → POST 落库 + 列表出现 + 自动打开 | POST `/api/bid_projects` 且 body 含 `rh_user_id=local-user`、`project_name`（已 trim）、`stage=pending_parse`；列表出现新项目；`activeProject.project_name` 等于新名；toast 含「已创建」 |
| ② | 新建项目：空名 → 只提示、零写请求 | toast 含「请填写项目名称」；`writes()` 为空（一分钱不花） |
| ③ | 重命名：`updateProject` 改 `project_name` → PATCH 落库 + 当前项目同步 | PATCH `/api/bid_projects/p1` 的 body 含 `project_name`；`activeProject.project_name` 同步 |
| ④ | 软删 → 还原：软删写 `deleted_at`、还原清空 | 软删 PATCH body `deleted_at` 非空 + toast「已移入回收站」；还原 PATCH body `deleted_at===""` + toast「已还原」 |
| ⑤ | 归档 → 取消归档：归档写 `archived:true`、取消写 `false` | PATCH body `archived===true` / `archived===false` + 对应 toast |
| ⑥ | 彻底删除：DELETE 落库 + 列表移除 + 按项目名提示 | DELETE `/api/bid_projects/p1`；列表不再含 p1；toast 含项目名与「已彻底删除」 |

关键前置事实（让测试跑在真实路径上）：本机 jsdom 默认域是 `localhost`，`decodeRhToken()` 走本地自用分支返回 `sub="local-user"`，所以 `requireLogin()` 放行、`loadProjects` 真发请求——这与 R57 行为网同一个「不 mock 业务逻辑」的前提。
