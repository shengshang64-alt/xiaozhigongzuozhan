## 1 · 问题 → 根因 → 修法 → 验证

### 问题（先测，不猜）

`src/components/bid-workspace/DeviationPanel.tsx:276`（改动前）在分组内 `g.rows.map()` 全量渲染。按 B46 纪律，**动手前先实测**：

**实测方法**：用真实语料 `test_results/审查正文-三明.txt`（47,046 字）+ 真实引擎 `resolveDeviationClauses(corpus, null, {limit:200, granularity:"l3"})` 造出 200 行真表，`render(<DeviationPanel …/>)` 后数 DOM。

```
{"corpusChars":47046,"clauseCount":200,"tableRows":200,"tbodyRows":200,
 "nodes":4224,"buttons":338,"tables":1,"ms":225}
```

→ **4224 节点 ≥ 1500 门槛 → 按规则改**（不是为凑活而改）。

### 根因

面板自身**没有行数上限**，它的 200 行来自调用侧 `useBidWorkspace` 的 `resolveDeviationClauses({ limit: 200 })`。也就是说：

- 200 是**数据截断**，不是渲染上限；
- 同一份三明语料在 `limit: 5000` 时能抽出 **949 条**；**真实项目「蚌埠医科大学第一附属医院智慧医疗核心业务系统」（招标原文 762,238 字）在 `limit: 5000` 时抽出 5000 条（顶满传参上限）**。

所以这棵树的行数不是稳定在 200，而是随「条款密度 × 调用侧 limit」线性膨胀。一旦有人调大 limit（或换更密的招标文件），面板会立刻变成编制页最重的子树——与 R80 修的响应表是同一类病。

### 修法（`DeviationPanel.tsx`）

1. `PAGE_SIZE = 100`（与 R80 同口径，注释里写明实测依据与「为什么是 100」）。
2. 新增 `page` 态；派生 `pageCount` / `safePage` / `pageRows`：
   - `safePage = Math.min(page, pageCount - 1)` —— **页码夹取**，防「看到第 2 页 → 换来源后只剩 1 页 → 空白表」。
   - `pageRows = rows.slice(safePage*PAGE_SIZE, …)` —— 只切渲染切片。
3. **分组与分页的语义冲突单独处理**：原实现是「先分组再渲染」，直接切 `rows` 会让同一来源跨页、组头数字变小。做法是**先按全局行序切片，再对切片重新分组**，并让组头如实标注：
   - 该来源全部在本页 → `100 条`
   - 该来源跨页 → `本页 100 条 / 全部 200 条`
   （只写「X 条」会让用户以为这一组只有这么多，翻页才发现还有。）
4. `gotoPage()` 翻页时 `setExpandedKey(null)` —— 展开态的 key 里含行号，不清理会漂到新页另一条条款上。
5. 分页条放在分组列表之后，**仅 `pageCount > 1` 时渲染** —— ≤100 行时零视觉变化。

关键边界：`rows` 未被切。统计卡（总条款/完全响应/部分响应/偏离/待人工核对）、`deviationVerbatimReport`、`exportDeviationWord` 全部仍用全量 `rows`。

| 指标 | 改前 | 改后 | 变化 |

| `<button>` | 338 | **175** | −48.2% |

**真实项目实机验证**（PB 真实记录，非合成夹具）：

**行为测试**（`DeviationPanel.test.tsx` 新增 8 例，23 例全绿）：

## 5 · 用户 3 分钟验收

**这轮做了什么（一句话）**：技术偏离表不再一次性渲染 200 行，改成每页 100 条 + 翻页条，首屏 DOM 减少 49%。

**怎么验证**：

1. `start-local.cmd` → 打开标书工作台 → 选「蚌埠医科大学第一附属医院智慧医疗核心业务系统」（真实项目，76.2 万字招标原文）→ 第 3 步。
2. 点 `📋 偏离与响应表` Tab，找到「技术偏离表」。
3. **如果该项目已生成偏离表**（`response_map` 非空）：表格下方应出现分页条「第 1–100 条 / 共 200 条（每页 100 条）」+ `1 / 2`；点「下一页」内容整体换批；若某来源跨页，组头会写「本页 X 条 / 全部 Y 条」。
4. **如果该项目尚未生成偏离表**（当前真实库 5 个项目的 `response_map` 都是空数组 `[]`，所以大概率看不到表）：这是数据现状不是 bug。可先点面板上「生成偏离表」（会走 AI，产生费用），或直接以测试用例为准：
   ```bash
   npx vitest run src/components/bid-workspace/DeviationPanel.test.tsx
   # → Tests 23 passed
   ```
5. 顺手核对：统计卡「总条款」数字翻页时不变（证明统计走全量）。

**改坏的风险：低**

- ≤100 行路径是唯一没改的分支，且有用例钉住（「≤100 行不出分页条」「未跨页来源只写 N 条」）。
- 唯一需要留意的语义变更：**跨页来源的组头文案**从「200 条」变成「本页 100 条 / 全部 200 条」——这是刻意为之，避免用户以为数据丢了。
- 未触碰任何数据写入与导出路：Word 导出仍导全量 200 条，条数不变。
- 已知取舍：翻页会收起已展开的行（避免展开态漂移），若希望保留展开需改用行 id 作 key，属可选优化。
