## 二、第 3 问：改前是「不能真用」，现在是「真能用」

### 2.1 改前失效的根因（实测，非推断）

本系统导出的 docx 把格式**写死在每个 run 的 `<w:rPr>` 上**，而样式层是空的：

| 实测项（`安中医-投标文件.docx`） | 改前 |
|---|---|
| run 数 / 带 `<w:rPr>` 的 run 数 | 678 / 678 |
| 文档内 `<w:rFonts>`（字体）个数 | **0** |
| `styles.xml` 是否有 `Normal` 正文样式 | **无** |
| `docDefaults` | `<w:rPrDefault/><w:pPrDefault/>`（**全空**） |

旧实现只改 `styles.xml` → 样式层改了、文字层没改 → **视觉零变化**；
且因为没有 `Normal` 样式，行距刷新**必然 fail**。

### 2.2 本轮修复（`src/pages/FormatTool/refreshDocx.ts` 等）

- 新增直接格式改写：`elementSpans`（深度计数容忍嵌套）/ `paraTarget` /
  `rewriteParagraphDirect` / `rewriteDirectFormat`，按范围（font/heading/spacing/page）
  同步改写**文字级** `<w:rPr>`；`RefreshStats` 如实统计改写处数。
- `refreshStylesXml` 缺 `Normal` 时**补建并写入正文格式**（否则正文格式在样式层无处落地）。
- 先改 `sectPr` 再按范围改直接格式；`buildApplyReport` 改为「标题按样式块判定（大小写不敏感）
  + 接受『文字级已改写』作生效证据」，报告新增 `direct` 字段。
- `refreshDocxFile` 新增 `opts.overrideDirectFormat`（默认 true，UI 可关）。
- UI：勾选框「覆盖文字级直接格式」+ 报告面板直接格式统计行。
- 修本轮测试抓出的两个真 bug：
  - 补建的 `Normal` 插到了 `out` 上、被 `return result` 整块丢掉；
  - `docDefaults` 内 `rPr` 偏移按 `rprd.text` 相对定位，旧写法产出**非法 XML**
    （Word 会报「文件已损坏」）。

### 2.3 改后实测（真实样本，脚本 `docs/evolution/_r46_format_refresh_verify.mjs`）

用「安中医-投标文件.docx」的格式标准刷新它自己：

```
槽位 ok 4/4｜正文字符数 137436 -> 137436 ✓ 文字0改动
正文文字逐字一致：✓ 完全一致（138022 字）
产出 XML 合法性：document.xml ✓；styles.xml ✓
docDefaults：存在 ✓；rPr 个数 1（应为 1）；含目标字体 ✓
样式表含 Normal 正文样式：✓
run 678 个，其中显式 <w:rFonts> 0 -> 677
损坏文件：抛错「invalid zip data」→ 界面提示「请确认文档是未加密的 .docx」✓
```

即：**格式确实改到了、正文一个字没动、产出的 docx 是合法可打开的**。

### 2.4 识别侧（第 3 问的另一半）：为什么原来读出来是空的

同一份导出物里**根本没有字体信息可读**，所以识别侧读出「正文: ?」。

修复（`src/pages/FormatTool/formatSpec.ts`）：
- 新增文字级抽样推定 `sampleDirectFormat`（按字符数加权众数推定字体 / 字号 / 行距 / 对齐 / 首行缩进，
  跳过表格内与封面 / 自定义样式段落）；
- `FormatSpec` 新增 `bodySource`（style/sampled/default）、`sampledChars`、`sampleAmbiguous`；
- **不臆造**：字体确实没写时，如实给「原文档没有写入字体信息…按系统默认套用」，
  而不是含糊地说「已抽样推定」。

## 三、顺藤摸出的更上游根因：默认导出不写字体（已修）

`src/pages/BidWorkspace/bidFiles.ts` 的 `exportBidDocxDefaults`（存量项目
`format_settings=null` 走的路径）此前构造 run **只给 `size`、不给 `font`**：

```ts
// 改前
children: [new TextRun({ text, size: 24 })]        // 正文
children: [new TextRun({ text, bold: true, size: 30 })]  // 一级标题
```

后果：导出物里 **0 个 `<w:rFonts>`** → Word 落到主题默认字体（正文不是仿宋、标题不是黑体），
并且格式识别 / 暗标检查都读不到字体。这也解释了 §2.4 的现象。

修复：新增 `DEFAULT_RUN_FONT`（标题 黑体 / SimHei，正文 仿宋 / FangSong），
标题级 `titlePara/h1/h2/h3`、正文级 `body`、封面副标题、图注全部显式写入字体。

实测（`docs/evolution/_r46_default_export_font_verify.mjs`，真实构建 docx）：

```
document.xml <w:rFonts> 个数：9
  含 eastAsia="黑体"：✓   含 eastAsia="仿宋"：✓
  含 ascii="SimHei"：✓    含 ascii="FangSong"：✓
无字体的裸 <w:rPr><w:sz> 运行数：0
识别侧读回：正文字体 仿宋 / 12pt / 行距 1.5倍
标题：L1:黑体/16pt  L2:黑体/13pt
```

→ **导出 → 识别 → 刷新** 三条链路首次闭合。

## 六、第 1 / 2 问的结论（本轮给判断 + 记账，不硬塞半成品）

### 6.1 第 1 问：能不能自动识别 / 切换「适合写标书的模型」？—— **现在不能，且缺口不大**

现状（读码结论）：

- 已有：手选模型 + 失败回退 `src/lib/modelFailover.ts` + 延迟预算 `src/lib/latencyBudget.ts`
  + 模型画像 `src/lib/modelProfiles.ts`。
- **画像里的 `tags`（长文 / 长文档 / 推理 / 中文…）与 `specialty` 目前只用于 UI 徽标展示，
  完全不参与路由** —— 这是数据已经就位、只差一层决策函数的典型情形。
- 多处子面板传 `modelRef: null` 走平台默认，本地部署下会**静默失效**。

结论：**有必要做，但不必改整体网关**。最小闭环 =
① 新增纯函数 `pickModelForRole(role, available, profiles)`（role：长文正文 / 章节大纲 / 解析抽取 /
视觉审阅 …；打分 = tags 匹配 + 上下文长度 + 可用性 + 成本），
② 标书工作台各步骤接入该函数，③ 保留用户手选覆盖（自动仅是默认值）。
→ 已登记 backlog `B19-auto-model-route`。

### 6.2 第 2 问：上传商务模板 → 自动识别样式/排版/内容/要求？—— **样式与排版已能识别，其余是缺口**

现状（读码结论）：

- 已有两条**重复**的识别链路：`src/pages/FormatTool/formatSpec.ts`（强，本轮又增强）
  与 `src/pages/BidWorkspace/bidDocxFormatExtract.ts`（弱）；底稿合并链路
  `bidDraftImport.ts` + `FormatSyncDialog.tsx`，**仅支持 1–3 级标题**。
- 缺：4–6 级标题、表格样式、页眉页脚、页码、封面、目录域、编号规则；
  模板里的**「内容要求」文本提取**；与招标文件评分点 / ★▲ 条款的**对齐**。

结论：**有必要，但要按「模板 onboarding → 项目级 `template_profile`」一次做对**，
否则就是在两条重复链路上再加第三条。→ 已登记 backlog `B20-template-onboarding`。

## 七、长教训 / 纪律（写死以免再犯）

- **「格式刷新」测真本事只有一个办法**：拿本系统**自己导出**的 docx 去刷新 —— 合成 fixture
  反而会掩盖「文字层写死格式」这个真实形态。本轮起 `refreshDocx.test.ts` 常备此类用例。
- **导出物必须自带字体**：`docx` 库的 `TextRun` 不给 `font` 就不会写 `<w:rFonts>`，
  这是「账面有格式、实际没格式」的隐形坑。今后任何新增导出路径都要带字体。
- **不许拿「样式层改了」当生效证据**：判定要以「视觉可变的文字级 / 样式级并集」为准。
