## 二 · 本轮落地：`priceScoreModel.ts`（引擎 414 行 + 单测 341 行）

### 问题
招标文件写「投标报价得分＝（评标基准价/投标报价）×10％×100」，我们存了这行字，却没有任何代码能算出「报 2480 万拿几分」。售前只能靠 Excel 手算，且**手算常常只算得分、不算「为拿满分该降到哪、那个价是不是废标价」**。

### 根因
解析链路把价格分当「文本」处理（`criteria` 字段是给人看的抄录），下游 `scoringItemsFromReport`（bidTypes.ts:1898）→ 模拟评标只把文本喂给大模型，**没有确定性的价格分模型**。大模型也不该算这类数：评标办法的算术必须可复核，让 LLM 口算得分属被质疑/废标级风险。

### 修法
新增纯函数模块，只认两类能机械复算的口径，**认不出就不算**：

1. `parsePriceFormula(原文, 满分)`（:173）——识别 `ratio`（比值法）与 `deviation`（偏差扣分法）；基准价口径三选一：最低价 / 算术平均 / 去极值平均；支持「平均值下浮 3%」的下浮率、双向扣分费率、`×10%×100` 与 `×价格权值×100` 两种满分写法。全角 `＝／×％（）` 与多余空格先归一（:76）。
2. `scorePrice(公式, 我方报价, 对手报价[])`（:283）——按口径复算基准价与得分；比值法封顶满分、偏差法扣完为止（不出负分、不超满分）；得分统一走 `money.ts` 的 R34 分位精确舍入，不吃二进制浮点尾差。
3. `priceScoreLadder(...)`（:333）——±% 报价敏感性阶梯，**每档重算基准价**（均价口径下我方报价本身进样本池，挪报价会拖动基准价，不能钉死基准价算）。
4. `fullScoreTargetPrice(...)`（:361）——拿满价格分的报价临界值 + 需要降价的幅度。均价/偏差口径给了闭式解（偏差法求自洽不动点 `p = (1-fl)·S/(n+fl)`）；去极值口径无闭式解时**返回 null**，交阶梯试算。
5. `checkPriceValidity(price, limits)`（:75）——本轮最关键的一层：真实招标文件写着「投标报价＜采购项目最高限价×45% 按无效投标处理」。**没有这层守护，第 4 条会直接给出「降到 1000 万拿满分」的废标建议。**
6. `findPriceScoringItem(评分项[])`（:403）——从已有评分项里挑出可测算的价格分项，识别不出的项跳过，不把「猜的」当「算的」。

**拒绝猜测的 6 个出口**（都有单测钉住）：公式不属于两类可复算口径 / 未标明评标基准价怎么来 / 偏差费率不成对 / 按「元」扣分不按 % / 公式隐含满分与分值列冲突（要求人工复核，不擅自取其一）/ 没有对手报价（价格分是相对分，缺参照系不给数）。

## 三 · 给非程序员：怎么自己验一下

1. 打开终端，在项目目录粘这一行，回车：
   `npx vite-node docs/evolution/_r35_real_tender_price_score.ts`
2. 看到 6 段中文标题的输出（【招标文件原文条款】到【区间守护】）。
3. 只需盯两行：
   - `【我方报价测算】` 里的 `"score":4.03` —— 用计算器算 `10000000 ÷ 24800000 × 10`，应得 4.0322… → 一致。
   - `【拿满分临界价】` 里的 `"invalidReason"` 不为 null —— 意思是「想拿满价格分就得报到 1000 万，但招标文件规定低于 1125 万（限价的 45%）算废标」，工具没有把这条废标建议直接推给你。
4. 想看它什么时候**不肯算**：把脚本第 4 行的对手报价改成空数组 `[]` 再跑，`【我方报价测算】` 会变成 `{"ok":false,"reason":"缺有效对手报价…"}`。

## 五 · 遗留项（如实记录）

- **L1｜引擎还没有用户入口**：本轮只交付算法层（§3.4「只落地能独立验证的一小步」的取舍），当前唯一消费者是单测与证据脚本。非用户可见功能。
- **L2｜对手报价没有数据源**：价格分是相对分，`competitor_evidence` 里是**中标金额**不是**投标报价**，不能拿来当对手报价用。故本轮刻意不自动取数（自动取数＝悄悄用错数据，属 R034 同类的「金额悄悄错」）。B12 需按手输设计。
- **L3｜未覆盖的口径**：按「元」计扣分、`低于基准价不扣分` 单边费率、`评标基准价×95% 得满分` 档位法、复合标底（招标人标底与均价加权）——均返回 `ok:false` 交人工。识别不出属设计选择，不是漏测。
- **L4｜偏差法线性扣分口径假设**：按「不足 1% 的部分同比例扣」线性计算。部分招标文件写「不足 1% 不计」或「向上取整」，此类条款文字本轮未识别；B12 落地时应在面板上把这行假设显示给用户确认。
- **L5｜环境**：R34 遗留的 `npx vite preview --port 5199`（PID 24532）本轮未处理（hook 禁止智能体结束进程），需用户自行关闭。本轮**未启动任何新服务**。
