## 一、问题：长正文在进模型之前就已经丢了一半，而且没人知道

医疗信息化标书正文常达数万字。改前链路上有三处静默丢失：

| 环节 | 改前行为 | 后果 |
|---|---|---|
| 废标自查 | `clipText(正文, MAX_BID_CHARS)` 截断后送模型 | 模型对自己没看到的条款照样给结论，结论无依据却与有依据的结论长得一样 |
| 偏离表 | 同样截断，另给「每章前 300 字摘要」当替代品 | 摘要是改写内容，模型据此判「响应位置」会指向不存在的正文 |
| 漏答兜底 | `sanitizeDeviationRows` 把 AI 没答的条款兜底为 **`deviation`（负偏离）** | 「系统没看到」→「投标人承诺不够」→ `deviationCommitHits` 命中 `deviation_undercommit` → 该规则在 **`GATE_FATAL_RULES`（硬闸）** 里 → 交付被拦、且措辞把责任判给了投标人 |

一句话：**不可见 ≠ 未响应，但系统把两者当成了同一件事。** 这是对外交付级事故（可交付的标书被判成废标风险），也是切片 3 要解决的问题。

## 四、最小人工复验步骤（≈4 分钟，全部可在界面上点出来）

1. 定向测试：`npx vitest run src/components/bid-workspace/DeviationPanel.test.tsx src/pages/BidWorkspace/bidVisibility.test.ts src/pages/BidWorkspace/bidFormatCheck.test.ts src/pages/BidWorkspace/promptVisibilityWiring.test.ts`
   → 期望 `4 passed / 103 passed`。
2. 把某条款对应的正文段落从章节里删掉，再点「生成偏离表」→ 该行应为 **「部分响应」+ 黄色「待人工核对」角标**，表格上方出现「待人工核对 N 条」提示，分组头出现「待核对 N 条」。
3. 同一项目点「导出偏离表」→ 打开 Word，该行「响应内容摘要」必须是 **「响应内容详见投标文件正文对应章节」**，全文不得出现「AI 未定位」「未注入」字样。
4. 把正文写到 2 万字以上再生成偏离表（或废标自查）→ toast 应显示已注入字数 / 定向检索段数 / 未注入字数。
5. 交卷体检页 → 应出现 `deviation_invisible_review`（warn，措辞含「请人工核对未注入部分」）；「闸门 check」页**不应**因它而无法「直接确认」（只提示，不进制裁名单）。

## 五、未覆盖边界 / 已知不做

- **召回率没有真实验证**：检索质量只在构造样本上测过。切片 4（Flash 选型实测）应带一份真实十万字级标书跑一遍，记录条款命中率与「未命中条款的人工判读」一致率。
- **切块只认「第N章」标题**：纯条款清单型正文（无章节结构）会落到单块切分——预算内仍全量注入，超预算时按条款检索仍生效，但没有更细的定位。
- **`needs_review` 没有「已人工核对」回写入口**：用户核对完只能改响应程度或重生成，角标不会因「确认过」而消失。建议下轮补「标记已核对」按钮（本轮刻意不做，避免引入新的写库字段）。
- **存量项目一律 `needs_review=false`**：升级不会让旧数据突然亮黄，这是刻意选择（旧数据没有标记 ≠ 已核对）。
- 切片 4 / 切片 5（Flash 选型实测、交付金丝雀）**本轮不做**。
