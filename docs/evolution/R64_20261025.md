## 一、问题（先取证，再动手）

情报中心「健康报·卫健官方媒体」这个源，抓回来的摘要（`summary` 字段）是**三段粘在一行**：

```
－健康报网——健康门户 {"id":"514749","toptitle":"","toptitle_color":"","title":" ","title_color":"",
"subtitle":"——论学习贯彻…","crtime":"2026-10-22 09:49:07","condition":"来源： 健康报 ",
"thumb": "","topic": "0"} □本报评论员在全国卫生与健康大会上，习近平总书记指出，保障人民健康需要
```

即「站点名 + 页面 JSON 元数据 + 真正文」。而情报中心的**列表卡片和右侧详情面板都是原样渲染** `item.summary`，
所以售前点开情报看到的第一句话是 `{"id":"514749","toptitle":"",…}`。

### 实测数字（`docs/evolution/_r64_intel_summary_scan.mjs`，直连 :7000）

```
库内情报 627 条 / 有 summary 58 条 / 含 JSON 元数据 9 条
源「健康报·卫健官方媒体」：共 11 条，脏 9 条（81.8%），最新一条 created 2026-10-22（仍是脏的）
脏条 created 日期：2026-09-19 … 2026-10-22（跨 5 周，不是一次性历史遗留）
```

> 采集时库内 627 条，20 分钟后复跑已是 666 条（抓取任务在线跑），脏条仍是这 9 条。

## 二、根因（两层，第二层才是这轮的关键）

1. **入库层**：`pocketbase/pb_hooks/intel_center.pb.js` 的抓取摘要拼装把整段页面元数据一起塞进 `summary`。
2. **展示层**：`IntelCenter` 的两个组件直接渲染 `item.summary`，**没有任何清洗**；
   而首页动态卡（`useHome.ts:206`）用的是 `displayizeIntel(row.summary, 160)` —— 同一个字段，两个页面两种待遇。

**第二层还藏着一个反直觉现象**：`displayizeIntel` 的判据里有 `CSS_LINE_RE = /[{}]/`（整行含花括号即丢），
而这 9 条的 JSON 与真正文**在同一行**，于是首页把它们**整行丢掉**——表现为「有摘要，但摘要区是空的」。
所以本轮不能简单地「首页那套照搬过来」，必须先剥元数据块、再交给 `displayizeIntel`。

## 三、修法（最小改动，只动展示层，不碰数据）

`src/pages/IntelCenter/intelBodyClean.ts` 新增两个纯函数：

- `stripIntelMetaBlobs(raw)`：
  - 剥「站点名前缀」——判据锚在 `{` 上（`^[^\n{]{0,30}?(?:网|门户|官网|首页|日报|晚报)\s*(?=\{)`），
    所以「健康报网 报道：…」这种正常正文不会被误剥；
  - 剥平衡的扁平 JSON 元数据块（要求块内至少有一个 `"key":`，避免吃掉正文里的孤立花括号）；
  - 剥被截断到末尾的半截 JSON（抓取按长度截断所致，无右花括号）。
- `cleanIntelSummary(raw, max)` = `displayizeIntel(stripIntelMetaBlobs(raw), max)`。

三处接线（口径同源）：

| 位置 | 改动 |
|---|---|
| `src/components/intel-center/IntelItemCard.tsx` | 新增 `summaryText`，渲染与「是否显示摘要区」都挂在它上面（清洗后为空则不渲染空段落） |
| `src/components/intel-center/IntelDetailPanel.tsx` | 同上；**「复制」也改成复制清洗后的文本**，避免「看到的干净、复制出去是 JSON」 |
| `src/pages/Home/useHome.ts` | `displayizeIntel(row.summary)` → `cleanIntelSummary(row.summary)`，修掉「有摘要但空白」 |

**没有改数据库、没有改 pb_hooks、没有改 schema、没有新依赖。**
