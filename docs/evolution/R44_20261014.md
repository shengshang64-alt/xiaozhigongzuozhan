## 三、改了什么

### 3.1 新增 `eslint-budget.json`（OHIF 式具名预算，入库）

以 OHIF 的 `.react-compiler-lint-budget.json`（`{ errors: 96, warnings: 94 }`）为范式，但**多了两个约束**：

- **按规则分档**（不是只有一个总数）；
- **规则 = 只许下降**：要上调必须先在当轮轮报里写明理由（写进文件的 `_note` 里，作为契约）。

```json
{ "capturedAt": "2026-10-14", "round": "R44",
  "totals": { "errors": 119, "warnings": 13 },
  "errorsByRule": { "react-hooks/set-state-in-effect": 73, "react-hooks/preserve-manual-memoization": 25,
                    "react-hooks/immutability": 10, "react-refresh/only-export-components": 7, "react-hooks/refs": 4 },
  "warningsByRule": { "react-hooks/exhaustive-deps": 13 } }
```

> OHIF 还有一个 `.react-compiler-budget.json`（以**文件/函数为粒度**列出被豁免的编译器拒绝项）。本仓未引入编译器，该文件**不适用**，未照抄。

### 3.2 新增 `scripts/health/verify-eslint-budget.mjs`（`pnpm verify:eslint-budget`）

三件事，缺一不可：

1. 跑 **与门禁完全相同口径**的 `eslint . -f json`（仓库根、不加参数），按规则汇总；
2. **逐规则**对照预算 —— **预算里没有的规则默认上限 0**（所以任何"新规则"或"僵尸 disable"都会立刻暴露，见 §五）；
3. **强制三处同源**：`eslint-budget.json totals.errors` ＝ 账本 `eslintBaseline` ＝ 账本 `gatesBaseline.eslint`。任一不同源即 `exit 1`。

> 第 3 条正是本轮能"挖出"旧账本的原因：预算写 119、账本还写 151 → 脚本直接判失败，逼着把状态文件一并回写。**口径分裂自此是机检项，不是纪律项。**

5. 顺带修正 R43 轮报（及 `docs/20 §9.3`）的一处错误陈述：其中写「`eslint` 只覆盖 `**/*.{ts,tsx}`」——**不准确**。实测 `npx eslint .` 的**分母是 780 个文件**，扩展名分布 `.ts 477 / .tsx 227 / .js 45 / .mjs 27 / .cjs 4`；`scripts/health/*.mjs`、`docs/evolution/_r44_eslint_snapshot.cjs`，甚至 `pocketbase/pb_hooks/*.pb.js` 都出现在 eslint 报告里。准确的说法是：**`eslint.config.js` 的规则块只对 `**/*.{ts,tsx}` 生效**，非 ts 文件会被解析但不套规则，因此不贡献 error。所以 R43「四门数字持平」的推理仍然成立，但「不在任何门禁分母内」的说法是错的；而且这意味着**新增 `.mjs` / `.cjs` 脚本会进入分母**，写脚本时要顺手自检。已写入账本 notes。
