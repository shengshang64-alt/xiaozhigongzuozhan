## 问题 → 根因 → 修法 → 验证

**问题**：资质台账右上角「导出硬拦截」开关，在**从没点过它的人**（新装/清缓存/换浏览器）那里显示「关」，但导出投标文件时会被红字阻断：「已阻断导出：N 项证书已过期或 30 天内到期」。提示让用户「去关闭硬拦截」，他点一下开关只会把 `"1"` 写进去（仍在拦），看起来像开关坏了。

**根因**：同一个键两处各写一套判定，默认值相反——

- `src/pages/QualCerts/useQualCerts.ts:57`：`getItem(...) === "1"` → 键缺失 = **关**
- `src/pages/BidWorkspace/useBidWorkspace.ts:9426`：`getItem(...) !== "0"` → 键缺失 = **拦**

P0-9（2026-10-24）只把闸门改成「默认硬拦截」，台账页那半没跟着改；而按钮提示写着「开启后：…将直接阻断导出」，等于在承诺「现在不拦」。

**修法**：

- 新增 `src/lib/qualHardBlock.ts` 作唯一真源：`readQualHardBlock()`（键缺失 → 拦；`"0"` → 放行；其它任何值含空串/`"true"` → 一律按拦；storage 不可用 → 放行，与闸门原 catch 分支同口径）、`writeQualHardBlock(on)`（开 `"1"` / 关 `"0"`，不删键）。
- `useQualCerts.ts` 改调这两个函数（+6/−5 行），删掉本地 `=== "1"`。
- 新增 `src/lib/qualHardBlock.test.ts` 10 例，含**跨文件哨兵**：台账页不许退回 `=== "1"`；导出闸门必须仍是「只有 `"0"` 才放行」（谁改口径这里立刻红）。

**验证**：

- 改动前（浏览器实测）：`key=null`，按钮 `text="导出硬拦截：关" aria-pressed=false`，同一时刻 `uiReads(=== "1")=false` / `gateReads(!== "0")=true`。
- 真实数据：`/api/qual_certs/summary` → total 34，`{expired:1, critical:3, warning:0, ok:5, unknown:25}` —— 4 条会被拦，缺陷当场可复现（ISO20000 过期 93 天 / ITSS 剩 11 天 / 软件企业证书剩 13 天 / 高新企业剩 24 天）。
- 改动后：键缺失 → 按钮「开」+`aria-pressed=true`+gate=true（三处一致）；点一次 → `key="0"`、按钮「关」、gate=false；再点 → `"1"`；F5 后保持；控制台 0 error。
- 反证（删实现即变红）：`useQualCerts` 改回 `=== "1"` → `1 failed | 9 passed`；还原 → `10 passed`，diff 只剩预期 +6/−5。
