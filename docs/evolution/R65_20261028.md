## 一、问题（先取证，再动手）

情报的 `content_snippet`（内容片段）字段，实际抓到的是**源站列表页的骨架**。两种形态：

**形态 A（导航串 + 日期 + 真正文）**

```
更多... 更多... 更多... 2026-10-26 近日，由清华大学智能产业研究院（AIR）孵化的AI医疗企业…
```

**形态 B（整段是同站其他文章的标题 + 日期）**

```
甘肃省进一步健全城市社区卫生服务体系提升服务能力的十项措施 2026-10-27 2026-10-26
江苏省印发《推进江苏省"人工智能+医疗健康"发展实施方案》 2026-10-23
```

这两个形态被**当成摘要**显示在两个地方：

1. 首页「情报摘要」卡片（`useHome.ts:205` → `displayizeIntel`，认不出「更多…」也认不出「标题+日期」列表）
2. 情报中心右侧详情面板的「内容片段」（`IntelDetailPanel.tsx:180` → **完全原样渲染 `{item.content_snippet}`**）

用户在「浙江发布会：安诊儿已接入2000+医疗机构」这条标题下面，读到的是甘肃、江苏两条完全不相干的政策标题。


## 二、根因

不是「没人清洗」，是**清洗判据的粒度不对**：

- `displayizeIntel` 的行级判据认的是「导航词 / URL / 花括号 / 纯日期行」，
  而列表残片是「**标题 + 日期 + 标题 + 日期**」——每个 token 都是正常中文，没有一条规则命中。
- 详情面板连 `displayizeIntel` 都没走，是裸渲染（R64 只改了同面板的 `summary`，没碰 `content_snippet`）。

## 三、修法（只动展示层，不动数据、不动入库、不动 pb_hooks）

新增纯函数 `cleanIntelSnippet(raw, { title, max })`（`src/pages/IntelCenter/intelBodyClean.ts`）：

1. `displayizeIntel(raw, 600)` —— 复用既有深度清洗（HTML/CSS 残片、URL、JSON 行）
2. `stripMoreTokens()` —— 剥孤立的「更多…」「多…」「…」token（要求前后是空白边界，句中「查看更多报告」不误伤）
3. 剥**行首**裸日期（列表页每条前面的时间戳；正文里的日期不动）
4. 若出现 ≥2 个日期戳 → 判定为列表残片 → 按日期切段，只留最长一段，且必须同时满足：
   - 长度 ≥ 40 字（标题一般 ≤40 字）
   - 含句读（`，` / `。`）—— 标题型无句读不算正文
   - **标题亲和度**：与标题的 3-gram 命中 ≥1 或 2-gram 命中 ≥2（实测本文正文命中 42~66，邻篇正文命中 0）
5. 任一条件不满足 → 返回空串，由调用方显示兜底文案

接线两处：

| 文件 | 改动 |
|---|---|
| `src/pages/Home/useHome.ts:206` | `displayizeIntel(row.content_snippet, 120)` → `cleanIntelSnippet(..., { title: row.title, max: 120 })` |
| `src/components/intel-center/IntelDetailPanel.tsx:56,179-186` | 新增 `snippetText`，替换裸渲染 `{item.content_snippet}`；空时显示「该条抓取自栏目列表页，片段是其他条目的标题列表，与本文无关，已隐藏；请点「查看原文」阅读正文。」 |

**没动**：`summary` 字段的清洗（R64 口径保留，实测 66 条 summary 里 0 条含「更多…」）、`cleanIntelBody` 入库路径、
`pb_hooks/intel_center.pb.js`、`useIntelCenter.ts`（该文件此刻有并发执行者的在途改动，本轮一个字节未碰）。
