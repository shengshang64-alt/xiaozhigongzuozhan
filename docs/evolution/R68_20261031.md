# R68 · 开标倒计时每天 00:00–08:00 多算一天：纯日期串被按 UTC 解析（当地 08:00），补录条还把原始时间串直出到界面

- **轮次**：R68（2026-10-31）
- **主题**：标书工作台的「距开标 N 天」在每天 00:00–08:00 比真实多 1 天（开标当天凌晨显示「距开标 1 天」而非「今日开标」）；同一组件把 `bid_open_date` 的原始串直出，`<input type="date">` 收到非法值后静默变空
- **定级**：**S2**（用户可见的错误状态，落在「错过投标截止不可挽回」这条线上；且同一屏两个答案）
- **分类**：**A 类（修）** — 日期口径错，属实现缺陷，不是产品取舍
- **四门**：tsc 0 error ✓｜build exit 0（7.63s）✓｜vitest 376 files / 4400 passed / 2 skipped ✓｜eslint 116 error / 11 warning（= 基线，零新增）✓

## 1 · 问题

2026-10-31 01:00（当地）浏览器实测，同一个项目（`ebxc598wu8bcvpd`，`bid_open_date = "2026-12-01 00:00:00.000Z"`）在三个位置给出三个说法：

| 位置 | 文案 |
|---|---|
| 首页「投标节点 · 未来 60 天」卡 | **剩 31 天** |
| `/bid-workspace` 顶部流水线徽标 | **距开标截止 32 天** |
| 同页「开标时间」补录条 | **距开标 32 天**，并显示 `开标时间：2026-12-01 00:00:00.000Z` |

补充实测：

- 点补录条的「修改」后，`<input type="date" aria-label="开标时间">` 的 `value` 为 **空**（HTML 属性里写着 `2026-12-01 00:00:00.000Z`，浏览器拒绝非法值并丢弃）→ 用户会以为日期没存上；「保存」按钮 disabled（`draft === saved`），想保存必须先重选一次日期。
- 纯函数层面（注入固定时钟，基准日 2026-10-31）：

```
日期                      00:30        07:59        08:00        12:00        23:00
2026-10-31           距开标 1 天   距开标 1 天   今日开标     今日开标     今日开标      ← 开标当天凌晨说"还有 1 天"
2026-11-01           距开标 2 天   距开标 2 天   距开标 1 天   距开标 1 天   距开标 1 天
2026-12-01           距开标 32 天  距开标 32 天  距开标 31 天  距开标 31 天  距开标 31 天  ← 每天早上 8 点跳一天
```

也就是说：**倒计时不是零点跳，是早上 8 点跳**；每天 00:00–08:00 那一段，所有项目都多显示 1 天。

- 真实数据面：PB 直连 28 条投标项目 / 可见 19 条 / 有开标时间 3 条，**3 条全部是 PocketBase 日期时间串**（`YYYY-MM-DD HH:mm:ss.SSSZ`），即 3/3 都会直出原始串。

## 2 · 根因

`bid_open_date` 的语义是**日历日**（开标那一天），但代码按**时间戳**在算，且解析口径分散在四处：

| 消费者 | 解析 | 问题 |
|---|---|---|
| `BidOpenDateBar.tsx`（补录条） | `bidOpenDateStatus` → `Date.parse(iso)` + `Math.ceil` | date-only 串被当成 **UTC 零点** = 当地 08:00 → 每天 00:00–08:00 多算 1 天；同时把原始串直接渲染进文案与 date 输入 |
| `PipelineStepper.tsx`（流水线徽标） | `bidTypes.daysUntil` → `new Date(dateStr)` + `Math.ceil` | 同一 UTC 口径；且 `daysLeft <= 0` 一律渲染「已过期 N 天」→ 改成日历日口径后开标当天会变成「已过期 0 天」，标签必须一起改 |
| `BidProjectList.tsx`（列表 chip） | `bidTypes.daysUntil` | 同上（**本轮未改**，见 §5） |
| `BidNodesCard.tsx` / `bidNodesLogic.ts`（首页卡） | R67 已改本地零点 | 正确 |

`src/lib/dateStamp.ts` 的注释里其实已经记过同一类事故（`toISOString()` 在 UTC+8 的 00:00–08:00 会写出昨天的日期）——本轮是它的第二次复现，只是换了字段。

## 3 · 修法

**新增 `src/lib/bidOpenDay.ts` 作唯一真源**（纯函数，零依赖，不碰 React / 后端）：

| 导出 | 作用 |
|---|---|
| `bidOpenDayMs(raw)` | 取前 10 位（年月日）按**本地零点**重建；月/日越界做回读校验后判 NaN。date-only 与 PB 日期时间串同口径 |
| `bidOpenDateDay(raw)` | 展示用 `YYYY-MM-DD`（无法识别 → 空串） |
| `daysUntilLocalDay(raw, nowMs)` | **本地日历日**差值（今天 = 0，昨天 = -1），`nowMs` 可注入 |

接线（每处都是最小改动）：

- `bidOpenDate.ts`：`bidOpenDateStatus` 改用 `daysUntilLocalDay`；`normalizeBidOpenDateInput` 的合法性判断改用 `bidOpenDayMs`（不再是 `Date.parse`）。
- `BidOpenDateBar.tsx`：拆 `savedRaw` / `saved`——`saved = bidOpenDateDay(savedRaw)` 供展示、date 输入、脏值比较；「尚未登记」提示改判 `!savedRaw`（库里没值），不再用「能否解析」代替。
- `PipelineStepper.tsx`：改用 `bidOpenDateStatus`，开标当天显「今日开标」；`daysLeft < 0` 才显「已过期 N 天」。
- `bidNodesLogic.ts`：R67 那份 `bidOpenDayMs` 搬进 lib，保留同名 re-export（首页与既有测试零改动）。
- `bidNodesWiring.test.ts`：哨兵跟着解析器改读 `src/lib/bidOpenDay.ts`，并新增「首页模块不许再持有实现」的反向断言。
