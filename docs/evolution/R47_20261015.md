## 二、第 1 问：按环节自动选模型（B19）

### 2.1 为什么原来不行（改前实测）

- 全流程只有一个顶部手选模型；**模型画像里的 `tags` / `specialty` 只用于 UI 徽标展示，完全不参与路由**。
- 解析报告 / 合规矩阵 / 质疑函 / 投诉书**四个子面板把 `modelRef` 硬编码成 `null`**（= 平台内置）。
  本地部署下平台内置通道必然 412 → **用户明明选了个人模型，这些面板却静默失效**。
  取证：`docs/evolution/_r47_model_route_verify.mjs` 逐条断言四个面板不再有 `modelRef: null`。

### 2.2 选型口径（纯函数，全部可解释、可单测）

| 顺序 | 规则 | 说明 |
|---|---|---|
| 0 | 硬门槛①：非文本模态排除 | 向量 / 作图 / 视频 / 语音不进候选，复用 R88 `isTextGenerationModel` 单一真源 |
| 1 | 硬门槛②：长期不可用档案排除 | 404 下线 / 上游停用 / Key 失效（R296 口径）直接排除，改选次优 |
| 2 | 标签匹配加权 | 环节偏好标签按顺序降权给分（`8 - i`，下限 1）；词表复用 `modelProfiles.ts`，**不另造一套词** |
| 3 | 人工标注加成 12 分 | 仅当用户标注与本环节偏好标签**有交集**才加分（防止「给视觉模型标了看图」污染正文环节） |
| 4 | 会话内冷却降权 6 分 | **只降权、不排除**（R233 口径：这一路刚失败，仍会如实先试） |
| 5 | 稳定兜底 | 同分「个人配置」优先于平台内置，再同分按候选原序 → 结果确定可复现 |

六环节 `ModelRole`：`longform` 正文撰写 / `outline` 大纲规划 / `extract` 解析抽取 /
`judge` 判定审查 / `vision` 图表审阅 / `chat` 中文文书。

**收口函数只有一个**：`resolveRoleModelRef(role, auto, manualRef, roleMap)` ——
手选具体模型（`auto=false`）时自动路由**不得覆盖**用户选择；自动档下该环节无可用候选时回落到手选 / 默认。

### 2.3 接线

- 默认档哨兵值 `AUTO_MODEL_KEY = "__auto__"`，标签「自动 · 按环节智能选择」；**手选具体模型即整体关闭自动路由**。
- `useBidWorkspace.ts` 内 `llmGenerate` 调用点实测 **54 处**：显式 `role:` **31 处**，其余按 `roleForScope` 兜底
  （未分类兜底 `judge` —— 判定类失败模式是漏判而非超时，宁慢不错）。
- 流水线 7 步 → 环节映射：`extract, extract, longform, judge, judge, judge, extract`。
- UI：模型选择器与工具栏就地提示「本环节挑了谁、凭什么」（`rolePickHint`）。

## 三、第 2 问：商务模板自动识别（B20）

### 3.1 两条既有链路合并（**刻意不新增第三条**）

- **强链路** `src/pages/FormatTool/formatSpec.ts`：任意字体 / pt / twips + R46 文字级抽样兜底 → 页面 / 正文 / 标题原始值。
- **补链路** `src/pages/BidWorkspace/bidDocxFormatExtract.ts`：页眉页脚 / 页码域 / 目录域 / 封面 / 要求行 / 表格 / 编号。
- 字段优先级冲突时以「强链路定样式与页面、补链路补 extras」裁决。

### 3.2 本轮补齐的识别面

1–6 级标题（原仅 1–3 级）、表格样式、页眉页脚、`PAGE` 页码域、目录域、封面页、标题编号规则，
以及模板正文里的「须包含 / 应列明 / 格式要求」式**要求行**抽取。

### 3.3 与招标文件对齐（本地规则，零 AI）

`scanScoreItems()` 抽评分点 + `extractStarParagraphs()` 抽 ★▲ 条款，与模板要求行做
中文 bigram 相似度匹配（阈值 `0.34`），命中数 / 漏项数写进 `alignment` 供界面复核。

### 3.4 落库与消费（**零新 collection、零 PocketBase schema 变更**）

- 落 `format_settings.templateProfile`（既有 json 列）；`normalizeTemplateProfile` 反序列化容错，
  `isMeaningfulTemplateProfile` 守门 —— **空 / 脏画像不覆盖旧画像**，暗标 `sealed` 不被模板覆盖。
- 提示词消费：`bidOutline` **4→5**、`bidChapter` **5→6**、`bidSection` **6→7**；
  **要求行为空时输出与旧版逐字一致**（`promptsSnapshot.test.ts.snap` 只动了 void 那 2 行 → 反向印证该承诺）。
- `FormatSyncDialog.tsx` 展示画像 + 1–6 级标题 + 布局 + 要求条数 + 对齐结论 + notes；
  `DraftMergePanel.tsx` 手动 / 自动套用底稿格式时一并落画像。

### 3.5 实测（3 份真实 docx + 安中医真实招标原文）

- 3 份真实模板全部识别成功，1–6 级标题全覆盖；JSON 落库往返深等价。
- 三份模板**都没有写入字体** → 按 R46 口径**如实提示**并按系统默认套用（不臆造）。
- 与安中医项目真实招标原文（**152,212 字**）对齐：抽出**评分点 31 项 / ★▲ 条款 6 条**。
  其中「本系统产出标书」命中 6 / 15 条模板要求，未覆盖 31 条评分点 → 界面提示人工确认漏项。

## 八、长教训 / 纪律（写死以免再犯）

- **`useMemo` 里出现「本地状态强触发票」**（如 `rolePickTick`：画像 / 会话冷却 / 健康档案变化计数）
  必须显式 `void tick` 消费并保留在依赖数组 —— 否则 `react-hooks/exhaustive-deps` 报
  「unnecessary dependency」，极易被误删成「选型不随状态刷新」的真 bug。
- **模板识别只允许两条链路**：强链路（`formatSpec`）定样式与页面、补链路（`bidDocxFormatExtract`）补 extras；
  禁止再加第三条 docx 解析链路。
- **模板画像落库走既有 `format_settings` json 列**，禁止为它新增 collection / 改 PocketBase schema。
- **提示词快照是「改字即现形」的闸门**：任何提示词改动都要连带处理 `.snap`，反之看 `.snap` 只动了哪几行
  就能反推哪一支提示词真变了（本轮据此确认「模板要求为空时逐字一致」）。
- **「选型落点」这类结论必须跑真实清单**：本轮落点是拿用户真实 `pb_data` 的 82 个模型跑出来的，
  不是拿缺省 fixture 猜的。
