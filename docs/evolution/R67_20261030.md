# R67 · 首页「投标节点」卡恒为空：开标日期解析只认纯日期，库里的日期时间串被静默跳过

- **轮次**：R67（2026-10-30）
- **主题**：`/`（工作台总览）的「投标节点 · 未来 60 天」卡永远显示「未来 60 天没有开标项目」，即使库里存在 32 天后开标的项目
- **定级**：**S2**（用户可见的错误状态，落在「错过投标截止不可挽回」这条线上）
- **分类**：**A 类（修）** — 日期解析口径错，属实现缺陷
- **四门**：tsc 0 error ✓｜build exit 0（15.88s）✓｜vitest 361 files / 4137 passed / 2 skipped ✓｜eslint 116 error / 11 warning（= 基线，零新增）✓

## 1 · 问题

首页「投标节点 · 未来 60 天」卡（`src/components/home/BidNodesCard.tsx`）恒显示：

> 未来 60 天没有开标项目。15 个项目未填开标时间……

而实测（浏览器内对同一批真实数据复算）：

```
19 个可见投标项目 / 其中 3 个有开标时间
现逻辑 upcoming = []                     ← 卡片显示"没有开标项目"
因解析失败被跳过：3 个（全部）
修好后 upcoming = [【UI测试】中医院信息化建设项目, 2026-12-01, 剩 32 天]
```

同一项目在 `/bid-workspace` 的项目列表里是有倒计时的（「距开标 32 天」）——两页对同一件事给出相反答案。

## 2 · 根因

库里 `bid_open_date` 存的是 **PocketBase 日期时间串**：

```
2026-12-01 00:00:00.000Z
```

卡片里内联的解析是「在日期串后拼 `T00:00:00` 再 `new Date()`」，只认 `2026-12-01` 这种纯日期。拼出来的 `2026-12-01 00:00:00.000ZT00:00:00` 是 **Invalid Date**，代码走 `continue`：

```ts
// 改前（BidNodesCard.tsx）
const t = new Date(`${d}T00:00:00`).getTime()
if (Number.isNaN(t)) continue      // ← 静默跳过，不报错、不提示、界面看不出少了一条
```

所以缺陷的形态是「卡片永远空」，而不是「报错」——这也是它能活这么久的原因：**这段逻辑内联在渲染体里，没有任何测试能碰到它**。

另有一套同类解析在标书列表（`bidTypes.daysUntil`，直接 `new Date(串)`），能认日期时间串，于是两边分叉。

## 3 · 修法

新增纯逻辑模块 `src/components/home/bidNodesLogic.ts`：

- `bidOpenDayMs(raw)`：只取前 10 位（年月日）按**本地零点**重建，两种历史格式（`2026-12-01` 与 `2026-12-01 00:00:00.000Z`）同口径；月份/日越界（`2026-13-01`、`2026-02-30`）会被 `Date` 顺延成别的日子，故做回读校验，越界判为无法识别。
- `buildBidNodeLists(rows, todayMs, horizonDays)`：分成「未来 N 天要开标的（按剩余天数升序）」与「未填开标时间待补录的（归档不提醒）」两组；`todayMs` 由调用方注入，便于固定时钟单测。

`BidNodesCard.tsx` 改为调用纯函数（`+8/−22`），展示日期恒为 `YYYY-MM-DD`（不再把库里的时间串打到界面上）；「未来 N 天」常量收进单一真源。

## 6 · 遗留项与新发现

- **B45（low）**：`bidOpenDateStatus`（`src/components/bid-workspace/bidOpenDate.ts`）用 `Date.parse` 解析，纯日期被当作 UTC 零点（= 本地 08:00）。实测开标日 **07:00** 打开标书工作台 → 「距开标 1 天」，**09:00** 才是「今日开标」。只在开标日 00:00–08:00 出现，本轮不扩大范围。
- **B44（medium）**：资质台账「未登记有效期」桶在页面上不可见。`/api/qual_certs/summary` 实测 `{expired:1, critical:3, warning:0, ok:5, unknown:25}`，页面四张卡只展示前三档 + 台账总数 → 看不出 25 条（34 条的 73%）完全不参与到期预警。属展示口径变更，需用户点头。
- **F67-1**：「同一件事两处各写一套」再次复现（R66 是同一个 localStorage 键两套判定）。规律：**从库里读日期再算天数，解析函数只允许一份，且必须同时吃 date-only 与日期时间串**。
- **F67-2**：「解析失败 → `continue`」是最坏的失败方式。以后此类分支要么给可见提示，要么至少让逻辑离开渲染体、可被单测打到。
- **F67-4**：并发在途 **175** 个未提交文件（R66 147 → +28；BidWorkspace 77 + components/bid-workspace 14 + prompts 10 + ProductMapping 17 + lib 12）→ B42/B40/B25 仍不可碰。
- **F67-5**：`docs/evolution/_loop_state.json` 的 `history` 里缺 R66 一条（R66 收尾只写了 `lastRound`），本轮已补记。
