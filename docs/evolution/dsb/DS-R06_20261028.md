## 一句话结论

**产品支持「商机关联方案」，但商机详情里没有一条路能走到方案工作室。**

能力其实全都现成：新建方案向导第 2 步有「关联商机（可选）」下拉，创建成功后会自动 PATCH 商机的
`ref_type/ref_id/ref_name`，商机详情就能显示「关联方案：xxx」并可跳转。**缺的只是从商机出发的那一步。**

本轮补上「去方案工作室新建」入口（与 DS-R05 的标书线并列成一个「基于本商机继续做材料」区），
并顺手撤掉了 DS-R05 留下的重复按钮。

## 问题 → 根因 → 修法 → 验证

### 问题（P1）：商机 → 方案 走不通

**实测复现**（浏览器真实操作）：

1. 进入 `/customer-management?opp=ct99spyp8bxj3wd`
2. 看商机详情面板可点元素

**修复前**：

```
链接: [{"t":"去标书工作台新建", ...}]     ← DS-R05 刚补的，只有标书这一条
按钮: ["编辑","删除","收起","线索","接触","需求确认","方案阶段","投标","中标","失单"]
提到"方案": true                          ← 但只是阶段名「方案阶段」，不是入口
```

### 根因

产品里「商机关联方案」的数据链完整：

| 环节 | 位置 | 状态 |
|---|---|---|
| 新建向导第 2 步「关联商机（可选）」下拉 | `NewSolutionWizard.tsx:274-286` | ✅ 已有 |
| 创建成功后回写商机 `ref_type=solution` | `useSolutionStudio.ts:703-712` | ✅ 已有 |
| 商机详情显示「关联方案：xxx」并跳转 | `OpportunityDetailPanel.tsx:232-240` | ✅ 已有（仅在有 ref_name 时） |
| `?solution=` 深链打开既有方案 | `useSolutionStudio.ts:856` | ✅ 已有 |
| **`?opportunity=` 深链预置新建** | — | ❌ **缺** |
| **商机详情「去方案工作室」入口** | — | ❌ **缺** |

只缺商机侧那一步，与 DS-R05 完全同构。

### 修法（两处）

**① 商机详情加「基于本商机继续做材料」区**（`OpportunityDetailPanel.tsx`）

标书线与方案线并列成两个按钮，都带 `?opportunity=<id>&hospital=<医院名>`：

```tsx
<div className="mt-4 border-t border-border pt-3">
  <div className="flex items-center gap-2">
    <Sparkles className="h-4 w-4 text-primary" />
    <p className="text-xs font-semibold text-muted-foreground">基于本商机继续做材料</p>
  </div>
  <div className="mt-2 flex flex-wrap gap-1.5">
    <Link to={`/solution-studio?opportunity=…&hospital=…`}>去方案工作室新建</Link>
    <Link to={`/bid-workspace?opportunity=…&hospital=…`}>去标书工作台新建</Link>
  </div>
</div>
```

**同时撤掉 DS-R05 留在「关联投标」空态里的那个同名按钮**——否则用户会看到两个一模一样的「去标书工作台新建」。
空态文案改为指向新区块。

**② 方案工作室消费 `?opportunity=`**（`useSolutionStudio.ts`）

```tsx
const oppDeepLinkIdRef = useRef<string | null>(null)
useEffect(() => {
  const oppId = searchParams.get("opportunity")
  if (!oppId || oppDeepLinkIdRef.current === oppId || listLoading) return
  oppDeepLinkIdRef.current = oppId
  const hospital = searchParams.get("hospital") ?? ""
  void Promise.resolve().then(() => {          // 微任务，规避 set-state-in-effect
    openNewWizard()                            // 会先清空表单
    if (hospital) setFormHospital(hospital)    // 故在其后覆盖预置值
    setFormOpportunityId(oppId)
  })
}, [searchParams, listLoading, openNewWizard])
```

**停在向导第 1 步（选方案类型）**：类型是售前自己要判断的事，不该替他选。
医院与商机已预置，选完类型点「下一步」即在第 2 步看到预置值。

## 本轮我误判了一次（必须记下来）

排查中途我三次报「医院名称没有预置上，只有商机预置了」，并准备去改状态更新次序。

**是我测错了。** 我用 `placeholder.includes('XX 市人民医院')` 找医院输入框，但对话框里有**两个**输入框都含这个字符串：

| 输入框 | placeholder |
|---|---|
| 方案名称（第一个） | `选填，默认「医院名 + 方案类型」，如 XX 市人民医院信息化规划方案` |
| **医院名称（第二个）** | `如：XX 市人民医院` |

我的 `find()` 取到了**第一个（方案名称）**，它的值当然是空的。

改成 `placeholder === '如：XX 市人民医院'` 精确匹配后：

```
医院名称输入框（ph 完全等于「如：XX 市人民医院」）= "厦门市杏林医院"
商机下拉 = "ct99spyp8bxj3wd"
```

**医院其实一直是预置成功的。** 我如果不去精确核对就动手改代码，会为一个不存在的缺陷改坏已经正确的逻辑。

这是本轮第三次踩同类的坑（DS-R03 grep 判页面状态、DS-R05 includes 判面板存在、本轮 includes 取错字段）——
**规律很清楚：用子串匹配定位 UI 元素，一定会命中不该命中的那个。必须用精确等值或稳定 DOM 锚点。**
