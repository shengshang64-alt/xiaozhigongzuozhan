## 一句话结论

**商机详情页告诉用户「去标书工作台关联本商机」，但那一栏里没有任何可点的地方。**

用户在客户的商机里看到一句静态说明，想往下一步走，只能自己切到标书工作台、从 160 个客户/33 个项目里重新找回这个商机。
本轮在空态补了「去标书工作台新建」入口，带 `?opportunity=<id>&hospital=<客户名>`，
点进去新建对话框已预置好医院与商机，创建即落 `opportunity_id`，**回流立刻可见**。

### 问题（P1）：商机「关联投标」空态是死路

**实测复现步骤**（浏览器真实操作）：

1. 进入 `/customer-management?opp=ct99spyp8bxj3wd`（唯一一条商机）
2. 看右侧商机详情面板最下方的「关联投标」区

**修复前实测文案**：

```
关联投标
在标书工作中关联本商机后，投标结果会自动同步到这里

面板内可点元素：["编辑","删除","收起","线索","接触","需求确认","方案阶段","投标","中标","失单"]
                                                              ↑ 全是阶段推进，没有一条通向标书工作台
```

### 根因

`src/components/customer-management/OpportunityDetailPanel.tsx:256-259`（修复前）：

```tsx
{linkedBids.length === 0 ? (
  <p className="mt-2 ... text-xs text-muted-foreground">
    在标书工作中关联本商机后，投标结果会自动同步到这里
  </p>
) : ( … 有数据时的 Link 列表 … )}
```

**空态只渲染了一段文字 `<p>`，没有任何交互元素。** 有数据时那一支才有 `<Link to={/bid-workspace?project=...}>`。

而反向能力其实全都现成：

| 能力 | 位置 | 状态 |
|---|---|---|
| 标书工作台选商机关联（写 `opportunity_id`） | `useBidWorkspace.ts:9792 linkOpportunity` | ✅ 已有 |
| 新建对话框里的商机下拉 | `useBidWorkspace.ts:1952 formOpportunityId` | ✅ 已有 |
| 创建时落 `opportunity_id` | `useBidWorkspace.ts:1996` | ✅ 已有 |
| 结果回流商机（中标/失单同步） | `useBidWorkspace.ts:9822` 回流三步 | ✅ 已有 |
| `?project=` 深链打开既有项目 | `useBidWorkspace.ts:3580` | ✅ 已有 |
| **`?opportunity=` 深链预置新建** | — | ❌ **缺** |

缺口只有一处：**从商机侧出发的那一步没有入口，也没有对应深链参数**。

### 修法（两处，都很小）

**① 商机详情空态加入口** — `OpportunityDetailPanel.tsx`

```tsx
{linkedBids.length === 0 ? (
  <div className="mt-2 rounded-md border border-dashed border-border py-3 text-center">
    <p className="text-xs text-muted-foreground">在标书工作中关联本商机后，投标结果会自动同步到这里</p>
    <Link to={`/bid-workspace?opportunity=${encodeURIComponent(opportunity.id)}&hospital=${encodeURIComponent(
      customer?.hospital_name ?? opportunity.customer_name ?? "")}`} …>
      <FileCheck2 /> 去标书工作台新建 <ExternalLink />
    </Link>
  </div>
) : ( … )}
```

**② 标书工作台消费 `?opportunity=`** — `useBidWorkspace.ts`

```tsx
const deepLinkOppIdRef = useRef<string | null>(null)
useEffect(() => {
  const oppId = searchParams.get("opportunity")
  if (!oppId || deepLinkOppIdRef.current === oppId) return
  deepLinkOppIdRef.current = oppId
  const hospital = searchParams.get("hospital") ?? ""
  void Promise.resolve().then(() => {          // 微任务，规避 set-state-in-effect
    setMainView("projects")
    openNewDialog()                            // 会先清空表单
    if (hospital) setFormHospital(hospital)    // 故在其后覆盖预置值
    setFormOpportunityId(oppId)
  })
}, [searchParams, openNewDialog])
```

## 本轮我自己纠错了一次（必须记下来）

排查中途我一度判定「点看板卡片会跳回客户列表，是 bug」。
**这是我的误判**：客户管理本就是「列表 + 右侧详情」并排，点卡片后 `setView("list")` 是正确的设计意图，
详情面板正常打开了。我用 `t.includes('商机详情')` 这种宽正则判断面板是否存在，
命中的其实是别处的「跟进记录」文案，才得出「没打开」的错误结论。

**改判方法**：换成稳定 DOM 锚点 `[aria-label="收起商机详情"]`，实测点击后计数 = 1，
深链也是 1 —— 说明两个入口都正常工作。撤回该误判。

（这是 DS-R03 那次「grep 判页面状态」错误的同类复发：**判断 UI 状态必须用稳定锚点，不能用文案子串。**）

## 下一轮建议

1. **DSB10（新）：商机 → 方案工作室 也是同样断点**。`OpportunityDetailPanel.tsx:79` 有
   `const refRoute = opportunity.ref_type === "solution" ? "/solution-studio" : "/bid-workspace"`，

   本次用了医院名而非客户名（因为标书项目的 `hospital` 字段存的是医院名）。
   若存在客户档案 `hospital_name` 与商机 `customer_name` 不一致的历史数据，预置值会以客户档案为准——
   需要核对真实库里两者差异率。
