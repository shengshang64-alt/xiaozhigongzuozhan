## 问题 → 根因 → 修法 → 验证

### 问题

质量体检把 8 个技术章全部判为不达标（标题深度 2~3 级 < 判据要求的 4 级），
会让用户去「改」本来合格的内容。

### 根因

判据 `headingDepthOf` 的正则只认**纯数字编号**：

```ts
const HEADING_LINE_RE = /^(\d+(?:\.\d+)+)\s*[^\d.\s]/   // 只认 1.2 / 12.9.8
```

而真实正文是**标准四级中文公文结构**：

```
11.1 项目理解与目标承接设计          ← 数字编号（判据认，depth=2）
  （一）现状痛点与核心需求研判        ← 中文括号（判据不认）
    （1）系统替换与业务连续性并存。…   ← 数字括号（判据不认）
      ① …                          ← 圈号（判据不认）
```

4 级结构被测量成 2 级 → 8 章全判 NG。

### 修法（两次迭代，第一次我修错了）

**第一版（错）**：加上中文层级识别，同时配守卫「带句末标点 / 超 40 字不算标题」。
→ 实测仍 0/8，深度掉回 3。因为真实语料里「（1）系统替换与业务连续性并存**。**本项目要求…」
是**标题与正文写在同一行**，既带句号又长，被误杀。

**第二版（对）**：改为看「序号后的内容形态」判断是「标题」还是「条目」：

| 序号后形态 | 判定 |
|---|---|
| 首个句号后仍有实质内容 | 标题+正文合写 → 认作标题 |
| 无句末标点（短标题） | 认作标题 |
| 长度 >30 且含逗号顿号 | 标题+正文合写 → 认作标题 |
| 单句结束（如「（1）支持换卡。」） | 条目行 → 不算标题 |

层级映射：数字编号按段数；`（一）`=3、`（1）`=4、`①`=5（以数字 2 级为基线做偏移）。
