## 问题 → 根因 → 修法 → 验证

### 问题：我前三轮用 grep 判「四态覆盖」，结论全是错的

DS-R01/R02 两轮我都用 `Select-String 匹配关键词` 判断页面有没有空态/错误态。
本轮按这个结果排序时，得到「11 个页面缺空态缺错误态」的结论。

**但真实浏览器探活推翻了这个结论：**

| 页面 | grep 判 | 真实情况 |
|---|---|---|
| `/`（工作台总览） | 空态=0 ❌ | 实际有「暂无」空态 ✅ |
| `/intel-center` | hasErr=true ❌ | 实际是「14 个源抓取失败」**正常业务提示**，不是系统错误 ✅ |
| `/product-mapping` | 空态=0 ❌ | 实际有引导态「选择来源后此处将展示…」 ✅ |
| `/materials` | 目录不存在 ❌ | 实际路径是 `MaterialLibrary/`，页面正常显示 3 个素材 ✅ |

### 根因

1. **grep 只看源码字符串，看不到渲染结果**。`hasEmpty` 正则里 `暂无` 匹配不到，是因为组件用了别的措辞或条件渲染。
2. **把业务文案当系统错误**。「14 个源抓取失败」是情报采集的尽力而为状态，产品如实显示并提供「点击处理」，这是**正确行为**，我却把它判成 `hasErr`。
3. **目录名猜错**。我用 `src\pages\Materials` 找素材库，实际是 `src\pages\MaterialLibrary`（由 `routeRegistry.ts:74` 确认）。

### 修法：改用系统级探针

不再匹配任何业务文案，只捕获**真正的技术故障信号**：

```
window.addEventListener('error')                控制台异常
window.addEventListener('unhandledrejection')    未捕获的 Promise 拒绝
window.fetch 包装                                非 2xx 响应的网络请求
document.body.innerText.length                   白屏判定（< 100 字符）
```
