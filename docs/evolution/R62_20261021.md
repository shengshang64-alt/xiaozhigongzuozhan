## 一、本轮做什么（一句话）

R46 只修了**投标文件**这条导出路径（`bidFiles.ts` 逐 run 写 font），B21 待办里明确写着「ppt/方案/报告等其余导出路径需同口径排查（凡导出可见文字的路径都要带字体）」。本轮把其余 6 条 docx 导出路径补齐：新建 `src/lib/exportFont.ts` 单一真源（`DEFAULT_RUN_FONT` 标题黑体/正文仿宋 + `DOCX_DEFAULT_STYLES` 整篇 docDefaults），5 个「整篇一个默认正文」的导出 Document 挂上 docDefaults，方案封面/目录逐 run 写 font；并加源码守卫 + 一条「拆开真 .docx 看 styles.xml」的产物级验证。

**为什么不是 P1 的 B32 剩余簇**：R61 轮报 §六明确把「章节生成/体检评标成功路径」留给后续专做，理由是它们依赖 LLM、需 mock 网关才能行为化（`runGenerateChapter` 单次生成链上有 5+ 个 LLM 调用点、各自 JSON 契约不同，`generateChapterContent` 还要过小节串行/断点续跑/预算治理/一致性审计，mock 成本与脆弱性都高）。本轮改做一条**非 LLM、可直接改善交付物质量**的 B21 收尾，理由写在 §九。

## 二、问题 → 根因 → 修法 → 验证

### 问题 1：6 条导出路径的 TextRun 不写 font → 导出的 Word 没有 `<w:rFonts>`，Word 落到主题默认字体

`docx` 库的 `TextRun` 不显式写 `font` 时，产出的 .docx 里不会有任何 `<w:rFonts>`（R46 实测根因），Word 会落到主题默认字体（本机常是中文等线 / 西文 Calibri）。R46 只修了投标文件，其余 6 条路径仍裸奔：
`toAnnotatedDocx.ts`（体检报告）、`defenseHandbook.ts`（讲标手册）、`quoteExports.ts`（报价 Word）、`deckExports.ts`（讲稿 Word）、`ChatStream.tsx`（售前周报）、`exportTemplate.ts`（方案封面/目录）。

**根因**：字体常量当初只定义在 `bidFiles.ts` 模块内（`const DEFAULT_RUN_FONT`），别的导出文件各自构造 TextRun 时没人想到要去抄一份，也没有任何守卫会红。

**修法**：新建 `src/lib/exportFont.ts` 作为单一真源，导出 `DEFAULT_RUN_FONT`（标题黑体 SimHei/黑体、正文仿宋 FangSong/仿宋）与 `DOCX_DEFAULT_STYLES`（`styles.default.document.run.font` → docx 落到 `w:rPrDefault/w:rFonts`）。5 个整篇导出 Document 挂 `styles: DOCX_DEFAULT_STYLES`（一处改动覆盖所有 run，含 `new Paragraph({ text })` 简写与字符串形式 `new TextRun("…")`）；方案封面/目录（无整篇 Document 在该文件）逐 run 写 `font`（标题黑体 / 其余仿宋）。`bidFiles.ts` 本地常量删除、改 import。

**验证**：四门全绿（§四）；产物级验证（§五）拆开真 docx 的 `word/styles.xml`，确认 `w:docDefaults` + `w:rFonts` + `仿宋` 都在。

### 问题 2：没有守卫，改天又会有人加一条「裸奔」导出

字体这东西加不加都能跑，只有「拆开 docx 看」才会发现少了 `<w:rFonts>`——纯粹靠人肉记不住。

**根因**：R46 之后没有任何「无字体 run 计数」自检（B21 待办里就点名要这个）。

**修法**：新增 `src/lib/exportFont.test.ts` 源码守卫（4 例）：
- ① `DEFAULT_RUN_FONT` 只定义在 `exportFont.ts`（其余导出文件不得再本地重定义）；
- ② 每个 docDefaults 文件里 `new Document(` 数量 === `styles: DOCX_DEFAULT_STYLES` 数量（防止以后新增导出裸奔）；
- ③ 方案封面/目录里 `new TextRun(` 数量 === `font:` 数量（每个 run 都要带字体）；
- ④ 投标文件导出用 import 而非本地 const。
另在 `toAnnotatedDocx.test.ts` 补一条**产物级**验证：`unzipSync` 拆真 docx，断言 `word/styles.xml` 含 `w:docDefaults`/`w:rFonts`/`仿宋`。

**验证**：反向验证 A/B 各自「删实现即变红」（§六）。

## 九、为什么本轮不做 B32 剩余簇（轮次口径说明）

R61 的「下一步」表面上是 B32 剩余两簇（章节生成 / 体检评标成功路径），但它们**依赖 LLM、需 mock 网关**，且 `runGenerateChapter`/`generateChapterContent` 是 5+ 个 LLM 调用点、各自 JSON 契约不同的深度编排（小节串行 + 断点续跑 + 预算治理 + 字数精调 + 一致性审计），mock 成本与脆弱性都高，一轮很难「小而实」地收口。B21 是 backlog 里**非 LLM、可直接改善交付物（字体统一）**的已知缺口，本轮做完 docx 侧全部收口。B32 剩余簇仍在 backlog（high），下一轮如要继续可专做「大纲生成成功路径」（比章节生成浅一档：单次 LLM + 一个 JSON 契约 + outlineLevel=1 可跳过层级补齐）。
