## 2 · 修法（S12 静默丢弃）

**原则**：不动 `useBidWorkspace` 的数据流结构（红灯约束），只让保存**如实反馈结果**。

`src/pages/BidWorkspace/useBidWorkspace.ts`：

1. `persistProject` 由返回 `void` 改为**返回 PATCH 响应体**（`Promise<Record<string, unknown> | null>`）。
   - 52 处调用方全部是 `void updateProject(...)`，忽略返回值 → **行为零变化**；
   - 队列清理仍用同一 `tail` 引用比较，语义不变。
2. `updateProject` 透传该返回值（返回类型显式标注，`cur` 为空时返回 `undefined`）。
3. `setSubjectiveConfirmation` 改为消费返回值：

```ts
void updateProject({ subjective_confirmations: next }, { quiet: true })?.then((saved) => {
  if (saved && !("subjective_confirmations" in saved)) {
    toast.error("主观分确认未生效：服务端还没有 subjective_confirmations 列（需重启 PocketBase 执行建列迁移），本次勾选刷新后会丢失")
  }
})
```

判定依据是**响应体里有没有这个字段**——这是 PB「列不存在时静默丢弃」的可观测信号（§1 已实测确认）。
