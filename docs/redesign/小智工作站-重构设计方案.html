01 / CURRENT STATE

现状理解：一个业务深度被界面拖累的系统

系统的业务内核相当扎实——投标 7 阶段流水线、AI 解析报告、隐式硬约束抽取、条款全覆盖、RAG 知识库，这些都是真正解决售前痛点的能力。但界面层仍停留在"把功能摆出来"的阶段，掩盖了系统的专业价值。

它是什么

产品定位

AI 驱动的医疗信息化售前与投标全流程协作平台。把"从一条情报线索，到一份能拿去投标的标书"这条链路，从散落在个人电脑的 Word / Excel / 微信记录，收敛成有数据、有护栏、有闭环的系统。

技术底座

React 19 + TypeScript + Vite，Tailwind + Radix / shadcn 组件，PocketBase 本地后端（SQLite + pb_hooks），AI 能力经统一模型网关接入，导出在浏览器端完成。

值得保留的内核

护栏

投标 7 阶段流水线，把废标风险从"依赖人的记忆"变成"系统的核对清单"，交卷闸门拦导出。

AI

AI 解析报告结构化提取招标要素并逐项标注出处，可人工核对，后续环节以核对后的报告为准。

零成本

隐式硬约束本地抽取（零 AI），"视为无效"类刚性要求自动注入大纲与章节生成。

02 / SCENARIOS

场景与主链路：围绕售前怎么打仗来组织

系统的价值不在单个模块，而在端到端打通的作战链路。重构以三类用户视角、三条主链路为骨架，所有页面都回答"我在链路的哪一步、下一步去哪"。

谁在用，关心什么

主要用户

售前工程师

跟商机、编方案、响应招标。关心：情报别漏、方案出得快、技术参数逐条响应到位。

关键角色

标书专员

生产投标文件、控废标风险。关心：招标解析准、废标项清零、格式合规、交卷有体检。

决策视角

售前负责人

决定投哪个、看整体进展。关心：商机漏斗、项目进度、中标率与失单原因、模型成本。

03 / DESIGN CONCEPT

设计理念：冷静、精密、有掌控感

医疗投标是零容错的法律级交付，界面应传递"尽在掌握"的确定感，而不是花哨的科技装饰。AI 能力退后一步、随叫随到，把舞台让给用户的判断。

一个隐喻：作战指挥室

冷静 Calm

深色导航锚定全局，浅色工作区专注内容；克制的强调色，只在需要判断与行动时出现。

精密 Precise

4px 网格、像素级对齐、tabular 数字、清晰的层级与密度，像仪表盘一样可信。

掌控 In Control

进度、风险、成本、护栏始终可见；长操作可中断，关键动作有确认，结果可追溯。

五条设计原则

1 · 场景优先于功能

导航与首页按作战链路组织，每个页面让用户知道"我在哪、下一步去哪"，而不是面对一堆功能入口。

2 · 一屏闭合一个判断

提高信息密度，相关信息聚合在一屏；用筛选与分区代替无尽滚动，主指标首屏可见。

3 · 护栏显性化

废标风险、条款覆盖率、闸门状态、成本确认都在界面上有位置，让风险藏不住。

4 · AI 是副驾不是主角

AI 能力嵌入工作流自然触发，结果可人工修改；AI 生成态、出处、费用清晰标注。

5 · 空态是行动邀请

空态说明"为什么空、去做什么"并给出一键入口；失败可重试，绝不留无意义空白。

6 · 延续品牌、克制焕新

保留"智"字与青色基因，升级为更沉稳的医疗青；不追逐会过时的视觉潮流。

明确不做（避免 AI 套路化）

不做满屏渐变与玻璃拟态；不做千篇一律的圆角卡片 + 统一灰阴影；不做全大写眉标、"A · B · C"式元信息、按钮后缀箭头；不为装饰而堆砌图标与动效。强调色数量克制，同属一个体系。
04 / INFORMATION ARCHITECTURE

信息架构：按作战阶段重排导航

把原来"按功能属性"的分组，改为"按售前推进顺序"的分组。导航即作战地图，从左到右、从上到下就是项目推进的方向。

导航分组（前后对比）

现状 · 按功能属性分组

  • 概览：工作台
  • 核心工作：方案编制、标书工作、PPT 与报价、格式刷新
  • 资源与知识：情报中心、竞品分析、客户管理、知识库
  • 系统：模型配置、小智助手、团队管理

重构后 · 按作战阶段分组

  • 总览：作战驾驶舱
  • 发现：情报中心
  • 研判：客户管理（档案 · 商机看板）
  • 制胜：方案工作室、PPT 与报价
  • 决胜：标书工作台、格式刷新
  • 沉淀：知识库、竞品分析
  • 支撑：小智助手、模型配置、团队管理

全局框架：固定外壳 + 内容区

① 侧边导航（深色，常驻可折叠）：作战阶段分组 + 模块，当前位置高亮；底部为用户与角色。

② 顶部全局条：面包屑 / 页面标题（左）；全局搜索 ⌘K、AI 副驾唤起、通知、模型快速切换、用户菜单（右）。

③ 内容工作区：列表页用「筛选区 + 列表 + 详情」三栏；作战页用「阶段步骤条 + 主工作面板 + 上下文侧栏」。

④ AI 副驾（全局浮层 / 侧栏）：任何页面可唤起，联动当前页面上下文执行任务。

07 / KEY INTERACTIONS

关键交互：让护栏与 AI 可感知

交互设计的重点是"状态可见、风险可控、操作可达"，尤其针对长任务、成本与废标风险。

长任务：进度 + 可中断

批量生成逐章串行，显示当前章节、进度百分比与预估；提供"停止"，停止后在飞请求不再计费，已生成内容自动保存。

AI 费用：先确认后执行

每轮 AI 调用前弹费用确认（模型、预估 token / 费用），追问沿用上下文；杜绝零弹窗扣费。

交卷闸门：留痕不拦导航、拦导出

parse / outline / compose / check / eval 五闸门状态常驻；未满足可继续浏览，但导出被拦截，强制放行需填备注。

看板：拖拽流转 + 终态确认

商机卡片拖拽换阶段，拖到中标 / 失单需确认并补跟进记录，结果回流驾驶舱复盘。

可达性：弹窗与长表单

弹窗 max-height 94vh 可滚动、底部操作区 sticky；长表单提交按钮始终可见，修复按钮点不到的问题。

反馈：Toast 与空态

操作结果以轻提示反馈（已保存 / 已发布 / 失败可重试）；空态给出一键行动入口而非留白。

建议以静态原型对齐方向，再在不改变业务行为与数据的前提下逐页落地，每步可验证、可回退。
