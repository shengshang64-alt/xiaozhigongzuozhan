## 2.2 大纲生成（单次） `buildBidOutlineMessages`

> bidTypes.ts:3995 | 触发：解析完成后一键生成；level 0-3 控制级数

**调用链：** 触发=解析后点「生成大纲」(leafGoal≤40 单次) ｜ 入口=`runGenerateOutline()` ｜ 网关=`chatViaGateway(page=bid-workspace · max=4096)` ｜ 模型=个人优先→平台兜底

**System 角色行：** `你是一位深耕医疗信息化行业十余年的资深投标顾问，擅长按评分办法组织技术标结构，确保每一分都有对应响应章节。` ＋ truthPreamble ＋ 当前任务行（含 level 对应的 `depthRule`）＋「硬性要求：」＋编号规则集。

**级数硬约束 `depthRule`（逐字）：**
- level 0：`不预设目录级数：由你按招标文件评分办法与章节要求自行决定技术部分合理级数（最多三级），保证评分办法每一档都有章节落点（级数约束只针对技术章，商务骨架章固定为章+一级小节两级）。`
- level 1：`级数硬约束（只按技术章计算）：技术章只有一级（章），技术章 children 一律为空数组，禁止出现二级或三级节点；商务骨架章可保留其一级小节。`
- level 2：`级数硬约束（只按技术章计算）：技术章恰好两级（章—节），每个技术章下必须有节，节节点的 children 一律为空数组，禁止出现三级节点；商务骨架章固定为章+一级小节。`
- level 3：`级数硬约束（只按技术章计算）：技术章恰好三级（章—节—条），每个技术章下必须有节，每节下必须至少有 1 个条级节点，条节点的 children 为空数组；商务骨架章仍只列一级小节、不展开三级。`

**核心硬性要求（逐字，商务/技术分组）：**
```
· 大纲顶层章分「商务部分」与「技术部分」两组：商务章在前、技术章在后，每个顶层章对象必须带 part 字段标明归属（"biz"=商务章、"tech"=技术章），深层节点不带 part；
· 商务部分输出 6-10 个骨架章（part="biz"）：投标函及报价、法定代表人授权、资质与证照证明、财务审计报告、同类项目业绩、商务条款响应/偏离表、售后服务承诺函、中小企业声明等，按【响应文件要求】【资质要求】【商务评分办法】增删，给出【投标保证金】【合同关键条款】时商务部分还须有对应骨架章落点；商务章 children 只列一级小节名，正文由投标人线下填写、不生成正文；
（includeBiz=false 时上述两条替换为：）本次不输出任何商务部分章节（part="biz"），投标函、资质证照、商务偏离表等由投标人线下自行处理，禁止为其安排任何章节；
· 技术部分（part="tech"）为详细响应骨架，必须以评分办法为纲：逐条覆盖下面技术评分的评分点，每个重要评分项都要落到具体章或节标题；
· 承接标注（R31）：每个技术章下的叶子节点（末级节/条）必须在 description 字段中标注其承接的评分编号，格式 [响应:R1] 或 [响应:R1,R3]（多个逗号分隔）；一个叶子只标注其直接相关的 1-3 个编号；商务骨架章不标注；不承接任何评分项的叶子节点可省略 description；
· 响应文件要求须逐条落实（组成、格式、签字盖章与装订要求对应专门章节或节）；
· 技术部分常规骨架参考：项目理解与需求分析、总体建设方案、详细技术方案（按系统分章）、项目实施组织与进度计划、质量保障与测试验收、培训方案、售后服务与运维保障、应急预案；再按本招标文件增删；
· 标题只写名称、不带编号、不以标点结尾；层级命名规范：一级=部分/章，二级=节，三级=条；
· 节/条标题必须用具体响应式命名：主题词+落点词（设计/范围/保障/机制/流程等），形如「设备兼容性设计」「多模态数据处理范围」「知识更新机制」；禁止「概述/说明/介绍/相关内容/其他」式空泛标题；
```

**条件注入规则（逐字）：**
- （17A 招标规定目录时，插到前列）`招标已规定响应目录：大纲章结构必须遵循其顺序与层级，禁止另起炉灶；标题文字可润色补全，规定目录未覆盖的内容可在末尾补充章节，商务骨架章仍置于最前；`
- （leafTarget>0）`规模硬要求（只按技术章计算，商务章叶子不计入）：技术部分叶子节点总数必须落在 {leafLo}-{leafHi} 个区间（目标 {leafTarget} 个），每个叶子节点将承载约 {sectionWords} 字正文，技术章的数量要与该规模匹配；不足时按系统/模块/阶段/保障维度拆章节拆小节补足叶子，超出时合并相近叶子；`
- （有隐式约束）`下面【招标隐式硬约束】共 {N} 条（如页数 / 份数 / 装订 / 格式等刚性要求），任何一条被违反都可能废标，大纲必须保证每条约束都有对应章节落点；`
- （有★条款）`下面【★/▲ 重点条款】为招标文件带标记的实质性响应条款，任何一条未响应都可能直接废标：大纲必须让每条重点条款都有明确章节落点，禁止只靠通用章节笼统带过；`
- （有条款清单）`下面【招标要求条款清单】共 {N} 条，每条条款必须至少对应一个技术章下的大纲叶子节点，对应叶子节点的标题须包含该条款的核心词，禁止遗漏任何条款；商务骨架章不承担条款覆盖，coverage 的落点一律填技术章的叶子标题；`

**输出格式（逐字）：** `{"outline":[{"title":"商务章标题","part":"biz","children":[{"title":"小节标题","children":[]}]},{"title":"技术章标题","part":"tech","children":[{"title":"节标题","children":[{"title":"条标题","children":[],"description":"[响应:R1,R3]"}]}]}],"coverage":[{"clause_id":"c1","node_title":"对应叶子节点标题"}]}`

**User 素材块（stableUser 前置）：** 技术评分办法(编号)/商务评分办法/技术方案与响应要求/资质要求/投标关键节点/投标保证金/合同关键条款/全局事实/隐式硬约束/★条款/招标规定目录/历史范本目录；taskUser 置后：招标要求条款清单。
