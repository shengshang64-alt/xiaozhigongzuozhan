## 2. 建议清单（按 ROI 排序）

### P0-1｜打断"在途改动堵门禁"这个循环　〔半天，收益最高〕

**症状**：门禁红的不是代码，是流程。`.loop/MORNING.md` 中 R37→R40 连续四轮都有"需你拍板：那批未提交改动怎么处置"。此刻工作区 18 改 + 27 未跟踪，其中 4 个文件贡献了全部 5 个 tsc error。

**同类项目怎么做**：Dify / n8n / Open WebUI 的共识是"**门禁只对 HEAD 负责**"——功能做一半就开 draft PR 跑 CI，红的 PR 不合并，主干永远绿。本地 loop 型项目（你的 autoloop）的等价物是：**每轮结束必须落一次提交或一次 stash，不许把红状态传给下一轮**。

**建议**：
1. 先给这批在途改动定性（那 4 个文件的 5 个错误都是分钟级小改，修完即可提交；与本轮无关的改动单独成一个提交）。
2. 给 `scripts/autoloop.mjs` 加硬规则：**轮末 `npx tsc -b` 不为 0 就不许写 `verdict: pass`**。现在"本轮文件 pass"这种自我豁免口径，等于门禁失效。
3. `docs/evolution/_loop_state.json` 增加 `gatesBaseline`：把 HEAD 上既有错误集合固化，门禁只判"本轮是否新增"。这样在途批次不再造成假红，也不会掩盖真红。

**验收**：`npx tsc -b` exit 0；账本 `verdict: pass` 与命令输出一致。

### P0-2｜eslint 门禁口径统一到命令原文　〔1 小时〕

`eslint.config.js` 的 `globalIgnores` 补 `data/`、`.loop/`、`_qa/`、`.probe/`、`.diag/`、`_eval/`；账本里记的口径直接写命令原文。顺带处理 `vite.config.ts` 自身的 4 条（它们会永远压在基线里）。

**验收**：`npx eslint .` 的数字 = 账本数字，差 0。

### P1-1｜schema 从"只活在本机"变成代码 ★ 最大单点风险

**症状**：`pb_migrations/` 空；40 个集合的结构只存在于 `pb_data/data.db`（320 MB、gitignore）；仓库里 tracked 的却是两个空 db。**这份仓库拷到新机器跑不起来** —— CLAUDE.md 那条"不删 `pocketbase/pb_data`"的红线，本质就是因为删了无法重建。

**同类项目怎么做**：PocketBase 生态（含官方 SaaS 模板）的标准做法是 `pb_migrations/*.js` 入库、`pb_data/` 只当运行态；Dify 用 alembic、RAGFlow 用迁移脚本 —— 共同点是"**schema 是代码，数据是数据**"。你的 `--migrationsDir` 参数已经写好了，只是目录是空的。

**建议**：
1. 在**副本**上先验证（红线：不直接对真库操作）：用 PocketBase 的 collections 导出能力，把 40 个集合定义落成 `pb_migrations/<ts>_init_collections.js`。
2. 新增集合一律走迁移文件，不再依赖 dev 模式手建。
3. 移除误提交的空 `data.db` / `auxiliary.db`（文件可留本机）。
4. 在 CLAUDE.md 红线旁加一句：**schema 的唯一真源是 `pb_migrations/`**。

**验收**：空目录起 `start-local.cmd` → 40 个集齐全、能建一条客户记录。

### P1-2｜182 处内联身份校验，值得做一次"能不能共享"的证伪实验　〔半小时实验，可能省 180 处维护面〕

**症状**：`pb_hooks/*.pb.js` 里 `x_rh_user_id` 出现 **182 次**，而 `function zxReqUser` 只有 **1 处**；`require(` **0 次**。`docs/09` 已把"身份头自证 + IDOR"列为 P1 —— **同一段安全关键代码复制 180 遍，任何一处漏改就是一个越权口子**。

**你的注释里给出的原因**：`zx_guard.pb.js` 写着"因 PB Goja prewarm 机制，handler 无法调用文件级 function，实际逻辑已内联"。**这个结论我建议用实验重新证伪**：PocketBase JSVM（v0.23+，你是 **v0.40.4**）支持在 hook 里 `require()` 本地模块。若成立，182 处副本可收敛为 1 个 `pb_hooks/lib/zx_identity.js`。

**同类项目怎么做**：PB 生态的常规做法就是 `pb_hooks/lib/*.js` + 共享；Dify / n8n 后端也都用共享中间件，而不是逐路由复制校验。

**建议**：最小实验 —— 新建 `pb_hooks/lib/identity.js`，挑 1 个 hook 改成 `require`（需重启 PB）→ 跑该路由的鉴权用例。成立就分批收敛（每轮 5~8 个文件 + 回归一起做）；不成立就把"为什么不能共享 + 复现命令"写进 docs，**终结这个被反复讨论的问题**。

**验收**：身份判定只剩 1 处实现，且 IDOR 回归全绿。

### P1-3｜数据模型：身份字段收敛到一套　〔半天〕

23 个 `rh_user_id` / 3 个 `owner_id` / 12 个都没有。建议：**有权属的数据一律 `rh_user_id`；全局共享数据显式加 `visibility = 'global'`**；把 3 个 `owner_id` 迁过去；`zxIsOwner()` 收敛成只认一个字段。

### P1-4｜2617 个测试、0 个组件测试 —— 补一层"UI 回归网"　〔1~2 天，边际收益极高〕

**症状**：无 `jsdom`、无 `@testing-library`；vitest 是 `environment: "node"`。也就是说**全站最贵的交付交互（金额单元格失焦落值、折扣歧义确认、章节生成门禁）没有自动化回归**。你现在只能靠"实机注入真实组件 + Playwright 截图"取证一次（R38/R40 就是这么干的）—— **取完证就散了，下次改动同样裸奔**。

**同类项目怎么做**：Dify / Open WebUI 全用 vitest + jsdom + testing-library 守组件；一次性的 Playwright 取证在成熟项目里会沉淀成 `e2e/` 用例进 CI。

**建议**：
1. 加 `jsdom` + `@testing-library/react` 作为**独立 vitest project**（不动现有 2617 例的 node 环境，零回归风险）。
2. 优先给"会静默算错钱 / 会静默漏条款"的交互补 5~10 例组件回归 —— 第一个就该是 `QuoteEditor` 的 `DiscountCell`（R40 刚修的那个）。
3. （可选，成本更高）把 R38/R40 的 Playwright 注入脚本固化成 `tests/e2e/`，用脚本名代替"截图存 docs"。

**验收**：新 project 全绿；**故意删掉 `DiscountCell` 的 blur 落值分支，测试必须变红**。

### P2-1｜给两个 God Module 做"按可测切面"的拆分　〔长期，但别重写〕

**症状**：`useBidWorkspace.ts` 9009 行、`bidTypes.ts` 7016 行 / 426 导出 / 59 处 import。对照 §1.2 —— **跨页面重复只有 5 个 label 常量**，说明这不是"重复造轮子"，纯粹是**单体化**（整个标书域长在一个文件里）。

**同类项目怎么做**：RAGFlow 的 `rag/` 按能力切（解析/检索/重排分离）、Dify 的 `core/` + `service/` 分层、n8n 把每个 node 做成独立包 —— 共同点是"**按能力边界切，且每层自带测试网**"。

**建议**（分批，不要一次动）：
- `bidTypes.ts`：按域拆成 `bidTypes{Scoring,Quote,Clause,Outline,Format}.ts` + 一个 barrel `bidTypes.ts` 原样 re-export → **59 处 import 一行都不用改**；拆完再逐个域补测试。
- `useBidWorkspace.ts`：按阶段抽子 hook（parse / compose / check / export），跨阶段状态用 `useReducer` 收口，而不是各 `useState`。
- 每轮只拆一个切面，**拆之前先给这个切面补测试**（否则拆完无法验证）。

**验收**：单文件 ≤1500 行；`tsc` + vitest 零回归；import 侧零变更。

### P2-2｜补一层薄数据层：59 处裸 fetch + 240 处 localStorage 是当前最大的架构债

**症状**：`pb.collection(` 全站只有 **1 处**，`fetch(` **59 处**（全在打 pb_hooks 的自定义路由），`localStorage` **240 处**，而生成的 `types.d.ts`（802 KB）基本没被当数据契约用。含义：接口改名靠人肉搜字符串；缓存/失效/竞态各页面自己造（所以才长出 `kbChunkCache` / `kbCorpusSharedCache` / `llmCache` 三套局部缓存）。

**同类项目怎么做**：Dify / Open WebUI 都有 typed client + 统一请求层（错误、重试、去重、取消），组件里不出现裸 fetch；PB 官方也推荐走 SDK（你其实已经装了 `pocketbase` SDK）。

**建议**：新建 `src/lib/api/<domain>.ts`，**只要求新增代码走新层，存量不动**（避免大爆炸式重构）。第一个域建议选 `intel`（最能吃到统一缓存/重试的收益，且正好对上 P2-3）。

### P2-3｜把"情报源 40% 失效"变成首页可见的一个数字　〔低成本高感知〕
