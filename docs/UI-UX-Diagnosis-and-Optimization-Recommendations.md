# 小智工作站 · UI/UX 诊断与优化建议报告

> **版本**: v1.0  
> **时间**: 2026-11-06  
> **作者**: AI 产品经理评审  
> **目标读者**: 项目负责人、开发团队、设计团队

## 一、总体评价

### 1.1 产品定位清晰
- ✅ **核心价值明确**：医疗信息化售前团队的本地工作台，聚焦于"标书/方案/PPT 生产"
- ✅ **功能完整性高**：标书七步流水线（解析→大纲→写作→检查）、方案工作室、PPT 报价等核心流程已基本完备
- ✅ **数据驱动意识强**：情报中心自动抓取招标信息、资质到期预警、投标复盘等功能体现数据化思维

### 1.2 主要问题诊断

#### 【P0】阻断性问题
| # | 问题描述 | 影响模块 | 严重度 |
|---|---------|---------|--------|

| 2 | **导航层级混乱**：左侧菜单 3 组分类 + 顶部标签栏 + 面包屑三套导航体系并存，同一功能在多处出现 | 全站 | P0 |

## 二、详细诊断报告

### 2.1 工作台总览（Home）

#### 现状描述
- 首屏展示：欢迎语 + 20 条情报待确认 + 资质过期提醒
- 中部区域：今日必看、投标节点、进行中事项、未完成待办、已完成待办、商机分布、待办事项、最近商机动态、待跟进商机、胜负复盘、最新动态、情报摘要、工作进行中事项、我的项目跟进清单
- **总高度约 2958px，需要滚动至少 4 次才能看完**

#### 核心问题

**【P0】信息密度爆炸，主次不分**
- **现象**：14 个卡片横向排布，每个卡片都有标题、数据、操作按钮、详细内容，用户在第一屏看不到任何一张完整的卡片
- **影响**：用户不知道"今天首先要做什么"，只能靠记忆或猜测点开某个模块查看
- **对比**：现代 B2B SaaS 的最佳实践是"任务导向型首页"——根据角色/时间/优先级，每次只展示 3-5 个最关键的任务卡

**【P0】视觉动线紊乱**
- **现象**：从左到右的布局期望是"从左看到右"，但这里实际上是上下分块；标题大小（32px/24px/18px）与实际重要性不匹配（"晚上好"最大，"今日必看"次之）
- **影响**：用户视线无法形成有效扫描路径，容易遗漏关键信息

**【P1】数据展示效率低**
- **现象**：
  - "商机阶段分布"图表只有"共 0 条商机"的文字提示，图表本身不可见
  - "待办事项"的输入框与列表混杂在一起，难以区分
  - "最近商机动态"的筛选器（全部/论文/媒体/政策）放在最上方但不生效（当前无数据）
- **影响**：页面元素看似丰富但实际承载信息量为零

**【P1】交互反馈缺失**
- **现象**：
  - 点击"处理情报"→无 loading，直接跳转但无过渡动画
  - 点击"继续标书"→进入标书工作台，但不知道从哪个具体项目开始
  - 点击"新增项目"→弹出对话框，但无默认值填充（如项目名称、客户、期限）
- **影响**：操作的即时性不足，用户需猜测下一步

**【P2】文案风格混乱**
- **现象**：
  - "晚上好"这种 C 端风格的问候语 vs "证书过期直接废标"这种专业术语并存
  - "正在读取投标项目..."与"复盘数据加载中…"两种 loading 文案混用
- **影响**：品牌语调不统一，专业感被削弱

#### 优化建议

**优先级 1：重构首页信息架构（预计投入：3-5 天）**
```
新的首页结构（不超过 1200px 高度）：
┌─────────────────────────────────────────────┐
│ 欢迎语 + 今日关键指标 (3 列)                 │
│ [资质到期预警] [情报待处理] [投标截止倒计时]    │
├─────────────────────────────────────────────┤
│ 优先级最高的 3 个任务卡 (可横向滚动)             │
│ → 继续编写 XXX 标书  → 审核 XXX 资质变更 → 回复 XXX 情报  │
├─────────────────────────────────────────────┤
│ 快速操作区 (4 个高频入口)                     │
│ [+ 新建商机] [+ 导入招标文件] [+ 查询资质] [+ 添加待办]   │
├─────────────────────────────────────────────┤
│ 个人进度看板 (折叠面板)                       │
│ → 进行中事项 (3 项)     → 今日完成 (1 项)      │
└─────────────────────────────────────────────┘
```

**关键改动：**
1. **减少卡片数量**：从 14 个减至 5 个核心模块（关键指标、任务卡、快捷操作、进度、更多）
2. **增加个性化配置**：允许用户拖拽 reorder 卡片位置，按个人习惯定制
3. **引入优先级算法**：基于截止时间、重要性、用户历史操作频率，对任务卡排序
4. **增强 actionable 提示**：每个卡片必须包含一个清晰的"下一步操作"按钮

**优先级 2：视觉层次重构（预计投入：2-3 天）**
- 标题字号规范：
  - H1: 32px (主标题)
  - H2: 24px (区块标题)
  - H3: 18px (子标题)
  - Body: 14px (正文)
  - Caption: 12px (辅助文字)
- 颜色权重：
  - Primary: 深蓝 (#1E3A5F)
  - Secondary: 浅蓝 (#4A90E2)
  - Success: 绿色 (#10B981)
  - Warning: 橙色 (#F59E0B)
  - Danger: 红色 (#EF4444)
  - Info: 蓝色 (#3B82F6)

**优先级 3：交互细节优化（预计投入：1-2 天）**
- 为所有按钮添加 hover/focus/disabled 状态
- 为所有表单输入添加实时验证（长度、格式、必填）
- 为所有异步操作添加 loading 状态（骨架屏优先于 spinner）
- 为所有删除/修改操作添加二次确认 + 撤销机会（Toast 通知带 Undo 按钮）

### 2.2 情报中心（Intel Center）

#### 现状描述
- 四大指标卡：待确认/已抓取总数/本月新增/转报数
- 过滤条件：来源类型（全部/政策/竞品/中标/媒体）、时间范围、关键词
- 列表区：每条情报包含来源、标题、摘要、发布时间、AI 摘要按钮、标签
- 右侧面板：智能标签、相似情报推荐、转报入口

#### 核心问题

**【P1】指标卡信息过载**
- **现象**：四个指标卡都只显示数字，标题不够清晰（"29/40"是什么意思？"980"是什么？）
- **影响**：用户需猜测这些数字的含义，不如直接展示"本周新增 29 条，本月累计 40 条"

**【P1】过滤条件层级混乱**
- **现象**：
  - 上方的过滤器（来源类型、时间、关键词）与下方的扩展过滤器（标签、来源网站、服务区域）重叠
  - "转报情报公开到团队"开关位置不明显（右上角小圆点）
- **影响**：用户想精准查找时，找不到高级筛选入口

**【P0】列表信息密度失衡**
- **现象**：
  - 每条情报占用空间过大（标题 + 摘要 + 来源 + 时间 + AI 按钮 + 标签），一屏最多显示 3-4 条
  - 标题过长且未截断（如"吉安市公立中医医院信息化建设项目变更澄清公告"整行显示）
  - 标签过多（每条约 3-5 个标签），视觉上显得杂乱
- **影响**：用户需频繁翻页才能浏览完所有情报，降低效率

**【P1】AI 功能入口不明确**
- **现象**：
  - "AI 生成摘要"按钮在每个条目中都一样大，但用户不知道它的作用（有些条目已有摘要）
  - 未生成的条目只显示"暂无摘要，进入情报中心用 AI 摘要打标"，缺乏一键触发
- **影响**：AI 功能的价值被稀释，用户不会主动尝试

**【P2】空态设计缺失**
- **现象**：
  - 当无匹配结果时，只显示"暂无符合条件的情报"，无重新搜索建议
  - 当首次访问时，无示例数据引导
- **影响**：新用户不知道如何开始使用

#### 优化建议

**优先级 1：重构指标卡（预计投入：1-2 天）**
```
原设计：[29/40] [980] [40] [0]
新设计：
┌──────────────────┬──────────────────┬──────────────────┬──────────────────┐
│ 本周待确认        │ 本月已抓取总数    │ 本月新增          │ 已转报团队        │
│ [29 条] 🔴         │ [980 条] 📈        │ [40 条] ⬆️        │ [0 条]           │
│ 点击查看详情       │ 同比 +15%         │ 昨日新增 7 条      │ 进入转报中心      │
└──────────────────┴──────────────────┴──────────────────┴──────────────────┘
```

**优先级 2：优化列表卡片（预计投入：2-3 天）**
- **采用紧凑模式/标准模式切换**：用户可按偏好选择单行显示（高密度）或多行显示（易读）
- **标题截断策略**：
  - 单行截断（显示前 60 字符，剩余...）
  - 悬停显示完整标题（Tooltip）
  - 点击进入详情页
- **标签分组显示**：同类标签合并（如"[政策][法规]"→"[政策法规]"）
- **增加批量操作**：勾选多条→批量转报/批量打标签/批量删除

**优先级 3：增强 AI 功能（预计投入：2-3 天）**
- **智能推荐摘要**：根据用户历史操作频率，预测哪些情报最值得 AI 摘要
- **一键批量摘要**：选中多条→批量生成摘要（节省逐个点击）
- **摘要质量评分**：让用户评价摘要是否准确（帮助模型迭代）
- **摘要预览展开**：默认只显示前 50 字，点击展开全文

**优先级 4：改进交互细节（预计投入：1 天）**
- 为所有操作添加 Toast 提示（转报成功/失败、标签已添加等）
- 为列表加载添加骨架屏（比空白更友好）
- 为空状态添加引导文案（"试试调整筛选条件"、"创建第一条情报"）

### 2.3 标书工作台（Bid Workspace）

#### 现状描述
- 投标复盘：3 个投标项目、中标率 0%、中标金额合计 0.00、结果待回溯 3 个
- 投标全流程工作台：七步流水线（解析招标文件→生成大纲→编制投标文件→查重→原标自查→模拟评标→归档导出）
- 项目列表：卡片视图/表格视图切换，搜索框，筛选条件

#### 核心问题

**【P0】七步流水线可视化不足**
- **现象**：
  - PipelineStepper 组件仅用简单的步骤标题表示，无法直观看到每步的进度
  - 某步完成后无法回退修改（除非有 undo 机制）
  - 当前步骤标识不明显（缺 color coding）
- **影响**：用户不知道"我完成了多少%"、"下一步做什么"

**【P0】项目卡片信息冗余**
- **现象**：
  - 每个项目卡片显示：项目名称、编号、截止日期、完成情况（0/11 章完成）
  - 但卡片面积过大（宽度固定 400px），一屏仅能显示 2-3 个
  - 点击"编制中"直接进入编辑器，无中间状态预览
- **影响**：项目管理效率低，尤其是多项目并行时

**【P1】操作后果不明确**
- **现象**：
  - "新建投标项目"无模板选择（公司标准模板/智业投标文件 Word 模板/招标文件全文范本等）
  - "导出 CSV"/"归档"等操作无二次确认
  - 删除项目后无回收站机制
- **影响**：用户担心误操作不敢尝试

**【P1】跨模块联动薄弱**
- **现象**：
  - 标书工作台→素材库→方案工作室之间的跳转需要多次手动操作
  - 客户管理中的商机→标书项目 conversion 不顺畅
  - 情报中心中的招标→标书项目 conversion 需要复制粘贴项目编号
- **影响**：打破信息孤岛的目标尚未实现

**【P2】性能问题**
- **现象**：
  - 加载标书项目列表时，网络请求耗时较长（可能有 N+1 问题）
  - 大文档编辑时内存占用过高（可能是整个文档加载进前端）
- **影响**：用户体验卡顿，尤其对老旧设备不友好

#### 优化建议

**优先级 1：重构流水线可视化（预计投入：3-4 天）**
```
新的 PipelineStepper 设计：
┌─────────────────────────────────────────────────────────────┐
│ [1. 解析] ████ 完成  →  [2. 生成大纲] ████ 进行中 → [3. 编制] ░░░░ 待开始 │
│      ↓                    ↓                              ↓    │
│   3 小时              5 章/11 章                  0 章/11 章    │
└─────────────────────────────────────────────────────────────┘
─────────────────────────────────────────────────────────────┐
│ [4. 查重] ░░░░ → [5. 原标自查] ░░░░ → [6. 模拟评标] ░░░░ → [7. 归档导出] ░░░░   │
└─────────────────────────────────────────────────────────────┘
```

**关键改进：**
- 进度百分比可视化（███░░ 进度条）
- 每一步的状态清晰标识（完成/进行中/待开始/阻塞）
- 点击任意步骤可跳转到对应编辑器
- 支持暂停/恢复（中断后下次继续）

**优先级 2：优化项目卡片（预计投入：2 天）**
- **改为表格视图为主**：卡片视图仅用于移动端或小屏幕
- **表格列自定义**：用户可选择显示哪些字段（项目名/客户/截止日期/进度/状态）
- **批量操作工具栏**：选中多条→批量启动/批量导出/批量归档
- **进度条嵌入**：表格中直接显示进度条（无需点击进入）

**优先级 3：强化跨模块联动（预计投入：3-5 天）**
- **情报考古→标书项目**：
  ```
  情报卡片上添加"转为投标项目"按钮
  ↓
  自动填充项目名称（来自情报标题）
  ↓
  自动关联客户（从情报中提取医院名称）
  ↓
  自动生成初始大纲（基于情报中的招标文件）
  ```
- **客户管理→商机→标书**：
  ```
  客户详情页中添加"新建跟进商机"按钮
  ↓
  商机升级为"投标机会"
  ↓
  自动生成标书项目草案
  ```
- **素材库→标书写作**：
  ```
  在 ComposeStep 编辑器侧边栏嵌入素材库浏览器
  ↓
  拖拽引用素材到正文
  ↓
  自动标注来源（哪份材料/哪个版本）
  ```

**优先级 4：提升性能（预计投入：2-3 天）**
- 虚拟滚动：长列表只渲染可见区域
- 懒加载：非活跃标签页内容延迟加载
- Web Worker：耗时的文本处理（查重/格式刷新）移至后台线程
- CDN 缓存：静态资源加入版本号，利用浏览器缓存

### 2.4 资质台账（Qual Certs）

#### 现状描述
- 统计指标：已过期 1、30 天内到期 3、60 天内到期 0、90 天内到期 25、有待办结 34
- 预警区：4 项资质即将过期，显示证书名称/类别/失效日期/适用范围
- 表格列表：证书名称/类别/证书编号/有效期起迄/适用范围/操作（编辑/删除）

#### 核心问题

**【P1】统计指标语义不清**
- **现象**：
  - "有待办结 34"是什么意思？（有待办理/待审核/待补料的杂项数字）
  - "90 天内到期 25"中，哪些是紧急的？哪些是可以缓的？
- **影响**：用户无法判断优先级，可能忽略真正危险的证书

**【P1】预警区作用有限**
- **现象**：
  - 预警信息只显示标题，不显示具体证书列表（需点击展开）
  - 无一键处理入口（如"批量发送邮件提醒负责人"）
  - 无历史预警记录追溯
- **影响**：预警沦为"数字展示牌"，未能驱动行动

**【P0】表格操作不便**
- **现象**：
  - 编辑/删除图标太小（点击困难）
  - 无批量操作（全选/反选/批量删除/批量延期申请）
  - 有效期字段显示格式不统一（"2026-07-28"vs"2027-10-26"）
- **影响**：日常维护成本高，容易出错

**【P1】缺少导入/同步能力**
- **现象**：
  - 手动录入每张证书（Excel 导入？扫描件 OCR 识别？）
  - 与企业官网/政府公示系统无对接（自动核验证书真伪）
  - 人员证书未与组织架构绑定（人员离职后证书归属问题）
- **影响**：数据源头混乱，更新不及时

**【P2】无投标联动机制**
- **现象**：
  - 标书工作中提到"需要提供 XX 证书"，但未自动关联到资质台账
  - 投标要求解析出资质条款后，未自动比对可用证书
- **影响**：标书编制时仍需人工翻找资质材料

#### 优化建议

**优先级 1：重构统计指标（预计投入：1-2 天）**
```
新设计：
┌──────────────────┬──────────────────┬──────────────────┬──────────────────┐
│ 已过期           │ 30 天内到期        │ 60-90 天到期      │ 正常            │
│ [1 张] 🔴 立即处理 │ [3 张] 🟠 优先处理 │ [25 张] 🟡 关注     │ [105 张] ✅       │
│ [查看详情]        │ [查看详情]        │ [查看详情]        │ [查看详情]        │
└──────────────────┴──────────────────┴──────────────────┴──────────────────┘
```

**优先级 2：增强预警机制（预计投入：2-3 天）**
- **分级预警**：
  - 🔴 红：已过期/7 天内到期 → 邮件 + 短信 + 站内信
  - 🟠 橙：30 天内到期 → 邮件 + 站内信
  - 🟡 黄：90 天内到期 → 站内信
- **预警队列**：
  - 新增"预警处理"列表，显示所有即将过期的证书及处理进度
  - 每个预警可分配给指定负责人（如行政部张三）
  - 支持批量操作（批量延期待办/批量发送邮件）
- **历史记录**：
  - 保存所有预警的产生/处理/关闭记录
  - 支持按时间/证书类型/负责人检索

**优先级 3：优化表格操作（预计投入：2 天）**
- **批量操作**：
  - 全选/反选/按条件筛选后批量操作
  - 批量导入 Excel（模板下载→填写→上传→校验）
  - 批量导出（PDF/Word/Excel）
- **搜索与过滤**：
  - 支持多维度搜索（证书名/编号/有效期/适用范围）
  - 支持组合过滤（类型=体系认证 AND 状态=正常 AND 有效期<6 个月）
- **快捷操作**：
  - 悬浮行显示操作按钮（编辑/查看/下载/延期待办）
  - 右键菜单（批量删除/批量导出/批量发送邮件）

**优先级 4：集成外部数据源（预计投入：3-5 天）**
- **政府公示系统对接**：
  - 定期爬取工信部/市监局网站的证书公示信息
  - 自动比对台账数据，标记异常（名称变更/吊销/注销）
- **OCR 识别**：
  - 上传证书扫描件→自动提取关键字段（证书名/编号/有效期）
  - 人工核对后入库
- **企业微信/钉钉集成**：
  - 证书到期自动发送消息给责任人
  - 支持移动端审批延期申请

### 2.5 AI 动态（AI Hot）

#### 现状描述
- 功能：AIHOT 精选流按「AI × 医疗软件信息化」过滤行业资讯
- 展示：论文/媒体/政策三类资讯，每条含标题、摘要、来源、时间
- 操作：转情报中心按钮

#### 核心问题

**【P1】内容价值低**
- **现象**：
  - Google Research in Nature 发表 AI-PPG-ACC-HTN 这类技术与医疗信息化售前关系不大
  - 资讯多为纯学术/技术报道，无商业价值（竞争对手动态/中标案例/政策变化）
- **影响**：用户认为这是"噪音"，直接忽略

**【P1】无内容筛选机制**
- **现象**：
  - "精选流"是自动还是人工？如果是自动，为何选择这条？
  - 无用户反馈机制（"有用"/"无用"、"相关性打分"）
- **影响**：无法迭代优化内容质量

**【P2】交互单调**
- **现象**：
  - 所有内容都相同样式，无差异化（重磅新闻应该更醒目）
  - 无收藏/分享/离线阅读功能
- **影响**：用户留存率低，用完即走

#### 优化建议

**优先级 1：重新定义内容来源（预计投入：2-3 天）**
- **优先级排序**：
  1. **政策变化**：国家卫健委/医保局的新规（直接影响投标参数）
  2. **竞品动态**：卫宁健康/东软医疗/创业慧康等的中标/融资/新产品
  3. **行业会议**：CHINC/HITCME/CACP 等的重要演讲/白皮书
  4. **技术趋势**：真正的医疗 IT 技术（不是通用 AI 研究）
- **人工审核**：建立编辑团队，每天审核 10-20 条高质量内容

**优先级 2：增加用户反馈（预计投入：1-2 天）**
- 每项内容下添加"有用"/"无用"按钮
- 根据反馈调整推荐算法（协同过滤）
- 展示用户对每条内容的评论（形成社区感）

**优先级 3：功能延伸（预计投入：2 天）**
- **一键添加到情报中心**：已具备，可优化为"自动打标签+AI 摘要"
- **订阅主题**：用户可关注特定领域（如"电子病历评级""DRG 支付改革"）
- **日报推送**：每天早上 9 点发送邮件 summarizing 前一天最重要资讯

### 2.6 小智助手（Assistant）

#### 现状描述
- 对话式 AI 助手，支持多轮对话
- 左侧会话列表（快捷会话/历史对话）
- 右侧对话区（新对话欢迎页/历史对话/当前对话）
- 底部输入框（支持 Enter 发送、Shift+Enter 换行）

#### 核心问题

**【P0】功能边界模糊**
- **现象**：
  - 欢迎页写着"你的售前专属助手：多轮对话、站内数据问答、长期记忆与技能指令"
  - 但三个快捷问题都是泛化的（"我手上哪些商机最久没跟进？""帮我总结最近的中标情报""给我列一下进行中的项目和进度"）
  - 实际测试：这些问题都需要调用具体业务 API，但后端是否有这些接口未知
- **影响**：用户期望很高，但实际能力不足，导致失望

**【P0】上下文管理缺失**
- **现象**：
  - 会话列表只显示标题和时间，无内容预览
  - 无法查看当前会话的历史上下文（之前的提问/回答）
  - 无法将对话内容保存为知识
- **影响**：对话是"一次性"的，难以复用

**【P1】技能体系不完善**
- **现象**：
  - 欢迎页提到"技能指令"，但未展示有哪些技能
  - 无技能目录/教程/使用示例
  - 用户不知道可以问什么、能做什么
- **影响**：用户只会用基础聊天功能，无法发挥 AI 潜力

**【P1】答案可信度低**
- **现象**：
  - 回答无来源标注（从哪里来的数据？）
  - 无置信度提示（AI 也不确定时会怎么说？）
  - 无纠错机制（说错了怎么反馈？）
- **影响**：用户不敢完全信任 AI 的答案

#### 优化建议

**优先级 1：明确功能定位（预计投入：3-5 天）**
```
小智助手的三大核心能力：
1. **问答机器人**：基于知识库的智能问答（如"我们公司的 ISO9001 证书有效期到什么时候？"）
2. **任务助手**：执行具体操作（如"帮我把这个标书导出为 PDF"、"创建一个新客户"）
3. **灵感引擎**：创意生成（如"写一个针对三级甲等医院的智慧门诊方案大纲"）
```

**优先级 2：重构对话界面（预计投入：2-3 天）**
- **会话管理**：
  - 每个会话显示最后 3 条消息预览
  - 支持会话重命名/收藏/删除/导出为 Markdown
  - 支持会话搜索（按标题/内容）
- **上下文增强**：
  - 顶部显示当前会话的上下文摘要（如"关于 XXX 项目的讨论，共 12 条消息"）
  - 支持引用之前的问题（"就像刚才说的..."）
  - 支持跨会话搜索（"所有关于'资质逾期'的讨论"）

**优先级 3：完善技能体系（预计投入：3-5 天）**
- **技能目录**：
  ```
  [常用技能]
  → 标书相关：生成大纲/检查偏离/生成响应表/模拟评分
  → 客户相关：创建客户/更新跟进记录/分析信息化水平
  → 资质相关：查询证书/预警提醒/导出扫描件
  → 情报相关：转报情报/生成摘要/竞品分析
  → 通用技能：写周报/整理会议纪要/生成 PPT 大纲
  
  [高级技能]
  → 倾向性参数识别
  → 毛利测算
  → 风险预判
  ```
- **技能引导**：
  - 每个技能提供使用示例（"你可以这样问我：'帮我生成一个针对 XX 医院的智慧病房方案'"）
  - 技能效果评分（用户评价 1-5 星）
  - 热门技能排行榜

**优先级 4：提升可信度（预计投入：2-3 天）**
- **来源标注**：
  - 回答中涉及的数据/事实，下方标注来源（如"数据来源：资质台账#ISO9001"、"参考文档：XX 医院信息化评级报告"）
  - 支持点击来源跳转到原始数据
- **置信度提示**：
  - "我对这个答案有 80% 的把握"（基于训练数据覆盖率）
  - "建议人工复核"（敏感数据如价格/资质）
- **反馈机制**：
  - 每条回答都有"有用"/"无用"按钮
  - "答案有误"入口（报告错误 + 提供正确信息）

## 三、整体架构问题

### 3.1 导航体系混乱

#### 问题描述
- **三套导航并存**：
  1. 左侧菜单（17 个模块，分为 3 组）
  2. 顶部标签栏（可打开多个页面，支持切换/关闭）
  3. 面包屑（当前页面路径）
- **导航语义冲突**：
  - 同一功能在不同地方有不同文案（"标书工作"vs"标书工作台"）
  - 分组逻辑不清晰（"沉淀·团队"中既有知识库/资质台账这种业务功能，又有模型配置/AI 动态这种后台功能）

#### 优化建议

**方案 A：保留左侧菜单 + 标签页，移除面包屑**
```
左侧菜单（扁平化，17 个模块，不再分组）：
├─ 工作台总览
├─ 情报中心
├─ AI 动态
├─ 客户管理
├─ 方案工作室
├─ 产品映射
├─ PPT 与报价
├─ 素材库
├─ 标书工作台
├─ 标书检查
├─ 格式刷新
├─ 知识库
├─ 资质台账
├─ 竞品分析
├─ 小智助手
├─ 模型配置
└─ 团队管理

顶部标签栏（仅作为多开窗口）：
[工作台总览] [情报中心] [+] 
↓
点击[+] 弹出快速启动器（类似 Spotlight）
→ 输入关键词搜索模块/功能/项目
→ 支持快捷键 Ctrl+T 打开新标签
```

**优点**：
- 扁平化降低认知负担
- 标签页满足多任务需求
- 快速启动器替代传统搜索

**缺点**：
- 17 个模块挤在左侧，可能需要滚动
- 新用户不知道哪些是高频功能

### 3.2 文案与术语问题

#### 问题描述
- **军事化黑话**："作战地图""制胜""决胜"等词汇与医疗信息化场景不符
- **术语不统一**：
  - "标书工作"vs"标书工作台"vs"投标项目"
  - "方案"vs"方案编制"vs"建设清单"
  - "情报"vs"情报摘要"vs"转报情报"
- **中英文混杂**：部分按钮/标签使用英文（Export CSV、Refresh）

#### 优化建议

**建立文案规范文档**
```
1. 禁用词：作战、制胜、决胜、杀手锏、利器、赋能、抓手
2. 首选词：工作、完成、处理、管理
3. 统一术语：
   - "标书"代替"投标项目"（名词统一）
   - "方案"代替"建设清单"（上下文依赖）
   - "情报"代替"资讯"（业务场景统一）
4. 中文优先：
   - "导出"代替"Export"
   - "刷新"代替"Refresh"
   - "新建"代替"New"
```

**建立术语词典**
- 维护一个 `glossary.json` 文件
- 每个术语包含：中文名、英文名、定义、使用场景、禁用同义词
- 代码审查时检查是否违反术语规范

## 六、结论与建议

### 6.1 核心结论

1. **功能完整性优秀**：标书七步流水线、方案工作室、情报中心等核心功能已经非常成熟，这在同类产品中属于第一梯队。

2. **UI/UX 存在较大提升空间**：虽然功能强大，但界面设计落后于时代，信息密度过高、交互反馈不足、视觉层次扁平等问题严重影响用户体验。

3. **跨模块联动薄弱**：情报→客户→标书→方案→PPT 这条主线中存在大量"手动搬运"场景，尚未真正实现"数据驱动的业务闭环"。

4. **AI 功能未充分发挥**：虽然有小智助手和多个 AI 功能点，但整体仍处于"锦上添花"阶段，未深入核心业务流程。

### 6.2 实施建议

1. **优先级策略**：按照 Phase 1→Phase 2→Phase 3 的顺序逐步推进，避免一次性大改带来风险。

2. **用户参与**：每个 Phase 结束后邀请真实用户试用，收集反馈后再继续下一阶段。

3. **度量指标**：为每个优化点设定明确的 KPI（如"首页信息密度降低 60%"、"标书生产效率提升 30%"），确保优化有价值。

4. **持续迭代**：UI/UX 优化不是一劳永逸的工作，建议建立季度回顾机制，持续收集反馈并迭代。
