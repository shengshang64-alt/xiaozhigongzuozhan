# PPT 制作能力优化分析（2026-10-30）

> 目标：结合同类项目最佳实践，找出当前 PPT 生成链路的差距，按「投入产出比」排序落地。
> 现状盘点基于 `src/pages/PptQuote/` + `src/components/bid-workspace/BidFigure.tsx` 实测。

---

## 一、同类项目最佳实践对比

### 1.1 Gamma（gamma.app）—— 生成质量标杆

| 做法 | 效果 | 本项目现状 |
|---|---|---|
| **标题必须是完整结论句**（如「数据孤岛是评级失败的头号原因」），不是名词短语 | 每页 3 秒读懂观点，汇报时可直接念 | ❌ 只约束了 ≤16 字，没约束「观点句」 |
| 卡片生成后**一键换布局/换肤**，内容自动重排 | 同一份内容可出 3 种风格给客户挑 | ⚠️ 有模板保真通道，但无「同稿换风格」 |
| 每卡 AI 配图 + 图表智能选型（看数据形态推 chart 类型） | 图文比例稳定，版式不单调 | ⚠️ chart/kpi/imageHint/figures 都有，但靠模型自觉给 |
| 大纲→分页两阶段，**大纲阶段全局统筹图文配额** | 整册风格统一 | ✅ 已有（分批生成说明里有） |

### 1.2 ChatPPT / AiPPT / iSlide（国内 AI PPT）—— 流程体验标杆

| 做法 | 效果 | 本项目现状 |
|---|---|---|
| **智能美化**：生成后给「这页字太多/图太少/标题不结论」的整改建议 | 非设计出身的用户能自助提质 | ✅ 有 deckLint（few_figures 等），✅ 方向对 |
| **AI 润色**：选中文字一键扩写/精简/口语化 | 素材直接进 PPT 不用来回改 | ❌ 没有（可后续接 LLM） |
| 模板市场按「行业×场景」分（医疗/政府/汇报…） | 售前开箱即用 | ⚠️ 有模板上传，无场景预置 |
| **动画建议**：按版式给切入动画 | 汇报更专业 | ⚠️ pptxgenjs 通道有切换动画，保真通道未知 |

### 1.3 Beautiful.ai / Pitch —— 版式工程标杆

| 做法 | 效果 | 本项目现状 |
|---|---|---|
| **Smart Layout**：内容溢出时自动缩字号/换布局，永不出框 | 导出零返工 | ⚠️ 有 lint 出框检测（Slide 侧），渲染侧无自适应 |
| 结构化组件（对比表/时间轴/指标卡）当一等公民 | 表格页不需要手画 | ❌ **缺「表格版式」**——参考范文里最高频的四列对照表、指标进度表没有对应图型 |

### 1.4 公众号范文（docs/ppt-refs，医疗售前实拍）

前面已逐张分析过 30 张成品页，稳定版式语言：

| 版式 | 频率 | 本项目覆盖 |
|---|---|---|
| 四列对照表（依据/要求/动作/边界） | 高 | ❌ 无 |
| 指标进度表（基线+年度目标+进度条） | 高 | ❌ 无 |
| ①-⑥ 流程卡（编号+标题+小图） | 中 | ⚠️ flow 图型近似但视觉差距大 |
| **分层架构图（左侧色块层标签+层间箭头+横切竖条）** | 高 | ❌ **渲染器是单色横条，差距最大** |
| 三栏并列卡（编号+图标矩阵+实景图+指标条） | 中 | ❌ 无（靠 banner+要点拼凑） |

**结论：范文里最高频的「架构图」恰好是当前渲染质量最差的一环。**

| # | 差距 | 借鉴来源 | 改造量 | 预期效果 |
|---|---|---|---|---|
| ① | **架构图渲染器单色横条 → 分层配色+层间箭头+横切竖条** | 范文 a19/a26 + Gamma 结构化组件 | 半天 | **导出 PPT 的架构页从「示意图」变「可交付」** |

## 三、本轮落地方案

### ① 架构图渲染器重写（BidFigure.tsx）

目标效果（对齐范文 a19_00 / a26_07）：

```
┌──────────────────────────────────────────────────────────┐
│ 架构图 · 图名                                            │
├─────────┬────────────────────────────────┬───────────────┤
│ ■ 渠道层 │ [互联网医院] [App] [自助机]      │ ▌横切关注      │
│ (琥珀色) │        ↓ 统一接入                │  信息安全      │
├─────────┼────────────────────────────────┤  运维管理      │
│ ■ 接入层 │ [网关] [统一认证] [安全防护]     │  标准规范      │
│ (橙色)   │        ↓ HTTPS/REST              │               │
├─────────┼────────────────────────────────┤               │
│ ■ 业务层 │ [门诊] [住院] [医技] [药事]      │               │
│ (蓝色)   │        ↓ 服务调用                │               │
├─────────┼────────────────────────────────┤               │
│ ■ 能力层 │ [集成平台] [主索引] [数据中心]   │               │
│ (紫)     │        ↓ 数据访问                │               │
├─────────┼────────────────────────────────┤               │
│ ■ 数据层 │ [业务库] [临床仓库] [数据中台]   │               │
│ (绿)     │                                │               │
└─────────┴────────────────────────────────┴───────────────┘
```

要点：
- 层标签 = 左侧**彩色圆角色块**（白字），颜色按语义（渠道=琥珀/业务=蓝/平台=紫/数据=绿/安全=红/默认=青灰）
- 层间**居中向下箭头 + 协议标注**（layers[].arrowLabel）
- `crossCutting[]` 渲染为右侧竖条（青灰底，竖排标题「横切关注」）
- 模块 chip = 主色 10% 透明底 + 主色描边 + 主色文字，深浅模式自适应
- 高度自适应：层数 4-6 层，超出截断

类型扩展（向后兼容，新字段全可选）：
```ts
{ type: "architecture"; title: string;
  layers: { name: string; modules: string[]; arrowLabel?: string }[];
  crossCutting?: string[]; caption?: string }
```

### ② 标题结论句规则

两处 prompt 改动：
- 大纲/单发生成铁律：页标题必须是**观点/结论句**（≤16 字），禁名词短语
- ARCH_RULES 第 9 条自检项：图上能不能看出关键质量属性（已有）

### 配套改动
- `normalizeSlideFigures`（PPT 侧归一）：透传 `arrowLabel` / `crossCutting`
- `ARCH_RULES`：引导模型给架构图带 `crossCutting`（安全/运维/监控）与层间 `arrowLabel`
- 新增单元测试：normalizeSlideFigures 透传新字段 + 架构图 SVG 结构断言
