## 0. 一句话结论

**能复用，但复用的是"思路与数据"，不是"代码"。** 两个来源的复用价值完全不同：

| 来源 | 复用什么 | 结论 | 是否已落地 |
|---|---|---|---|
| **格式镖师**（暗标 docx 检查引擎） | **算法 + 地区标准数据** | ✅ **值得**，且是本轮性价比最高的一块 | ✅ **本轮已落地 3 项** |
| **喜鹊标书AI**（Vue3 在线平台） | **产品形态 / 交互设计** | ⚠️ **只做产品对标，不做代码复用**（技术栈不同，无源码可搬） | ⏭ 仅登记为路线图参考 |

三条直接回答：

1. **怎么处理** —— 格式镖师只抄"最难的那几段算法"（字体继承链解析、numbering.xml 编号解析、地区标准参数），并把它的**已知缺陷当反面教材**（敏感词裸子串匹配等一律不学）。喜鹊网站**一行代码都不搬**，只把它当"同类产品做到什么程度"的标尺。
2. **有没有必要** —— **有必要，且必要性已经被我自己验证过**：我方的字体类检查项在接入继承链解析之前，对同一份文档会**误报**（"宋体 / SimSun / Songti SC"被当成 3 种字体、run 不写字体就统计不到）；而且"暗标格式标准"默认全空，导致 L1-10/12/13/14、L5-C1/C6/C7/C9 这些项**长期空转**。复用直接把这些检查项从"账面有、实际不判"变成"实际在判"。
3. **你来操作** —— ✅ **已完成**：新增 3 个引擎/数据模块 + 1 条暗标规则（L5-C10）+ 配置弹窗地区预置。**四门禁实测全绿**（见 §6）。

## 2. 格式镖师：值得复用的东西（含落地状态）

| # | 能力（报告出处） | 为什么值钱 | 本轮状态 |
|---|---|---|---|
| 1 | **字体继承链解析**（§9） | Word 里"这个字什么字体"是**继承**出来的，没有直接答案。解析链：run 的 `rFonts/@eastAsia` → run 字符样式 → 段落样式（沿 `basedOn` 上溯）→ `docDefaults`。再加**别名归一**（宋体 ↔ SimSun ↔ Songti SC）与**中英混排**（含中文才采信 `eastAsia`；Arial/Times 等占位字体忽略）。**这是全项目最难、也最容易出错的一段。** | ✅ **已落地**：新增 `engine/fontResolve.ts`（+ 单测），接入 L5-C1 正文字体、L1-1 字体不一致、L1-11 字体达标 |
| 2 | **numbering.xml 编号解析**（§11） | `w:num → w:abstractNumId → w:abstractNum/w:lvl/w:numFmt` 链，判"项目符号 vs 数字编号 vs 中文数字"。暗标普遍写"**不得使用项目符号，须用 1. 2. 3. 数字编号**"，没有这条链就判不了。 | ✅ **已落地**：新增 `engine/numberingResolve.ts`（+ 单测），新增规则 **L5-C10** |
| 3 | **地区格式标准数据**（§12.1） | 内蒙古/河北/四川三套**真实招标条款**（正文字号、行距、边距、是否允许页码/彩色…），把"招标文件条款"变成可判定参数。 | ✅ **已落地**：新增 `config/anbidRegionPresets.ts`（+ 单测）+ 配置弹窗一键套用 |
| 4 | **占位符保护式标点转换**（§10.1） | `@COMMA@/@DOT@/@COLON@` 先占位、再整体替换，避免"改了一处把别处改坏"。 | ⏭ **候选**（本轮未做，见 §7） |
| 5 | **编号原地修复**（§11.1） | 不动文字、只改 OOXML 的 `numPr.numId`，把圆点项目符号批量变成 `1. 2. 3.`。 | ⏭ **候选**（涉"写回文件"，风险高于只读检查，需单独评估） |
| 6 | **标题/列表/表格启发式判定**（§9.4） | 标书标题多是手打的，不套 Word 标题样式。报告用"编号正则 + 中文序号 + 样式名 + 字号/加粗兜底"四级判定。 | ⏭ **候选**（我方目前靠样式/大纲，可补一层启发式降漏报） |

> 落地口径：以上三项**全部是重写实现**，未拷贝任何 Python 代码；仅复用算法思路与公开的招标条款数值。

## 3. 格式镖师：**绝对不能照搬**的部分

报告 §18 自己列了 13 条功能性缺陷 + 6 条安全风险，其中几条正好是我们**已经做对**的地方，属于典型的"反面教材"：

| 反面教材 | 它的问题 | 我方的做法（保持） |
|---|---|---|
| **敏感词裸子串匹配**（§13.2） | `if keyword in para.text`，无分词/无大小写归一/无上下文。`省/市/县/区` 这种单字会**海量误报**（"市区""省事"都命中）。 | 我方 L5-A*/B*/F* 走**词库 + 正则（社会信用代码/手机号/邮箱格式）+ 结构化报告**，绝不退回裸子串 |
| **检查项空开关**（R3） | `check_punctuation` 函数体是 `pass`，界面开关是摆设。 | 我方规则**有开关就必须有测试**（每条规则均有单测） |
| **永不触发的检查**（R4） | 用不存在的 python-docx 属性判空，检查项**永远不触发**却显示"已检查"。 | 我方"未配置/无法判定"显式标 `unconfigured`/`skipped`，不假装通过 |
| **静默吞异常**（§18.3） | 满地 `except: return False`，失败即静默。 | 我方引擎返回 `available/unresolvedRuns` 计数，解析不到就**如实上报** |
| **只看第一节**（R7） | 只查 `sections[0]`，多节文档页边距漏检。 | 我方按整文档解析 |
| **硬编码密钥 + 客户端计费**（S1/S2） | Fernet 固定口令、支付宝私钥全文编译进客户端，"免费试用=永久不限量"。 | 与我方无关；**明确不引入任何客户端授权/计费逻辑** |
| **明文携带全套业务源码**（S6） | 打包即泄露全部逻辑。 | 复用即"重写"，天然规避 |

**一句话**：这份报告的最大价值，一半在 §9/§11/§12 的算法，另一半在 §18 的"错误清单"——它替我们把坑踩了一遍。

## 4. 喜鹊标书AI（网站）：只做产品对标，不复用代码

**技术栈对不上，谈不上代码复用**：它是 Vue 3 + Element Plus + TipTap + Mermaid 的 SPA，后端 `//ai.bidfile.qianlima.com/api`，Agent 是 Python；我方是 React + TS + Vite + PocketBase。**结论：一行代码都不搬。**

但它作为"同类产品做到什么程度"的标尺，有 5 处**产品/交互层**值得登记为参考（不是现在做）：

| 参考点 | 它的做法 | 我方的对应位置 | 价值判断 |
|---|---|---|---|
| **招标文件预览 + 评分点高亮** | 多文件 Tab、目录/查找双模式、**评分点高亮标记 + 文本搜索定位** | 我方有文件解析与阅读视图 | ⭐ 交互可借鉴（"点中评分点跳到原文"是刚需） |
| **AI 解析结果三栏展示** | 基本信息 / 评分要求 / 招标需求，Markdown 渲染 | 我方有材料解析与要点提取 | ⭐ 信息架构可直接对标 |
| **"思考过程"分阶段可视** | 5 阶段（需求理解→详细需求→评分项列表→评分项分析→目录构建），带进度百分比 | 我方 AI 生成过程可见性较弱 | ⭐ "让用户看见 AI 在读什么"能显著提升信任 |
| **状态机管理** | 目录写入 `PENDING→GENERATING→READY→CONFIRMING→CONFIRMED` | 我方生成流程状态较粗 | 参考（长任务防丢/可恢复） |
| **风险审查（标书提交前复核）** | `/riskReview` 路由 + `inspectScoreGate` 评分门槛检查：缺项、废标高频问题、格式风险 | **正是我方的 BidCheck** | ⭐ 已验证我方方向与头部产品一致；可补"评分门槛（得分点是否都响应了）"这一子视角 |

它还做了：以标写标（历史中标书变量替换）、施工标（横道图/网络图/工程附表）、述标 PPT + 讲稿 + 高频问答、智能配图（Mermaid/信息图）、多平台（Web/H5/WPS/桌面）。这些属于**产品路线图**，与"暗标格式检查"不是同一战役，本轮**只登记不行动**。

## 5. 结论（正面回答三个问题）

1. **怎么处理**：把"格式镖师"当**算法字典**用——只取 §9/§11/§12 三段，重写成我方 TS 引擎；把"喜鹊"当**产品标尺**用——只记交互与信息架构，不碰代码。两条来源都**不产生代码依赖、不引入合规风险**。
2. **有没有必要**：**有必要**，且不是"锦上添花"——不复用的话，我方字体类规则会**误报**、格式标准类规则会**空转**（账面有条目、实际不判）。这次复用是把"摆设"变成"真检查"。
3. **我帮你操作了**：三项落地 + 一条新规则 + 配置体验升级，**四门禁全绿**。详见 §6。
