## 你必须遵守的（详细规则已在 .qoder/rules/ 中注入）

1. **一轮只做一件事**：选**一个**优先级最高的项，禁止并行多主题。
2. **先取证再动手**：确认问题真实存在，留下可重放证据。禁止"我觉得"。
3. **放行门**：A 类（修）/ B 类（优化）可自动执行；**C 类（新增能力）默认只写方案、不动代码**。
   **例外（用户 2026-10-12 全量预授权）：落在 `docs/17-C类预授权与依赖白名单-2026-10-12.md`
   预授权范围内的 C 类，可直接实现，无需再等确认。** 范围 =
   ① **交付链卡点类**：`.loop/ledger.json` 中 id 以 `delivery-` 开头的项，或 `docs/16` 第五节覆盖的
   标书 `/bid-workspace` / 方案 `/solution-studio` / PPT `/ppt-quote` / 知识库 `/knowledge` 四大模块；
   ② `docs/17` 第三节白名单内、许可证为 MIT/Apache-2.0/BSD/ISC/MPL-2.0、可离线、可回退的依赖。
   范围外一律停下写方案等确认。报告中必须写明本轮依据第几条第几款。
   **红线优先级高于预授权**，拿不准就按未授权处理。
4. **红线**：不改 PB schema、不改 AI 提示词语义、不改费用与认证逻辑、不改**已有**导出物版式契约
   （新增导出模板属已授权）、不重构 `bidTypes.ts`/`useBidWorkspace.ts`、不引入白名单外依赖、
   不删业务数据、不动 VibeX 平台保护文件。
5. **验证门禁**：`npx tsc -b && npx vite build` 通过 + `npx eslint src` 无**新增**错误。不过则先回滚。
6. **诚实原则**：没做的、没测到的、降级验证的，全部写进报告的诚实清单。**禁止谎报**。
7. **零费用优先**：静态读码/接口直查/DOM 快照/本地复算能得出结论的，不要调 AI。
8. **交付链优先**（用户 2026-10-12 拍板）：候选池中存在未关闭的 `delivery-*` 项时，
   **优先从其中选**——它们直接卡住"能不能真交付"，优先级高于同级别的其他项。
