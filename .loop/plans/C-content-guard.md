# C 类方案 · 内容护栏 AI 增量（一致性规则 2/3/4：量化依据 / 量级自洽 / 政策时效）

> 提出轮次：R81（2026-09-26）· 状态：**等用户确认** · 预估 2 轮
> 来源：账本 content-guard-03（06#9 一致性检查器，R7 已落纯本地规则 1/5，本方案补需要语义理解的 2/3/4）

## 做什么

在**交卷体检**步骤新增「AI 内容护栏」增量检查（与既有本地数字对账**并存、互补、不替代**），逐章把正文与三类基准做语义级核对：

| 规则 | 核对内容 | 基准来源 |
|---|---|---|
| ② 量化依据 | 正文中的关键数字（工期/人数/金额/响应时间）是否有招标原文或全局事实依据，禁止无中生有 | 全局事实表 + 招标原文片段（既有 tenderFragments 通道） |
| ③ 量级自洽 | 数字量级是否自洽合理（预算 2500 万 vs 报 4000 万、并发 10 万 vs 2000 床医院等） | 全局事实表 + KB（知识库同赛道文档） |
| ④ 政策时效 | 引用的政策/标准/评级是否现行有效（如「2021-2025 行动方案」已过期） | 知识库政策法规赛道 + KB 检索 |

## 设计要点

- **只报不拦**：结果作为交卷体检的增量 issue 列表（复用既有 FormatIssue 结构与体检面板渲染，**零 schema 变更**），逐条附原文摘录与依据出处；处置（改/留）仍由用户判断
- **成本透明**：逐章一次 LLM 调用（走既有费用确认弹窗），可按章跳过；KB 检索走 kbAssemble 既有共享缓存
- **上下文裁剪**：每章正文前 6000 字 + 事实表 + KB 命中片段（各 ≤2000 字），控制 token

## 动哪些文件

| 文件 | 动作 |
|---|---|
| `src/pages/BidWorkspace/prompts/consistencyGuard.ts`（新增） | 逐章护栏 prompt 构造器（PROMPT_VERSION + 快照锁字，与搬迁同规范） |
| `src/pages/BidWorkspace/useBidWorkspace.ts` | 交卷体检调用链追加该检查（Promise.allSettled 既有模式），结果并入体检面板 |
| `promptsSnapshot.test.ts` / 新单测 | prompt 快照 + 结果解析纯函数用例 |

## 数据影响

零 schema 变更（结果进既有体检 issue 列表随项目 PATCH 落库）；不自动修改任何已生成正文。

## 边界（v1 不做）

不做自动改写（发现→人工改）、不做全文档一次过（逐章可中断可控费）、不引入新依赖。
