# C 类方案 · 标书拆分自动识别标包（多包件招标支持）

> 提出轮次：R73（2026-09-26）· 状态：**等用户确认** · 预估 2–3 轮
> 来源：用户需求「标书功能在拆分的时候能自动识别标包」

## 做什么（v1 三件套）

1. **解析新增「标包划分」分区**（key = `lots`）
   - **本地抽取（零 AI）**：正则扫描「第X包 / 标段X / 包X / 分包X」标题行及其后续内容/预算行，产出逐包清单（包号、名称、预算金额、主要内容摘录）；与 ★条款本地扫描同一模式
   - **AI 兜底**：解析配置增加该分区勾选项，AI 解析提示词同步补 guide（本地漏掉的由 AI 补）
2. **解析报告展示**：分区走现有渲染路径自动出现在核心信息列表，内容可人工修改补充（与其他分区同规则）
3. **大纲联动（最小版）**：大纲/章节生成提示词注入「本项目为多包件招标，本次投标针对：{用户在分区里确认的包}」上下文——用户在分区编辑里写明投标哪个包即可生效。**不做**自动按包拆大纲（交互改动大，列为 v2 提案）

## 为什么

- 多包件招标是政采常态（R44 解析专项验收清单「多包件分开解析」本就是检查项），当前系统完全没有包概念——拆分时包结构丢失，投标针对性差
- 解析分区架构为灵活 json 数组，新增分区**零 schema 变更**

## 数据影响

零 schema 变更（parse_report.sections 数组追加一项）；旧项目无该分区 → 界面不显示、生成不受影响（向后兼容）。

## 边界（v1 不做）

自动按包拆大纲/按包分别出整份标书（v2 提案）、标包与商机/报价的关联。
