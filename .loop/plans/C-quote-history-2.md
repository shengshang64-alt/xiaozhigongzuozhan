# C 类方案 · 报价历史库二期（结单沉淀 + 参考区间推荐）

> 提出轮次：R77（2026-09-26）· 状态：**等用户确认** · 预估 2 轮
> 前置事实（本轮取证）：一期（R40）已交付「同商机历史报价参考 + 一键导入」（`historyQuotesFor`，纯检索零 AI）；**当前库内报价存档 = 0 份**。

## 关键判断（为什么不能直接做"智能推荐"）

二期的目标「按医院等级+床位数+模块组合给参考区间」本质是**从历史成交样本统计区间**。样本为 0 时上线该功能，只能输出编造的数字——违反产品诚实原则。因此方案按「先沉淀、后推荐」两步走，并设数据前置门槛。

## 做什么

### 第一步 · 结单沉淀（B 类，数据侧）

- 报价单新增「标记为成交参考」动作（用户显式点击，非自动）：把该报价标记为**沉淀样本**，同时从关联商机 → 客户档案带出**医院等级 / 开放床位 / 模块组合**三个元数据字段存入报价记录
- 新增字段走 PocketBase 动态集合模式（与既有 quote 字段演进同模式，`sanitizeQuote` 归一存量），不改动其他集合
- 存量报价支持补标（列表页批量入口）

### 第二步 · 参考区间推荐（C 类核心，展示侧）

- 新建/编辑报价时，按「医院等级一致 + 床位数 ±40% + 模块重合度 ≥50%」匹配沉淀样本
- 命中 ≥2 个样本 → 显示参考区间卡：`该组合下历史成交 N 例，模块合计区间 X–Y 万元（中位数 Z）`，附样本清单可展开
- **样本 <2 或无匹配 → 明确显示「沉淀样本不足，暂无参考区间」**，绝不输出弱依据数字
- 一键导入沿用一期能力（导入的是整份明细，不是区间）

## 数据影响

- quotes 集合新增 3 个可选字段（hospital_level / beds_total / modules_summary）+ 1 个标记字段（is_won_sample）——动态 schema 同既有演进模式，存量记录 sanitize 归一，零迁移
- 不删除任何数据

## 数据前置门槛（写进功能的诚实提示）

参考区间在沉淀样本 ≥2 且匹配命中时才出现；当前 0 份，**功能上线后需要实际使用积累**（每次成交后点一下「标记为成交参考」）。建议团队从下一个真实项目开始养成。

## 预估

2 轮：第一步 1 轮（沉淀动作 + 字段 + 批量补标），第二步 1 轮（匹配引擎 + 区间卡 + 单测）。

**确认回复**：「同意」两步都做；或「只做第一步」（先只解决沉淀，推荐等样本够了再说）。
