# 方案（待你点头）· 报价 vs 最高限价/预算 交叉核对（numeric-consistency-02）

## 1. 要解决的问题（一句话）

投标报价**一旦超过招标文件的最高限价/预算，就是直接废标**——这是最贵的一类错误。现在"交卷体检"里没有一条专门的规则去盯这件事。

## 2. 现状取证（为什么现在没这条规则）

我已把相关代码逐条看过：
- 招标文件解析时，**预算/限价已被当作"硬指标要点"提取**（提示词明确要求「预算金额：3500 万元」这种格式），所以限价值通常已经在项目事实里。✓
- 已有的"数值一致性检查器"很强，但它只在**同一个名词**的数值前后不一致时报警（比如"预算金额"一处 3500、正文写成 4000）。
- **报价是另一个名词**（投标报价/总报价/开标一览报价），所以"报价 vs 预算"这条**跨名词、且只看'报价是否更大'的方向性判断，目前不存在**。这就是要补的缺口。
- 报价的**真实总额**其实是在"PPT 与报价"模块里算的，**没有接进标书体检**（那边的报价单关联的是"商机"，不是"标书包"）。

## 3. 两个可选做法（差别在"数据从哪来"）

### 做法 A（最小·纯本地·零红线）——**我推荐先做这个**
- 规则：在**标书正文里出现过的投标报价数字**（投标函、开标一览表、报价表章节、偏离表响应里写的金额）与**事实里的最高限价/预算**做**方向性比对**：报价 > 限价 → 交卷体检报警"【废标风险】投标报价 X 超最高限价/预算 Y（超 Z%），导出前必核"。
- 复用现成的数值解析与"元/万元"归一工具，**只是多加一条规则**。
- **不碰**：数据模型、AI 提示词、AI 调用、费用、导出门禁。完全对齐前几轮"只提醒、不阻断、审计中立"的做法。
- 代价：约 1 个文件加一个纯函数 + 接线 + 若干测试，改动面小、可独立回滚。
- **唯一的局限（必须如实告诉你）**：只有当**报价数字被写进了标书正文**时它才报得出来。如果你只在"PPT 与报价"模块里算价、标书正文从不写具体总价，这条就看不到那个价。

### 做法 B（完整·跨模块·动静大）
- 把"PPT 与报价"里那份报价单的**真实总额**接进标书体检来比对。
- 优点：不受"正文有没有写价"限制，用的是真数。
- 代价：**要新搭一条跨模块数据管道**（标书包 ↔ 商机 ↔ 报价单的对齐与取数），改动面和风险都明显更大，属更重的 C 类。

## 4. 落地范围（若你选 A）

- 判定：`投标报价 > 最高限价`（限价取"最高限价/控制价"，无则退用"预算金额"，并在文案里注明用的是哪个口径）。
- 触发面：技术/商务各章正文 + 偏离表响应里出现的报价数字；同一章去重、总条数上限沿用现有 ≤30。
- 呈现：交卷体检里一条 `warn`（现有最高级，**不加新等级、不改 UI**），文案带【废标风险】使其醒目。
- 防误报：只在能明确识别出"这是投标报价"且能取到"限价/预算"时才算；识别不确定时宁可不报（对齐既有检查器的保守取数）。
- 验证：`vitest`（补正反用例：报价>限价报、报价≤限价不报、无限价不报、单位万元/元混用正确归一）+ `tsc` + `build` + eslint 无新增；再在 dev 里逐真实项目动态 import 复核 0 误报。

## 5. 我的建议

**先做 A**：它能挡住最常见、最贵的"报价超限价"废标，零红线、可快速上线验证；B 作为 A 之后的增强，等你确认"A 的正文取数不够用"时再单独立项。
