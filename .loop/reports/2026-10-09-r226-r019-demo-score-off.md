# R226 · R-019/R-024 演示分默认不生成 + 线下准备提示 + 生成开关（第 2 轮改造 · 标书链第七 slice）

## 选题依据与已有能力判断
第 2 轮 R-019/R-024：标题含「演示 / 演示分 / 答辩 / 视频」的节点是**现场环节的真实评分项**（样例：功能演示 1/2 共 6 分），
但应答内容是实机演示与讲标答辩，AI 长篇正文既无法替代、又会白占字数页数预算。要求：默认不进正文生成、不计字数页数、
保留节点并醒目标「演示分·不响应」、提供生成开关、线下准备演示提示语。
既有「商务骨架章不生成正文」（isGenTargetChapter + chapterWordBudgets 权重 0）正是同一生命周期模式，本 slice 让演示分节点复用该中央判定。

## 关键设计
- 复用商务骨架章生命周期：演示分不是新造机制，而是把 isGenTargetChapter/chapterWordBudgets 两个既有单一判定各加一个默认 true 的
  可选参数，令「不生成 + 不计字数页数」在批量生成、待生成计数、任务队列、完成度、预算分配全链路自动一致，杜绝散点漏改。
- 向后兼容零回归：两参数默认 true → 既有 21 例（scopeTriMode 7 + formatCharsPerPage 7 + …）行为字节不变；存量项目 gen_options 无
  generate_demo → normalize 得 false → 演示分节点即刻默认不生成（符合 R-019「默认关闭」预期，无需迁移）。
- 「视频」误判防护：医疗标书里「视频监控 / 视频会议 / 视频影像 / 远程会诊」是真实技术章必须生成，故 DEMO_VIDEO 分支要求视频与
  演示/播放/录播/讲解等意图同现才判演示分；单靠 演示|答辩|讲标 已覆盖样例「功能演示一/二」「现场答辩」。
- 开关持久化随项目：generate_demo 走既有 setGenOption/applySetting 防抖落库通道（与逐条应答强化/素材优先注入同款），非全局 localStorage。
