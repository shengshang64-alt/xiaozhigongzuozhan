# R80 · B-01 知识库首屏性能：25-30 秒 → 约 2 秒

## 本轮做了什么

知识库打开时不再把 6400+ 篇文档的**全文**全部拉一遍——列表只传标题/摘要等元数据（传输量降约 90%），正文在你点开阅读、编辑或删除时按需单条拉取。实测首屏加载从 25-30 秒降到 **约 2 秒**。

## 根因与改法

**根因**：`useKnowledge.refreshDocs` 调 `listKbDocs()` 全量翻页拉取**含 content 全文**（2173+4825 篇），冷加载即 25-30 秒。
**改法**：
- `kb_docs.pb.js` list 路由加 `slim=1` 查询参数：命中时响应把 `content` 置空（**向后兼容**，不带 slim 的调用行为完全不变）
- `useKnowledge.refreshDocs` 改走 `listKbDocs({ slim: true })`
- 新增 `kbCore.getKbDoc(id)` 单条补拉；阅读器 selectedDoc 变化时自动补拉；编辑、单删、批删前正文保真（回收桶不丢内容）

**过程如实记录**：先后试了两个方案都被实测否掉——①PB 原生 fields 参数（返回空体 `{}`， PocketBase 层行为不明）；②`\s` 本已覆盖全角空格导致字符类冗余（顺带修掉 2 个历史 lint 错，eslint 145→144）。最终采用 hooks 加 slim 参数（同 R74 quotes 模式）。

## 门禁与验证

- 357/357 单测 · tsc ✓ · build ✓ · eslint **144 = 基线-1**
- 双模式 API 验证：slim=1 content 空 ✓ / 不带 slim content 全文 ✓（向后兼容实证）
- 实机：首屏约 2 秒，2173 篇目录树全渲染；截图 `_shots/R80/kb-slim-loaded.png`
- 涉及 pb_hooks：已重启 PB（8000/7000 双 200）

## 你怎么自己验证

1. 打开知识库 → 计数即出（团队 2173 / 笔记 4825），秒级
2. 点开任意一篇文档 → 正文完整显示（自动按需补拉）
3. 删除任意一篇 → 回收站里正文仍在（删除前保真）

## 遗留

- 回收站恢复后 content 有值 ✓；知识库「搜索标题与正文关键词」对未点开的文档只搜标题与摘要（slim 后正文不在前端）——影响极小，因为问知识库/RAG 检索走 kbAssemble 独立全量通道不受影响。如实记录，不改。
