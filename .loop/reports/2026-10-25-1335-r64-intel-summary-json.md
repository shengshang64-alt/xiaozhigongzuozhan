# R64 · 2026-10-25 13:35 · 情报中心摘要不再显示成原始 JSON

## 一、本轮做了什么

情报中心里，「健康报」这个源抓回来的摘要，前半段是一坨网页元数据：

```
－健康报网——健康门户 {"id":"514749","toptitle":"","title":" ","crtime":"2026-10-22 09:49:07",…} □本报评论员…
```

而情报中心的**卡片和右侧详情面板是原样显示的**——售前点开一条情报，第一眼看到的是 `{"id":"514749"…}`。

本轮把这层「站点名 + JSON 元数据」在**显示时**剥掉，露出真正文。改完后同一条情报显示为：

> □本报评论员在全国卫生与健康大会上，习近平总书记指出，保障人民健康需要 。

**顺手修掉一个更隐蔽的问题**：首页的动态卡其实已经做过清洗，但那套清洗规则是「整行含花括号就整行丢掉」，
而这批数据的 JSON 和正文粘在同一行 → 首页上这 9 条情报表现为**「有摘要，但摘要区是空的」**。
现在三处（列表卡片 / 详情面板 / 首页动态卡）走同一个清洗函数。

## 二、为什么做这件事

**发现路径**：读 `.nightrun/MORNING_REPORT.md` 与 `docs/测试报告-售前工作台全面检查.md`，
其中 BUG-003 写着「情报中心部分条目含未清洗的 JS 代码/JSON/导航菜单」。这条一直挂在待办上没人复核。

**取证（不是靠读代码猜）**：直连本地 PocketBase 把 627 条情报全量拉下来扫了一遍——

```
库内情报 627 条 / 有 summary 58 条 / 含 JSON 元数据 9 条
源「健康报·卫健官方媒体」：共 11 条，脏 9 条（81.8%）
脏条创建日期：2026-09-19 … 2026-10-22（跨 5 周，不是一次性历史遗留；该源最新一条仍是脏的）
```

**为什么不是别的**：候选池里优先级更高的项（`docs/23` 的 P0 交卷清单 / 证据台账 / 正文质量门禁、
B25 长文召回、B28 拦截阈值重校）全部落在 `src/pages/BidWorkspace/**`，
而开工时工作区有 **91 个未提交文件**正在被另一个执行者改（BidWorkspace + bid-workspace 组件几乎全在其中）。
碰那些文件等于把别人的半成品搅在一起，所以本轮选了**完全不在在途批次里**、且能被真实数据证伪的一项。

## 六、遗留与新发现

1. **根因还在服务端**：病根是 `pocketbase/pb_hooks/intel_center.pb.js` 的摘要拼装。本轮只治展示层
   （存量 9 条立刻可读，且不依赖重启），但**新抓的条目仍会带 JSON**。根治要改 pb_hooks，
   而 pb_hooks 不热加载、**必须重启 :7000**，项目 hook 禁止智能体结束进程 → 需你操作。
2. **内容片段还有「标题－站点名」前缀**（同一源 9 条，例如 `建强卫生与健康系统干部人才队伍－健康报网——健康门户`）。
   可读、属噪声，本轮未动（snippet 实测 0 条含 JSON/HTML）。
3. **3 条未来日期**：`HIT专家网` 有 3 条发布日期是 **2027-04-29 / 2027-01-03**，
   「按发布时刻」排序会把它们顶到最前。测试报告 BUG-003 的「日期错(2027)」至今没闭环。
4. **情报搜索要按回车才筛**（只输入不生效）。是否设计如此未定，先记账。
5. **并发在途 91 个文件**：本轮一个没碰、也没 `git add -A`。因此全量 vitest 的 326/3785 **含对方在途用例**；
   `AGENTS.md` 的基线行**故意没同步**（同步会把别人未提交的数字写进仓库约定）。
