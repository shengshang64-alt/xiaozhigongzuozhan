## 坐实的问题：CSV 公式注入（CWE-1236 / OWASP CSV Injection）
R106 的 `buildCsv` 已正确做 RFC4180 转义（逗号/引号/换行 → 双引号包裹 + 内部引号翻倍），
但**没有任何公式注入防护**。当导出单元格的文本以 `=`、`+`、`-`、`@`、制表符 `\t`、回车 `\r` 开头时，
RFC4180 转义只保证「不窜列」，却把它原样写进文件——用 Excel / WPS 打开该 CSV 时，这些单元格会被
当作公式或 DDE 命令解析执行。例如厂商名/客户名/备注/情报标题/报价明细等**用户可编辑字段**填成
`=cmd|' /C calc'!A0`，导出后在他机器上用 Excel 打开即可能触发远程代码执行（DDE 载荷）。
本项目「导出 CSV」是全站在用的高频出口（exportToCsv 服务 7 个列表 + 竞品能力矩阵转置导出），
导出文件常被转发/在他人电脑打开，故这是一条跨模块、真实可达的安全面，不是理论风险。

## 方案（复用既有单一口径，不引新依赖、不自研引擎）
- 在 `csv.ts` 的 `escapeCell` 内补一层**前导单引号（Excel 强制文本）**中和：
  仅对 `typeof v === "string"` 且匹配 `/^[=+\-@\t\r]/` 的单元格前置 `'`，令 Excel 按文本解析、不当公式执行。
- **数字类型不劫持**：`-5`、`3.2` 等以 number 传入的合法数值保持原样（负数非注入风险，
  只有「字符串」以 `-` 开头才需防护），避免把正常数字单元格误转成文本。
- 与既有转义**叠加**：先加前缀再走原 `/[,\r\n"]/` 判定，故「含逗号的注入载荷」既加前导单引号又整体双引号包裹。
- 修复点选在**全站唯一拼装函数** `buildCsv`，`exportToCsv`（7 调用方）与竞品矩阵 `buildOrderCompareCsv`
  自动继承防护，零调用方改动、零口径漂移——正是 R106 收敛为单函数后带来的红利。

## 新旧口径对比（关键行为）
| 场景 | 旧（仅 RFC4180 转义） | 新（叠加公式注入防护） |
| --- | --- | --- |
| 文本 `=cmd\|' /C calc'!A0` | 原样写出，Excel 打开触发 DDE | `'=cmd\|' /C calc'!A0`（前导单引号强制文本） |
| 文本 `=1+1` / `@SUM(A1)` | 被当公式求值/引用 | `'=1+1` / `'@SUM(A1)`（不执行） |
| 文本 `-3` / `+2`（串） | Excel 当公式 | `'-3` / `'+2` |
| 以制表符 `\t` 开头的文本 | 部分版本被公式解释 | `'\t=1`（加前缀） |
| number `-5` / `3.2` | `-5` / `3.2` | **逐字不变**（合法数值不劫持） |
| 普通名称「智业软件」 | `智业软件` | `智业软件`（无回归） |
| 含逗号的注入载荷 `=x,y` | `=x,y`（窜列且可执行） | `"'=x,y"`（前缀 + 双引号，安全且列对齐） |
