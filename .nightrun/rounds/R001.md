- 本轮评分：影响 3 / 严重 3 / 可验证 5 / 可感知 3 / 风险 2 / 阻塞 0 → score=25

## 改前（证据）

1. 静态：`DocStatus` 仅三态 `outline/generating/done`（solutionTypes.ts:134）；`runBulkGenerate` 终态三元 `allDone ? "done" : "outline"`（useSolutionStudio.ts:995）——部分完成必然回落「大纲中」。
2. DOM（改前）：种子方案（2/3 章成稿）列表卡片同屏显示「大纲中」+「正文 2/3 章」（evidence/R001_dom_list_before.txt）。
3. **实测实锤（计划外发现）**：真实跑一次批量生成（拦截 LLM 失败，发生了 1 次真实 AI 调用，见下）3/3 章全部生成成功后，`doc_status` 卡死 `generating`（evidence/R001_api_after_repro.json / R001_api_after_repro2.json），页面将永远显示「生成中 + 正文 3/3 章」。
4. 服务端排除：手动 `PATCH {doc_status:"done"}` 返回 200 且落库正常 → 纯前端根因。

## 根因（两个，同属一类）

- **根因 A（三态不足）**：批量生成中止/部分失败时终态只能取 `outline`，与「正文 X/Y 章」计数矛盾。
- **根因 B（并发 PATCH 丢字段）**：循环内每章 fire-and-forget 一笔 `{chapters}` PATCH，循环一结束立刻发 `{doc_status}` PATCH。后端自定义路由 `solutions.pb.js` 的 PATCH 是「读整行 → 改一个字段 → 存整行」，两请求在服务端交错时，后落库者用**旧读快照**整行覆盖，把先落库者的字段冲回旧值 → 最终的 doc_status 写入丢失（实测卡死「生成中」即此机制）。
- 排除候选：React 状态未同步（ref 同步更新，排除）；服务端校验拒绝（手动 PATCH 200，排除）；服务未落盘延迟（2 次间隔复查仍 generating，排除）。

## 影响面与剩余风险

- 影响：方案编制（列表+编辑器）、客户管理链资产标签；`usePptQuote` 仅判 `=== "done"` 天然兼容；assistant 取数透传 text 无影响。
- 剩余风险：① 章节与章节 PATCH 之间的竞态窗口仍在（本地毫秒级 vs LLM 秒级，实际概率极低，未在本轮串行化）；② 旧数据若已处于「outline+有正文」的失真态，不做迁移，打开编辑/单章生成后会自然收敛；③ 后端「整行读改写」的丢更新窗口对全部 collection 仍存在（已记账 D-8 遗留 + 建议）。
- **费用如实记录**：取证时浏览器隔离环境导致 fetch 拦截未生效，实际发生 1 次 LLM 调用（第 3 章正文 747 字，平台内置模型 agnes-3.0-flash）。该内容随种子数据删除，未污染真实数据。
