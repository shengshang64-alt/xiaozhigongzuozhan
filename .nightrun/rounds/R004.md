## D-10 删除方案后商机引用悬空

### 改前（证据）
- 种子：商机 `kig8yhi7vap5tk8` ref 指向方案 `eixaqxbwvnib6re`（模拟 confirmOutline 关联）。
- UI 删除方案成功（toast「方案已删除」，方案 GET 404）后，商机 ref 仍为 `{"ref_type":"solution","ref_id":"eixaqxbwvnib6re"}`（evidence/R004_api_opp_dangling_before.json）→ 商机详情出现死链。

### 根因
`deleteSolution` 只删方案；confirmOutline 建立的商机→方案 ref 无任何清理路径。opportunities 后端 list 仅支持 rh_user_id/customer_id/stage 过滤（无 ref_id），前端也从未反向清理。

### 改动
| 文件 | 改动 | 原因 |
|---|---|---|
| `src/pages/SolutionStudio/useSolutionStudio.ts` | deleteSolution 删除成功后：拉取 `opportunities?rh_user_id=…&perPage=200`，客户端筛 `ref_type==="solution" && ref_id===rec.id`，逐个 PATCH 清空 ref 三字段；清理失败给含下一步的 toast（不动删除成功语义） | 最小改动面；只用既有 API；与全局搜索兜底同模式 |

### 验证

## D-9 solutions 列表 totalItems 谎报 + >200 静默截断

### 改前（证据）
- 种 201 条 `[NIGHTTEST] D9-xxx` 方案（seed/seed_d9.mjs，幂等）。
- API：`perPage=2` 返回 `totalItems=2`（真值 201，evidence/R004_api_totalitems_before.json）。
- UI：列表渲染 200 张卡片，最旧的 D9-001 被静默丢弃（前端 perPage=200 上限，B6 注释自认）。

### 根因
① 后端 list 路由 `totalItems: items.length`（谎报）；② 前端单页 perPage=200 无翻页、无截断提示。

### 改动

| `pocketbase/pb_hooks/solutions.pb.js` | totalItems 改为过滤后真总数。注意：PB v0.40 JSVM **没有** `countRecordsByFilter`（实测报 "Object has no member"），改用既有 `findRecordsByFilter` 大 limit(100000) 计数，失败回退 items.length | 修 API 契约，调用方得以感知还有更多页 |
| `src/pages/SolutionStudio/useSolutionStudio.ts` | loadSolutions 改按页拉全（perPage=200，循环至 totalItems 或 10 页上限） | 修用户可见的静默截断 |
