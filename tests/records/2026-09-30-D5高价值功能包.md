## 一、totalItems 谎报族统一根治（27 路由）

### 问题
JSVM 自定义路由 list 端点返回 `totalItems: items.length`（= 当前页条数），
非全量总数。前端启发式 `mTotal > items.length ? mTotal : …` 做防御但不可靠。

### 修复方案
镜像 customers.pb.js 已验证的 D-9 模式：在 return 前增 try-catch 计数查询
```javascript
var totalItems = items.length
try {
  var countRecords = filter
    ? $app.findRecordsByFilter("COLLECTION", filter, sort, 100000, 0, params)
    : $app.findRecordsByFilter("COLLECTION", "", sort, 100000, 0)
  totalItems = countRecords.length
} catch (err2) {}
return e.json(200, { items: items, page: page, perPage: perPage, totalItems: totalItems })
```

## 二、perf-02 大纲编辑器可折叠分组

### 问题
方案大纲 121 个 input 同时渲染，DOM 节点多→初始挂载慢。

### 方案
可折叠分组替代虚拟滚动（爆炸半径更小）：
- 顶层章（depth=0）增加 ChevronDown/Right 折叠按钮
- 折叠时 children `<ul>` 不渲染，显示"N 个小节已折叠"提示
- 标题栏增"全部折叠/全部展开"切换
- 状态由 `collapsedIds: Set<string>` 内部管理
- 默认全部展开（向后兼容）

### 效果
121 input → 折叠态仅 15（顶层章）可见 input；展开行为等价原版

## 三、gap-pool-01 竞品差距→能力需求池（设计评估）

### 结论：登记设计方向，本轮不实施

理由：
1. "差距项标记"需在 CompetitorAdopt 写回时增加结构化提取（AI 输出非固定格式），
   依赖 prompt 改造 + 新字段（gap_items json），违反"零 schema 新建集合"约束
2. "汇入能力需求清单"需要新集合或复用现有方案 notes 字段，跨模块协调复杂
3. P3 优先级，非关键路径——竞品分析写回闭环已在 D4 完成（threat_notes），
   差距池为增值功能

- CompetitorAdopt 增"提取差距"选项 → 解析 AI 输出中的差距段落
- 存入 competitors.gap_items（json 数组 [{dimension, description, severity}]）
- 方案生成时注入"针对 X 竞品差距的应对策略"提示词片段
