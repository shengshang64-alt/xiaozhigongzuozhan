  14 章大纲 = 8 个空商务章 + 6 个已成稿技术章（正是「商务同事写了一半、技术材料要 AI 补齐」的真实形态）。

## 操作步骤与预期

1. 进入标书工作台 → 打开该项目 → 第 3 步「投标文件编制」。
2. 展开「底稿增量合并」面板 → 上传 .docx（mammoth 浏览器本地解析，原文不出网）。
3. 核对五态合并计划（原文保留 / 带参考重写 / 缺失自动生成 / 补偏离表 / 底稿多出）。
4. 勾选「追加底稿中大纲未认领的章」→「应用合并计划」→ 确认框 → 查看结果块与 toast。
5. 落库取证（`scripts/r245_verify_db.py`）：保留章 `draftLocked` 且正文=底稿原文；已有正文的章不被覆盖、
   底稿要点转进「写作资料」(`ref_materials_text`)。
6. 对保留章点「交 AI 重写」：解除保留、正文不丢、该章回到待生成队列。
7. 刷新页面重进项目：已锁定章仍可管理（不依赖本次是否重新解析底稿）。

## 结论

四个缺陷（2 个口径/解析缺陷 + 2 个交互断链）全部在真实场景下复现、修复并复验；
零 schema（只给 Chapter 加 2 个可选字段，随既有 json 列透传）、零提示词改动、零改批量生成逻辑；
四门全绿：tsc 0 / vitest 150 files 1767 passed 2 skipped（基线 149/1741，+1 文件 +26 用例，单测本文件 26 tests 全过）/ eslint 0 / build 4.40s。

## 遗留（已回写账本挂账）

- 参考重写口径细化：保留章转参考段时按 REF_LINE_CAP 截断，长底稿的要点选取可再智能化。
- 「底稿多出章」清退：换一份更短的底稿重新应用时，上一轮追加的 `draft-extra-*` 孤儿章不会被回收。
- 大纲未确认（章节清单为空）时面板整体不渲染，缺一条「先生成/确认大纲」的入口引导。
