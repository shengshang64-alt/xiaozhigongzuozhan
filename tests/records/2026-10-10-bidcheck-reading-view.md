## 操作步骤与结果（实机 localhost:8000/bid-check）
1. 选项目（React 受控 select 经原生 setter + change 事件选中）→「开始检查」→ toast「检查完成：2 项建议整改，无必改项」，Tab 徽标 2。
2. 「检查结果」Tab 三栏渲染：左树 34 章带问题数徽标（商务条件响应表 2 / 项目理解与需求分析 2 / 总体建设方案 2）+ 当前章高亮；中栏 A4 版心（标题层级字号、正文行高 1.8 首行缩进、工具条「段落 551 · 章节 34 · 页数≈128」）；右栏 8 处命中按级别分组，每条完整章节路径 + 段落全文 + 定位/标记已改。
3. 位置标记：L1-T1 命中段琥珀底 + 左橙竖条 + 右上「建议 L1-T1」角标，与交付规格一致；点「定位」中栏滚动至该段（闪烁 1 秒）。
4. 首轮发现 6/8 命中「无正文定位」→ 根因 clip 摘录前导省略号/跨段窗口 → 修 resolvePositions（两端剥省略号 + 前缀/后缀候选）+ 4 条回归单测 → 重跑 8/8 定位、console 0 warn/0 error（#17/#18 通过）。
5. 「只看有问题」：非问题段折叠「连续 30 段无问题（点击展开）」灰条，问题段保留标记；「显示全部」还原。
6. 「规则清单」Tab：L1 14 条逐条开关（7/14 启用，identity_leak disabled 标「由 L5 处理」）+ 每条层/严重度/说明含命中示例；L5 21 条目录随总开关；L2/L3/L4 规划说明。**实机负控**：关闭「措辞检查」重跑→Tab 徽标 2→1（L1-T1 含其 6 处命中不再报），重新启用复跑恢复 2（配置已还原）——改配置即调规则、无需改代码。
7. 顶部汇总条四级别 pill（必须整改 0 / 丢分风险 0 / 建议整改 2 / 提示 0）+ Excel/HTML 导出与门禁弹窗原样可用（#16）。
